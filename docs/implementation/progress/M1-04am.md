# M1-04am · 대시보드 기간 탐색 연결

상태: 구현·검증 완료. S03에서 저장된 계획의 기존 Orbit·타임라인·기간 목록을 탐색하고 Planner로 이동한다.

- 앱 shell이 planning의 공개 탐색 컴포넌트를 dashboard의 구성 영역에 주입한다.
  domain module 사이의 private import를 추가하지 않는다.
- 대시보드 rolling 조회와 계획 기간 선택은 독립된 URL 상태이며 뒤로가기·새로고침을 지원한다.
- 계획 조회는 대시보드 집계와 독립적으로 시작하고 로딩·빈 계획·실패·오래된 데이터를 구분한다.
- 기간 각도·길이는 날짜 비율이다. 완료율·실제 활동·계획 초안을 생성하거나 수정하지 않는다.
- 사용자·로그인 수명이 바뀌면 조회 캐시를 격리하고 이전 응답이 새 계정 화면에 섞이지 않게 한다.

## 검증

- `pnpm check --maxWorkers=2`: 생성물·Prettier·lint·typecheck 및 96개 파일 1,114개 시험 통과.
  새 탐색 컴포넌트 7개 시험에 URL/계층·보기·hover/focus·오류 복구·오래된 응답·계정/세션 격리,
  마지막 성공 조회 시각 보존과 잘못된 응답 거절을 포함한다.
- `API_ORIGIN=http://127.0.0.1:4301 pnpm build`: 7개 task 통과.
- 실제 OIDC/API/DB E2E 13개 통과: 신규 탐색 3개·카드 편집 5개·대시보드 UI 3개·타임라인 2개.
  키보드 계층 탐색, Orbit/타임라인 전환, 새로고침·뒤로/앞으로 가기, rolling 조건 유지,
  320px reflow와 Planner/달력 연결, 쓰기 요청 없음·저장 버전 불변을 검증했다.
  신규 1개는 대시보드 집계 응답만 503으로 주입하고 기간 탐색은 실제 API/DB로 확인했다.
- Aside 실 브라우저: 합성 계획에서 목록으로 Season 선택→원형에서 Enter로 Wave 선택→
  타임라인 전환을 확인했다. 선택한 기간 링크로 Planner에 진입해 같은 Wave와 날짜 범위가
  선택됨을 확인했다. 조회 시각 표시와 타임라인/목록/링크 배치를 screenshot으로 검토했다.
  `2026-09-17_hUofushtAllBHqqb/artifacts/dashboard-period-timeline.png`
  (Aside 세션 로컬 파일, 저장소에 포함하지 않음).
- DAG 78개 참조·비순환·evidence 경로·착수 의존성 및 diff 검사 통과.
  Herdr split-pane 독립 리뷰 base/tree·결과는 커밋 본문에 기록한다.

`planPeriod`·`planPeriodView`는 대시보드 탐색 URL 값이고 `anchor`·`window`·`timezone`을
덮어쓰지 않는다. 앱 shell이 공개 planning 컴포넌트를 항상 마운트하므로 집계 응답을 기다리지 않고
저장된 계획을 조회한다. 날짜 보기 링크는 Planner의 기간 lens에 calendar renderer를 선택하며
기간 트리를 수정하지 않는다. 조회 시각은 이 화면이 응답을 받은 시각이며 공급자 동기화 시각이 아니다.

API·DB schema·규칙은 변경하지 않았다. 상위 M1-04와 외부 출시 gate는 미완료로 유지한다.
