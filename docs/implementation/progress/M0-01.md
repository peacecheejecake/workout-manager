# M0-01 · 개발 도구·품질 기반

기준일: 2026-09-16. 상태: **완료** — 구현·로컬 검증 및 독립 peer review 완료.
연관: FUT-01/03/10의 개발 기반. 제품 화면·기능 수용 시험을 완료한 상태가 아니다.

## 구현

- pnpm workspace, Turborepo build/typecheck graph, strict TypeScript 공통 설정과 package exports.
- Node 24.12.0, pnpm 10.34.5, 직접 의존성 exact version, pnpm lockfile 및 frozen install.
- ESLint flat config, React Hooks/접근성, 선언된 public export 및 계층 경계 검사.
- Prettier/EditorConfig와 build·캐시·민감한 파일 제외. 규칙 문서·제공 설계 원본은 일괄 포맷하지 않음.
- Vitest node/jsdom 프로젝트, React Testing Library·user-event·MSW, V8 coverage.
- Playwright Chromium desktop/mobile와 오류 시 trace/screenshot.
- CI quality/E2E job과 아직 구현하지 않은 검증 목록. CI workflow는 작성했으며 원격 실행은 미수행.
- 독립 React/Vite fixture: 입력 검증, 비영속 mock POST, 오류 후 draft 보존·재시도.
- Vercel React Best Practices와 Composition Patterns를 동일 upstream revision으로 설치.
  원본 정보: [react-skill-source.json](../react-skill-source.json).
- `AGENTS.md`에 명시 요청된 native orchestration, composition 기본 지침, 규칙 변경 보호를 추가.

## 조율 및 검증

구현 작업은 Codex native agent에 경계 검사와 테스트 fixture를 독립 배정했다. root가 manifest·lockfile·CI와
통합 검증을 담당했다. Herdr pane은 독립 peer review에만 사용한다.

| 검사                             | 실제 결과                                              |
| -------------------------------- | ------------------------------------------------------ |
| `pnpm install --frozen-lockfile` | 통과                                                   |
| `pnpm check`                     | format/lint/typecheck/Vitest 통과                      |
| `pnpm test` / `test:coverage`    | 경계 51 + Hooks 설정 회귀 24 + component 3 = 78개 통과 |
| `pnpm build`                     | fixture production build 통과, Turbo output 경로 확인  |
| `pnpm test:e2e`                  | Chromium desktop/mobile 각 2개, 총 4개 통과            |
| Aside 실 브라우저                | 빈 입력 오류 → 한글 입력 → HTTP echo 확인 메시지 표시  |
| `pnpm test:integration`          | 예상대로 exit 1; M0-05 미구현 안내. DB 검증 통과 아님  |
| GitHub Actions                   | workflow 작성, 원격 실행 미수행                        |

로컬에서는 기존 전역 pnpm 11이 하위 명령에 선택되는 충돌을 발견했다. Node24와 pnpm10 Corepack shim을
PATH 우선으로 사용해 검증했다. 사용자 전역 설치를 변경하지 않았으며 재현 방법은 루트 README에 적었다.

## 범위와 다음 작업

- M0-02 공유 runtime 계약 및 M0-07a 로컬 FIT 작업이 후속 ready 후보다. 실제 착수 상태는 DAG에 기록한다.
- Next/Vite 제품 shell, Zustand store, 실제 API/DB, Garmin, native, Python batch는 아직 구현하지 않았다.
- fixture가 반환하는 메시지는 저장되지 않는다. mock endpoint는 Vite 개발 서버에서만 동작한다.
- 실 브라우저에서 한글 값을 입력한 것이 OS IME 조합·native keyboard 검증을 대신하지 않는다.
- ESLint 경계는 정적으로 확인 가능한 import와 package manifest를 검사한다. 임의 TS path alias나 전이적
  client import graph는 아직 분석하지 않으며 도입 시 별도 검사 확장이 필요하다.
- ESLint 9는 선택한 plugin peer 범위에 맞춘 현재 기반으로 설치했으며 registry에 지원 종료 경고가 있다.
  새 lint major 전환은 plugin peer 지원과 경계 회귀 시험을 함께 확인해야 한다.
- 기존 AGENTS의 초기 저장소/미구현 설명은 계획 작성 시점의 기준선이다. 현재 구현 상태는 이 기록을 따른다.
  사용자 지시 없이 기존 규칙 문장을 상태 갱신 명목으로 수정하지 않았다.
