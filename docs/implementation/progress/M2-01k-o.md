## 1. 설계

### 1.1 한 분류, 한 마무리 (A와 B 공통, `packages/server/courses/src/disclosure.ts`)

- **분류**는 privacy trim 자체다. `trimCourseForPrivacy`를 원(circle) 일반형 `trimLineAgainstCircles`로 쪼개(동작 불변,
  기존 privacy-trim 시험 그대로 통과) GPX는 보호 구역 원으로, 링크는 공유용 확장 원으로 같은 규칙에 넣는다. 결과는 넷:
  구역 없음 / 거절(SPLITS·LINE_CROSSES·REMOVES_EVERYTHING) / 닿지 않음 / 양 끝 안(§5 표).
- **마무리**(`finishDisclosedLine`): 좌표를 소수 5자리로 반올림한 **뒤** 원을 다시 자른다(T25). 반올림이 끝 정점을
  원 안으로 밀면 그 정점도 잘리고, 가운데라면 거절된다. 경유점은 원 밖 via만, 잘린 끝은 선의 끝(이름 없음)이 된다. 마지막에
  "어떤 정점·선분·경유점도 원에 닿지 않음"을 단언으로 다시 확인한다(가정이 아니라 검사).
- `owner-exact`(D3b)만 원 revision 그대로 7자리다. `no-zones-exact`(D3a)도 5자리다(R-2 문언).

### 1.2 A — 확인 receipt와 GPX (`apps/api/src/course-disclosure-routes.ts`)

- `GET /courses/:id/disclosure-preview?purpose=export|share`: 서버가 head와 원으로 계산한 선택지(나갈 선 그대로, 시작·끝,
  원래 끝에서의 거리, 정점 수, 이름 기본값, 경고 필요 여부, revision 추가 여부)와 구역 이름·구역별 제거 정점 수. 중심·δ 없음.
- `POST /courses/:id/disclosure-confirmations`(멱등 키): 서버가 전부 다시 계산하고 화면이 본 revision·구역 digest를 검사한다.
  거절 trim은 409 `COURSE_EXPORT_BLOCKED`(receipt 없음), 경고가 필요한 선택지(`no-zones-exact`, `owner-exact`)에 체크가
  없으면 409 `COURSE_EXPORT_NOT_CONFIRMED`, 링크+구역 0은 409 `COURSE_SHARE_REQUIRES_PROTECTED_AREA`(D3c), 링크+정확한 선은
  contract가 400(T20(4)). GPX 제거본은 privacy trim과 같은 파생 revision을 덧붙이고 receipt는 그 revision에 묶인다(R-10).
- receipt(`course_disclosure_receipt`): revision·구역 digest·목적·노출·이름 포함 여부, 1시간 유효, revision FK cascade.
- `GET /courses/:id/export.gpx?receipt=`: receipt가 없거나 목적·revision·구역 digest가 지금과 다르면 본문 없이 409(거절 trim이면
  `COURSE_EXPORT_BLOCKED`, 아니면 `COURSE_EXPORT_NOT_CONFIRMED`). 기존 export 라우트는 `course-routes.ts`에서 이리로 옮겼다
  (disclosure 조합이 없으면 GPX 라우트 자체가 없다 — 확인 없는 GPX는 없다).
- GPX writer(A-1, R-3, R-6): `metadata`는 이름을 넣을 때 `name`만, `desc`·`time`·확장 없음, `creator="course-route-export"`
  (제품명 없음, importer는 여전히 인식), 파일 이름에 revision 번호 없음, 이름을 빼면 `course.gpx`. 이름 기본 포함(D6).
- 계정 export는 gate 밖(D4). v23: 구역의 δ(`coursePrivacyZoneShareOffsets`)와 링크 사실(`courseShares`: token·digest·snapshot
  없음). 계정 import 경로는 이 제품에 없으므로 export가 링크를 되살릴 수 없다(T13).

### 1.3 B — 보기 전용 링크 (flag 기본 꺼짐)

- **flag**: `COURSE_SHARING` 미설정·`off` = 꺼짐. `on`이면 `COURSE_SHARE_EPOCH`(정수), `COURSE_SHARE_RATE_KEY`(≥32 bytes),
  `COURSE_SHARE_TRUSTED_PROXIES`(IP 목록, 비어 있으면 안 됨 — §8)가 모두 없으면 **시작 거부**. 꺼짐: 링크 관리 라우트 미등록, 링크 확인 미제공, 읽기는 DB에
  가지 않고 404. 화면은 목록 라우트가 없음을 보고 공유 control을 하나도 그리지 않는다.
- **token**: 256비트 CSPRNG base64url, 서버는 SHA-256만(`course_share.token_digest` unique). 생성 응답 한 번만 평문.
- **공유 원(B-1)**: 구역마다 S=max(r,200m), R_eff=1.5S, 중심 = 구역 중심 + δ·0.5S. δ는 단위 원판 균일 점으로 **구역 생성
  시** 한 번 저장(`course_privacy_zone_share_offset`, UPDATE 금지 trigger, 구역 삭제·말소와 함께 삭제). 이 노드 이전의 구역은
  첫 사용 때 한 번 뽑는다(그 뒤 불변). δ는 공유·확인 응답과 로그 어디에도 없고(T22 통합이 응답 전체에서 δ 부재를 확인),
  소유자 자신의 계정 export(v23 `coursePrivacyZoneShareOffsets`)에만 나간다 — 구역 중심처럼 다시 만들 수 없는 입력이라서다.
- **스냅샷**: 링크 생성 시 head(확인된 revision이어야 함)를 공유 원으로 잘라 `course_share.snapshot`에 저장, revision FK
  `ON DELETE CASCADE`. 링크는 active→revoked만 가능(trigger). 캡: 소유자 20, 코스 5(현재 epoch·미만료 기준). 만료 기본 7일,
  최대 30일(초과는 contract 400).
- **어떤 receipt로 링크를 만들 수 있나**는 저장소 한 곳(`createShare`의 SQL: `purpose='share' AND exposure=<저장하는 선의
노출>`)에서만 정한다.
- **읽기**: `POST /bff/v1/shared/course`, 인증 plugin 밖, 세션·쿠키를 읽지 않는다. 본문 파서가 거부한 본문, DB 오류, 형식 오류,
  없음, 만료, 철회, epoch 불일치, flag 꺼짐, 한도 초과 모두 같은 404 본문·헤더(`no-store, private`, `no-referrer`,
  `x-robots-tag`, `nosniff`). 형식 오류 token도 digest를 계산해 같은 DB 호출을 탄다(타이밍). 응답은 strict allowlist:
  좌표, 경유점 role·position(이름은 켰을 때 via만 — 끝이 이름을 잃은 사실이 곧 trim 단서라서 끝에는 이름을 두지 않는다),
  (켰을 때) 이름, 정수 m 거리, 만료 **날짜**.
- **읽기 함수** `read_course_share`(SECURITY DEFINER, runtime 역할은 EXECUTE만): 한 번의 digest index 조회 뒤 active·미만료·
  epoch 일치·"더 높은 epoch 행 없음"(설정 되돌림 fail-closed)·tenant 미말소를 검사한다. rate limit(B-4, D7): client 분당 30,
  실패 시간당 100(넘으면 그 창 동안 전부 404), 링크 분당 60(맞은 읽기만, share id 키, R-5). 카운터 키는 client 주소의 keyed
  HMAC(평문 IP 없음), 2시간 지난 행은 읽기가 지운다. PostgreSQL 카운터라 인스턴스가 공유한다. client 주소는 신뢰 프록시 목록의
  `X-Forwarded-For`만 믿는다.
- **철회(§4)**: 명시 철회, "모든 링크 끄기", 구역 추가 시 새 구역의 공유 원에 닿는 링크 자동 철회(B-6, 같은 트랜잭션), 구역
  삭제 시 그 구역으로 잘린 링크 철회(R-7) — 모두 `course_share_audit`(token·digest·좌표 없음)에 기록. 코스 삭제·활동 삭제
  reclaim은 FK cascade, 계정 말소는 `erase_account` 체인 새 고리(`erase_account_before_course_sharing`, 77206→0→행)가 링크·
  감사·receipt·δ·링크 카운터를 지운다.
- **복원(B-5)**: 링크는 생성 epoch를 저장. 복원 절차가 runtime 접근 전에 epoch를 올리면 복원 전 모든 링크가 404(원장 재생 없음,
  fail-closed). drill이 이를 실행한다(§3).

- 편집기 쪽 변경은 최소: workbench의 "GPX 내보내기"가 확인 화면을 열고, 보호 구역 패널 옆에 링크 패널, 보호 구역 패널에

## 6. 남은 것

- 재식별 검토 r1: B를 켜는 데 **조건부 통과**. R1의 진행 방향·역투영 공격(N=20에서 약 0.2·S) 완화는 **사용자 결정으로 별도
  후속 노드 M2-01as**다. 그 전에는 B를 켜지 않는다(flag 기본 꺼짐 그대로). 이 노드는 그 완화를 구현하지 않았다(§8).
- B를 켜려면 web shell 앞에 `X-Forwarded-For`를 연결 주소로 설정하는 front proxy가 필요하다. Next rewrite는 이 header를
  붙이지 않고 클라이언트 값을 그대로 넘긴다(§8 실측). runbook에 조건으로 적었다.
- 발견 (a)(백업 뒤 삭제한 코스가 복원으로 되살아남)는 M2-01ao(049 코스 삭제 ledger)로 닫혔다. drill의 해당 기록은 지웠고,
  `deleted_course_share_not_served_after_restore`는 이제 049 replay 뒤 코스·링크 행 0과 두 epoch 모두 `not_found`를 단언한다(§7).
- CDN/프록시가 생기면 `/bff/v1/shared/*` 캐시 우회와 철회 후 probe(T11/§4 캐시 행): `not_executed`.
- 확인 화면의 "지도"는 SVG 선 미리보기+목록이다(basemap 지도는 공유 보기 화면에만). §5 "지도와 목록을 함께"의 해석으로 적는다.
- 링크 이름을 켜도 두 끝에는 이름이 없다(B-3 trim 단서 차단). 요구 문언보다 보수적인 해석이므로 검토에서 확인 필요.
- 복원 epoch 증가는 배포 설정이다. drill은 설정을 모델링한다. runbook에 복원 단계로 적었다(§8). 실제 배포 설정 변경은
  실행하지 않았다(`not_executed`).
- (관찰, 이 노드 밖, 후속 M2-01at) 044/045의 purge lease는 `tenant_erasure`를 tenant 없이 읽는다. 소유자가 superuser·BYPASSRLS가 아니면
