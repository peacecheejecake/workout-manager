# M3-02n · HealthKit 운동 선택 UI와 native bridge

상태: **구현·로컬 합성 검증 완료**. M3-02m의 등록 UUID 범위 수집 이후, 사용자의 운동 선택을 계정 귀속 선언으로 취급하는 명시 등록 UI를 연결한다. 개별 해제·재등록·기존 자료 감사의 통합은 M3-02o, 제품 실기기 수용은 M3-02h다.

## 소유 범위와 입력 계약

- 루트: `packages/contracts/src/native-bridge.ts`와 계약 시험, Xcode source membership, graph/진행 기록.
- Native 담당: native-only 선택 engine/UIKit sheet, 고정 등록 POST와 credential/session/consent 검증, bridge dispatch/cancel, collector refresh seam 및 합성 Swift harness.
- 웹 담당: platform client, identity HealthKit panel과 시험, 명시적 synthetic bridge fixture의 실제 브라우저 점검.

기존 v3 host는 optional capability `healthkit.workouts.selection`이 없으면 선택 기능을 지원하지 않는 것으로 처리한다. 기존 workout status 계약은 보존한다. `select`는 빈 payload를 받아 실제 native 화면을 연 뒤 `opened`와 무작위 opaque `selectionId`를 반환한다. `selectionStatus`와 `cancelSelection`은 해당 handle을 요구해 이전 계정 화면의 요청이 새 화면에 영향을 주지 못하게 한다. 이 handle은 HealthKit sample UUID가 아니며 후보 UUID·epoch·원본·요약·정밀 시각은 WebView에 보내지 않는다.

Status는 유한 상태와 제한된 건수만 가진다. registeredCount/resultCount의 null은 미확인이며 0으로 대체하지 않는다. native 후보 조회는 사용자가 지정한 날짜 predicate/최대 200개, 선택 최대 50개로 제한한다. 명시 귀속·업로드 확인 전 POST를 보내지 않고, ACK membership과 완전한 최신 등록 목록을 확인하기 전 수집 범위를 추정하지 않는다. 취소 후 이미 전송된 명령은 되돌렸다고 표시하지 않는다.

## 현재 실제 검증

- 2026-10-05 공유 계약 첫 집중 실행은 2파일·15시험 통과했다. opaque lifetime handle을 추가한 첫 실행은 fixture가 새 필드를 빠뜨려 14통과·1실패였고 이를 보존한다. fixture 수정 후 15/15와 contracts build가 통과했다.
- 2026-10-06 동일 계약 시험을 재실행해 **2파일·15/15**, contracts typecheck와 diff 검사 종료 코드 0을 확인했다.
- 새 Swift 두 파일을 Xcode PBXFileReference/group/Sources에 연결했고 plutil lint 및 diff 검사가 통과했다. 전체 Xcode app build·서명·기기 실행 통과로 표현하지 않는다.
- 작업 브랜치의 node_modules가 실제로 없어졌음을 확인했다. offline frozen install은 store의 Fastify tarball 미존재로 실패했고, 네트워크 승인 후 같은 frozen lockfile install이 exit 0으로 완료됐다. lockfile 변경 없음, msw build-script ignored 경고를 보존한다. 해당 환경 실패를 제품 시험 실패 또는 통과로 계산하지 않는다.

## 웹/platform 검증 · 2026-10-06

- platform/client와 identity/component **2파일·45시험**, platform·identity·tooling·mobile-web typecheck **4/4**, 변경 파일 lint/format/diff, mobile-web production build와 합성 fixture build가 통과했다.
- 실제 Aside에서 Enter 선택→choosing, offline→registered 복구, content 280px 좁은 container의 overflow 0을 확인했다. Aside sandbox loopback 연결 실패는 승인된 접근으로 복구했다. `setViewportSize` 미지원으로 viewport 검증은 Chrome을 사용했다.
- 실제 Chrome에서 320/390/767/768/1024/1279/1280/1440px overflow 0, Tab focus solid 2px, offline 복구·consent=false 후 미확인 건수 초기화·구형 host 선택 버튼 부재를 확인했다. 임시 consent=null refresh는 선택 상태를 유지한다.
- Playwright 최초 8건은 bundled Chromium 미설치로 launch 전에 실패했다. `HEALTHKIT_FIXTURE_BROWSER_CHANNEL=chrome`으로 설치된 Chrome의 격리 임시 profile을 사용한 재실행은 320/390/768/1440px × 2흐름 **8/8**을 통과했다. 개인 profile을 사용하지 않았다. 브라우저 탭·fixture server는 정리됐다.
- 최초 polling 시험의 fake timer/user-event timeout과 최초 lint에서 발견한 refresh cleanup 취소 플래그 누락은 수정 후 통과했다. 기존 use-client/sourcemap·Zod 주석·큰 chunk build 경고는 남는다.
- root는 반환된 웹 결과와 공유 계약을 합쳐 **3파일·51시험**을 재실행해 통과했다(`/private/tmp/wm-m3n-root-combined-tests.log`). 이는 native UIKit/실제 HealthKit 증거가 아니다.

## 남은 조건

이 노드의 로컬 구현 수용을 완료했다. 기존 raw/receipt 감사·해제·safe rollout 통합은 M3-02o에서 진행한다. DEBUG의 개인 HealthKit 읽기 금지를 유지한다. 운영 HTTPS 등록 경로·기기 UIKit/VoiceOver·OS 읽기/observer/background delivery·개인 건강 자료 및 phase 독립 검토는 **not_executed**다. 모의 bridge나 Swift compile을 실기기 증거로 계산하지 않는다.
