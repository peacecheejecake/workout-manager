# M1-04a · 체크인 계약·API·저장

상태: **구현·로컬 검증 완료**. 2026-09-16 사용자가 지도와 무관한 제품 구현의 의존성 분리를 승인했다.
M1-04의 서버 하위 작업이다. S12/V2-F17, V2-A45의 revision 기반 근거 갱신 기반에 해당한다.

자기보고 피로·불편감 0–10과 미보고 null을 구분하고 관측 시각·시간대·입력 시각·정정 이력을
보존한다. 질문과 척도 끝점의 의미를 checkin-v1로 고정한다. 수면 품질·기기 지표·종합점수·
진단·회복 전략·자동 계획 변경은 이 API의 범위가 아니다.

명령은 tenant 단위로 멱등 처리하고 현재 revision·이력·collection revision·outbox를 한 거래에서
기록한다. 삭제는 건강 payload와 정정 이력을 제거하며 최소 명령 receipt만 남긴다.
계정 삭제·export·백업 복구에 신규 원장을 포함한다. 아래 실행 결과를 기록했다.

## API와 데이터 의미

`POST /bff/v1/check-ins`, `GET /bff/v1/check-ins`, `GET/PUT/DELETE /bff/v1/check-ins/:id`를
제공한다. 쓰기는 현재 앱 세션·CSRF·Origin·`Idempotency-Key` header를 요구한다. body에는
사용자 ID나 provenance를 받지 않는다. 생성 `{values}`, 정정 `{values,expectedRevision,reason}`,
삭제 `{expectedRevision}`을 엄격히 검증한다. 피로·불편감은 정수 0–10/null이며, 메모·부위와 함께
최소 하나를 보고해야 한다. 관측 시각은 offset이 있는 instant와 IANA timezone을 받고 UTC로 정규화한다.
현지 날짜는 서버에서 계산하며, 5분을 초과하는 미래 관측은 거절한다.

목록은 `from` 이상 `toExclusive` 미만의 **각 기록 현지 날짜**로 필터링한다. 1–90일 범위, 기본 50개/
최대 100개, offset 상한 10,000이다. 현재 목록·전체 개수·collection revision은 동일 DB snapshot으로
읽는다. 기록이 없고 collection head도 없으면 revision 0이다.

명령 응답은 `{id,revision,collectionRevision,deleted}`이며 **해당 명령이 성공한 시점의 결과**다.
같은 key의 재요청은 원래 결과를 돌려주므로 UI는 응답을 현재 데이터로 덮어쓰지 않고 재조회해야 한다.
삭제 후 생성 명령을 재전송해도 tombstone과 receipt 때문에 기록은 부활하지 않는다.
정정 이력의 건강 값·이유는 해당 기록 삭제 때 제거한다. outbox에는 ID·revision·동작만 저장한다.

`source:user`, `method:self_report`, `definitionVersion:checkin-v1`과 고정 질문/척도 정의를 사용한다.
초기 정의는 `packages/contracts/src/check-ins.ts`에 있다. 원점수·진단·회복 점수나 session RPE와 합치지
않는다. 내보내기는 collection 추가를 명시하는 schemaVersion 2로 올렸고 기존 v1 파일은 보존한다.

## 실제 검증

- `pnpm check`: 생성물·Prettier·ESLint·typecheck 및 400개 테스트 / 33파일 통과.
- 임시 실제 PostgreSQL: 67개 / 8파일 통과, 신규 체크인 10개 포함. 동시 생성·정정·삭제,
  tenant 격리, outbox 실패 rollback, 계정 삭제 경쟁, 시간 경계, null/0와 오래된 receipt 재전송을 검증했다.
- `pnpm build`: 7개 build task 성공. 포트 분리 후 Next production build도 다시 성공했다.
- OIDC + 실제 API/DB + 합성 공급자 E2E: 10개 통과. 새 체크인 journey는 실제 로그인 후 API로
  생성·정정·충돌·export v2·건강 payload 삭제·재전송 억제를 확인한다. 체크인 화면 완료 증거는 아니다.
- 백업·복구 drill: 10개 검사와 cleanup 통과. 체크인 4개 테이블의 삭제 원장 재적용·다른 tenant의
  0/null·관측 시각·현지 날짜·정의 유지와 삭제 계정 쓰기 차단을 확인했다. 기존 8/9개 보고서 보존.

초기 품질 검사는 API 테스트가 바뀌는 동안 생성자 인자 타입 오류가 있어 실패했고 수정 후 다시 통과했다.
첫 E2E 시도는 기존 Docker 프로세스가 4300을 사용해 시작하지 못했다. 해당 프로세스를 유지하고
테스트용 API만 4301로 분리했다. 로그는 `/tmp/workout-checkin-check-final.log`,
`/tmp/workout-checkin-build.log`, `/tmp/workout-checkin-build-isolated.log`,
`/tmp/workout-checkin-e2e-isolated.log`, `/tmp/workout-checkin-backup-drill.log`다.
DB 최종 결과는 실행 session 62771에 있다. 앱 UI는 이번 서버 task에서 변경하지 않았다.
독립 Herdr 최종 리뷰의 base/tree·결론은 커밋 본문에 기록한다.
