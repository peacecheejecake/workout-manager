## 1. 설계 근거

각 행의 `reason`이 말하는 공백 하나하나에 시험을 하나 이상 대응시켰다. 규칙은 매트릭스 헤더와 같다. 시험이
이 노드에서 실행되어 통과하고, 요구의 핵심을 단언하고, 기능을 되돌린 **변이에서 실패**해야 한다.

- 변이는 제품(또는 lint 규칙) 파일의 **정확히 한 곳**(anchor가 파일에 한 번만 나올 때만 적용)을 바꾼다. 적용 →
  시험 하나 실행 → 원본 사본으로 복원 → `filecmp`(byte 비교)로 `identical` 확인. 도구는 scratchpad의
  `mutate.py`/`mut.sh`이며 커밋하지 않는다.
- UI 변이는 컴포넌트 시험에서 보였다. E2E에서 UI 변이를 보이려면 Next/Vite를 다시 빌드해야 하고 harness
  잠금을 오래 잡는다. API는 identity harness가 source(tsx)로 띄우므로 API 변이는 E2E에서 직접 보였다.
- 다른 노드와 겹치지 않게 제품 코드는 **lint 규칙 한 파일**만 바꿨다. M2-01k-n(차트 drag 범위·lap/map 연동),
  -l(미디어 탭), -m(영향 분리)이 만질 S09 컴포넌트는 건드리지 않았다. 시험은 새 파일에 두거나 기존 spec 끝에
  더했다.

## 2. 만든 것

### 2.1 제품 결함 수정 — geo-kit 경계를 lint가 실제로 막지 않았다(P5-geokit-boundary)

계획 5절: "`experience/geo-kit`은 SDK-free MapPath와 선택 위치·이벤트만 받는다. 내부 MapLibre adapter가 SDK
객체를 소유하며 FIT/GPX 출처나 서버 정책을 모른다." 기존 `architecture/boundaries` 규칙은 kit → module/app과
kit → server는 막았지만, 다음 두 위반은 **`pnpm lint`를 통과했다**(아래 변이 `p5-sdk`, `p5-parser`가 규칙을 빼면
시험이 실패하는 것으로 확인).

1. `maplibre-gl`을 아무 곳에서나 import할 수 있었다. 도메인 module, app shell, kit의 SDK-free 파일
   (`map-path.ts`, `map-view.tsx`)도 마찬가지였다.
2. kit이 FIT/GPX 파서(`@workout/track-parsing`, 계층상 `tooling`)를 import할 수 있었다.

수정(`packages/tooling/eslint/boundaries.mjs`):

- 지도 SDK(`maplibre-gl`)를 import할 수 있는 파일은 `packages/experience/geo-kit/src/maplibre-adapter.ts`와 M0 UI
  spike의 지도 패널 `packages/experience/ui-spike/src/map-panel.tsx`(kit보다 먼저 있던 별도 experience 패키지)뿐이다.
  spike는 **그 한 파일**만 허용한다(검토 N3). spike의 다른 파일은 SDK를 쓰지 않는다.
- geo-kit 자신의 시험(`packages/experience/geo-kit/tests/`)은 SDK **type**만 import할 수 있다(`import type`, 검토
  N3). 시험이 SDK 형태를 이름으로 부를 수는 있어야 하지만, 값(생성자·함수)을 import하면 adapter를 거치지 않고
  SDK 객체를 만들 수 있다. 현재 시험은 `vi.mock('maplibre-gl', …)`만 쓴다(문자열이라 규칙 대상이 아니다).
- 누구도 SDK를 **다시 export하지 않는다**. adapter도 마찬가지다(검토 N1). `export { Map } from 'maplibre-gl'`이나
  `export * from 'maplibre-gl'`은 SDK 객체를 adapter 밖으로 다른 이름으로 넘긴다.
- 패키지 이름이 아니라 설치 경로로 부른 SDK도 SDK다(검토 N2). 상대/절대 경로를 풀어 `/node_modules/maplibre-gl`
  (뒤가 `/`이거나 끝)을 지나면 같은 규칙을 적용한다. 예: `'../../../../node_modules/.pnpm/maplibre-gl@…/node_modules/maplibre-gl'`.
- UI/experience 계층은 `packages/track-parsing`을 import할 수 없다.

현재 저장소에는 이 규칙들을 어기는 파일이 없다(`pnpm lint` 0 경고).

## 6. 남은 것

- 병합 검토(r2)의 비차단 R2-1: zoom 반복의 2–4단계는 앞 단계 ease 애니메이션이나 basemap tile 로딩으로 화면이 바뀌어
  그 단계의 키 없이도 통과할 수 있다(거짓 통과만 가능, 거짓 실패는 아님). `n4-noop`은 1단계만 증명한다. 각
  `previous` 캡처 전에 연속 두 frame이 같아질 때까지 기다리거나 idle 속성을 노출해 기다리면 닫힌다. P8-simplify의 주
  근거는 컴포넌트 LOD 시험이라 판정은 그대로다.
- UI 변이를 E2E(재빌드)로는 보이지 않았다. 단위 변이와 실제 스택 E2E 통과를 합쳐 판정을 제안했다.
- hover로 움직이는 커서가 생기면(M2-01k-n 등) `detail-cursor-store.test.tsx`에 그 경로를 더해야 한다.
- UI 확인 순서: 이 노드는 새 화면·동작을 만들지 않았다. Aside·Chrome은 쓰지 않았고 Playwright(identity E2E)만
  썼다.
