# M3-02i · 명시적 HealthKit 독립 Activity 생성·삭제 수명주기

상태: 로컬 수용 완료. `phase/m3-02`의 하위 작업이며 phase 독립 검토 전이다.

## 수용 경계

- 사용자가 active HealthKit workout UUID와 원본 digest를 보고 명시적으로 확인한 경우에만 HealthKit 소유 canonical Activity를 만든다. 기존 fit/manual Activity에 연결하는 결정은 M3-02e의 별도 명령이다.
- 원본에 없는 제목·시간대·심박·경로·운동 종류를 추정하지 않는다. 검증된 시간·거리·단위와 원천 표식을 보존하고, 동일 UUID나 재전송을 두 번 합산하지 않는다.
- 실제 `HKDeletedObject`나 HealthKit 동의 철회, 사용자의 로컬 Activity 삭제에서 HealthKit 소유 자료를 억제·정리한다. fit/manual 소유 Activity는 보존한다.
- 생성·삭제·중복 요청·다른 계정·동시성·export/erasure를 실제 PostgreSQL에서 검증한다. 제품 선택 UI와 서명된 iPhone 실행은 M3-02g/h에 남는다.

## 구현 경계

- 마이그레이션 062와 tenant-scoped 저장소는 확인된 active workout UUID, 원본 digest, `confirmed: true`, 멱등 키를 요구한다. 동의·표본·lineage를 한 거래에서 잠그고 새 canonical Activity, source head/revision, outbox, 명령 receipt를 원자적으로 기록한다. 이미 연결된 UUID는 다시 생성하지 않는다.
- 새 source kind `healthkit`은 읽기·필터·계획 내 실제 활동에서 구분된다. FIT import 명령으로 HealthKit 출처를 위조할 수 없다. HealthKit 종목 코드는 설치된 Apple SDK 정의의 걷기·달리기·자전거·근력 운동 값에만 대응하며 나머지는 `other`다. 기간 정의는 `unknown`; 제목·시간대·심박·경로를 만들지 않는다.
- `HKDeletedObject`, 동의 철회, 로컬 Activity 삭제는 HealthKit 소유 canonical과 overlay/source revision/receipt를 정리하고 suppression을 남긴다. 로컬 삭제 시 해당 raw 표본도 tombstone 처리한다. 복원 시 부재 Activity 삭제 원장과 늦은 원본 업로드도 HealthKit 억제를 적용한다. 다른 소유 활동과 다른 raw UUID는 보존한다.
- export v28은 `created_activity` lineage를 포함하며 이전 v27 형식은 그대로 파싱된다. API는 인증된 소유자와 기존 cookie CSRF 경계를 따른다.

## 검증

- 독립된 실제 PostgreSQL: 전체 통합 86개 파일, 837개 테스트 통과. M3-02i 집중 8개 테스트가 생성·멱등/경합·소유권·삭제/철회·export/erasure·삭제 원장 replay를 검사했다. 외부 백업 복원 훈련은 하지 않았다.
- 전체 단위/컴포넌트 4,211 통과, 기존 7 건너뜀. 첫 sandbox 실행은 로컬 HTTP fixture가 차단되어 35개 실패했고, 접근 권한을 적용한 재실행에서 통과했다.
- generated check, 전체 ESLint, 전체 Prettier, TypeScript typecheck 34/34, build 15/15, 기본 Playwright 4/4 통과. 인증된 Web·mobile Playwright 전체를 두 번 실행해 각각 302 통과·13 건너뜀(14.9분, 14.7분)을 확인했다.
- Aside CLI의 필수 update 확인은 `fetch failed`였고, Chrome 탭 연결은 `Debugger unattached`였다. 따라서 Playwright를 사용했다. 이 검증은 서명된 iPhone HealthKit 실행의 증거가 아니다.

## 남은 한계

- 로컬 HealthKit Activity 삭제는 배치와 표본 간 인덱스가 없는 현재 receipt 형식 때문에 해당 계정의 HealthKit 배치 digest를 모두 지운다. 오래된 native outbox 배치의 재전송은 충돌하므로 재조정 경로가 필요하다. 이 후속 경계는 M3-02g/h에서 확인해야 한다.
- 제품 선택·동의 화면은 M3-02g, 서명된 실기기 수집·삭제·background delivery는 M3-02h다. 실기기 검증 상태는 `not_executed`다.
