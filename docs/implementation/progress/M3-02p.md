# M3-02p · phase 수용 E2E의 비동기 fixture·포커스 경합 검증

상태: **진행 중**. M3-02n 이후 phase 전체 검사에서 발견한 공유 시험 경계를 별도 추적한다. HANDOFF의 반복된 흔들리는 시험은 별도 노드로 다루라는 지침에 따라 합성 Garmin MFA 실패도 포함한다. 제품 기능·실제 공급자·기기 수용의 완료를 선언하지 않는다.

## 범위·소유·수용

Root는 공유 E2E 시험 수정·DAG/기록·결과 통합을 소유하고, native agent는 고정 HEAD에서 실제 harness/API/Python fixture/Chrome 격리 회차와 제한된 tmp 진단을 수행한다. 진단은 고정 요청의 상태·시간만 기록하며 credentials/본문/header/query/정밀 위치·개인 자료를 수집하지 않는다. 제품 코드·안전 gate·기존 엄격한 schema/확인/비노출 단언은 유지한다. 수정한 고정 HEAD에서 전체 identity 두 성공 회차와 자기 서버/PG 정리를 확인한 뒤에만 이 로컬 노드를 완료한다. phase 독립 검토와 운영/기기 gate는 별도다.

## 실제 실패·수정·미실행

- 첫 전체 `isolated-r1`: 301통과·8실패·12skip, exit1. 공통 export helper28/실제 producer30 불일치를 runtime schema/assert를 보존한 literal/type 수정으로 해결했다. `ebe3d185`에서 `isolated-r2` 전체309통과·12skip·exit0이었다.
- `isolated-r3`: 삭제 영향 조회가 끝나기 전 disabled 확인 버튼에 focus를 요청하는 경합을 확인했다. 자기 runner만 SIGINT해 119통과·1실패·1중단·2skip·198미실행, exit130. 두 focus 전에 toBeEnabled를 기다리고 재확인 focus도 명시 단언해 `11f6ced5`에 커밋했다. 전체 typecheck·시험 lint/format/diff exit0. 제품은 조회 미확인을 삭제 가능으로 오인하지 않는 gate를 유지했다.
- `isolated-r4`의 삭제 시험은 통과했으나 비공식 Garmin MFA UI가5초 안에 나타나지 않았다. 실패 snapshot은 실제 로그인 처리중·control disabled였다. 자기 runner만 SIGINT해 **251통과·1실패·1중단·12skip·56미실행**, 실제 exit130(10.1분)과 자체 포트/PG 정리를 확인했다. 이 회차는 두 성공 회차 조건을 충족하지 않는다.
- 원본 단언을 유지한 tmp 진단은 실제 API/Python fixture/Chrome에서 **3/3·exit0**이었다. 고정 POST login 응답은 Next628ms/200, Vite334ms/200, 다른 pinned계정338ms/409. 원래 r4의 HTTP 완료 시간은 미관측이므로 이 수치로 이전 실패 원인을 확정하지 않는다. 진단은 `/private/tmp/wm-m3-unofficial-timing-r1.log`에 보존하고 자체 포트/PG 정리를 확인했다.
- 원본 시험에는 UI login 전에 고정 POST 응답 대기를 등록하고 실제 HTTP 상태200/409와 body 수신 완료를 확인하는 순서를 추가했다. Python 호출이 포함된 click을 로그인 완료로 취급하지 않으며, worker120초·시험 기본30초·기존 UI5초와 import poll30초를 구별한다. timeout/임의 sleep/제품 코드·gate를 바꾸지 않았다. 원본 실제4개 집중 시험 **4/4·exit0**(17.7초), 자체 포트/PG 정리와 전체 typecheck·lint/format/diff exit0을 확인했다. 이 smoke는 HEAD11f6ced+root의 미커밋19줄 수정에서 실행했으며 clean HEAD의 전체 두 회차가 아니다. 로그는 `/private/tmp/wm-m3-unofficial-receipt-smoke.log`다.
- 전체2회 완료는 아직 미실행이다. 새 실패를 일부 재실행 통과로 덮지 않는다. 로그/output의 원본 실패와 중단을 보존한다. local fixture는 실제 Garmin 계정/공식 연동 증거가 아니며 기존 provider gate·계정/자료 삭제 억제·운영 미실행은 유지한다.

세부 전체 phase 검사와 원본 로그 경계는 [phase 기록](M3-02-phase-review-20261006.md)을 따른다. 노드·phase 완료나 main 병합은 아직 하지 않았다.
