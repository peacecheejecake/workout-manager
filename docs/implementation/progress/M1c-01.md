# M1c-01 · 범용 루틴 core

상태: **운영 런타임 권한 검토 대기**. 루틴 Blueprint의 불변 버전·라이브러리 상태,
유한 Schedule/Occurrence 미리보기와 명시 승인, Run 단계 진행·선택·타이머 및
기존 실제 기록 연결을 구현했다. 기존 보강 운동 템플릿과 영양 계획은 고정 버전으로
참조하며, Run 자체는 Activity나 섭취를 만들지 않는다. 루틴 발생분만 승인하는
화면은 네 도메인 계획을 임의로 바꾸지 않는다. 공동 후보의 네 도메인 원자 승인은
M1c-04에서 다룬다.

S31~S33 웹·모바일 화면은 Zustand의 계정·세션별 초안과 React Query의 읽기
캐시를 사용한다. 일정 전개는 날짜 범위와 발생 건수 상한을 적용하고, 승인 때
preview digest 및 참조 버전을 다시 확인한다. 단계의 실제 기록은 현재 canonical
Activity·섭취 원장 또는 사용자가 확인한 checklist 사실을 참조한다. 선택하지
않은 대안은 진행 분모에서 제외하고, 타이머 종료만으로 수행을 확정하지 않는다.

023 migration은 새 테이블 모두에 FORCE RLS, 불변 버전·발생분·개정 보호,
계정 말소 연동을 제공한다. 기존 `erase_account(text)`를 감싼 새 함수의 EXECUTE
권한은 migration 뒤 `grantOperations` 재실행이 필요하다. 자동 승인 검토가
운영용 `grantRoutineCore` 추가를 거절해 이 변경은 적용하지 않았다. 필요한 최소
권한은 런타임 역할에 다음과 같다.

| 권한                   | 새 테이블                                                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| SELECT, INSERT         | routine_blueprint_version, routine_schedule_version, routine_occurrence, routine_run_revision, routine_checklist_confirmation, routine_command_receipt |
| SELECT, INSERT, UPDATE | routine_blueprint_head, routine_schedule_head, routine_run, routine_step_timer                                                                         |

DELETE 권한은 요청하지 않는다. 임시 E2E fixture는 삭제되는 격리 DB 역할에만
위 권한을 부여했으며, 실제 운영 역할의 권한 설정은 여전히 대기 중이다.

검증: 전체 `pnpm check`의 포맷·lint·24개 패키지 타입 검사·184개 파일/1,932개
단위 테스트, 격리 PostgreSQL 31개 파일/264개 테스트, Web·mobile-web
production build가 통과했다. 실제 OIDC·임시 PostgreSQL·Chromium E2E는 루틴
저장→단일 발생분 승인→checklist 수행, Activity 비중복, Bob 계정의 Alice 루틴
조회 차단, 계정 말소를 확인했다. Herdr split-pane 독립 리뷰가 응답 유실 후
명령 재시도, Activity의 명시적 미상 시각, 타이머 정리 후 재시작 P2 세 건을
지적했다. 미상 시각을 원본/epoch로 보충하지 않고 연결을 거절하며, 타이머의
정리→재시작을 개정 증가와 함께 허용했다. UI는 응답이 유실되면 같은 명령·키를
보존하고 명시적 재시도를 제공한다. 수정 후 전체 검사와 격리 DB·Chromium
E2E를 재실행했다. 기준 HEAD `8a93a5c48a658079c5c0edc271e1eabd3f32cbd0`와 이
진행 기록을 제외한 최종 staged diff SHA-256
`bd8a6f3b5308d5d2768871924539f4f8f28ef5ea0194c07bea7f0d0f3a63aac6`에 대한
Herdr 분할 창 독립 재검토에서 세 P2가 해결됐고 추가 actionable finding은
없었다. 리뷰어는 테스트를 직접 재실행하거나 파일·index를 변경하지 않았다.

범위 한계: 회복·체크인 콘텐츠의 신규 참조와 실제 연결, 여러 기기 간 오프라인
Run 동기화, 고급 일정 편집 및 네 도메인 통합 승인은 이번 core 경로에서
검증하지 않았다. 다중 계정 실브라우저 경로는 검증했지만 실제 Garmin,
실기기, 자동 알림은 이 작업의 완료 증거가 아니다.
