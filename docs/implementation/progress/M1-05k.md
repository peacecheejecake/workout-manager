# M1-05k · 훈련 계획 명시 승인 transaction

상태: **completed**. M1-05j의 불변 후보를 사용자가 명시적으로 확인할 때만 새
PlanVersion을 만든다. 승인 요청은 후보 ID·서버 digest·`confirmed: true`·멱등 키를
참조하며 클라이언트 계획 초안을 받지 않는다. tenant 잠금 아래 후보 원장 무결성,
read basis·동의·정책·전체 원장 의존성, 현재 계획 head와 지역 날짜, 세션 잠금·완료
보고를 재검사한다. 저장된 초안을 현재 근거로 재투영하고 diff·검증 결과가 봉인된
본문과 같으며 error/unknown이 없을 때만 적용한다.

새 계획 버전, `candidate_approved` 이력, 최소 ID만 담은 outbox, 요청 해시와 버전
ID만 담은 receipt를 한 transaction에 기록한다. 동일 키 재전송은 원래 버전을
반환한다. 다른 키의 동시 승인 한쪽은 최신성 충돌로 거절하고, outbox 충돌 시 계획
버전·이력·head 변경이 모두 롤백된다. 승인 뒤 AI 동의 철회는 후보 본문을 회수하되
이미 승인한 계획의 동일 키 재전송을 유지한다. 내보내기는 회수된 후보와 승인 이력을
구분하고 계정 삭제는 둘 다 제거한다. 비프로덕션 fixture 경로에서만 현재 API를
연결하므로 실제 모델의 후보 품질이나 프로덕션 사용 가능성을 증명하지 않는다.
