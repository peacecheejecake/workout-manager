## 범위

사용자 등록/수정/조회 입력과 결과를 strict runtime DTO로 만들고, RaceEvent 계획과 RaceResult/TrainingBest 실제를 분리한다. 서버 소유 revision/id/official verification 시각의 입력 권한을 구별하고 명시 mutation의 expectedRevision과 idempotency를 정한다. Course revision은 고정 참조이며 연결 Plan을 자동 변경하지 않는다. 날짜 변경의 영향 preview·별도 승인은 후속 use case이고 PB 포함/순위 정책을 이 단계에서 임의 선택하지 않는다.

Root가 graph·공통 exports·runtime 조합·migration을 통합한다. Agent는 새 command 계약/집중 시험과 기존 저장 use case 대조를 맡는다. contract/consumer typecheck 및 invalid boundary 시험 전 완료로 기록하지 않는다. DB transaction/RLS/API/UI·실제 공식 결과·운영/기기 수용은 미실행이며 계약만으로 통과시키지 않는다.

## 후속 저장 경계

현재 `Course` 삭제는 revision을 실제 제거하므로 RESTRICT FK를 무조건 추가하면 기존 삭제가 깨진다. 고정 참조의 unavailable 표시, Activity tombstone과 중복/재생성 방지, tenant별 Plan·Course·Activity/RaceEvent 참조 검증을 저장/조회 경계에서 다룬다. Export allowlist/schemaVersion30, 계정 erasure 및 exact restore suppression, migration 명시 목록·role grants/runtime role ownership guard를 함께 갱신해야 한다. 이 대조는 실행 수용 증거가 아니다. PB 순위·공식 원격 검증·app/provider 의미를 여기서 결정하지 않는다. 부모 M2-02와 모든 외부 gate는 미완료 상태다.
