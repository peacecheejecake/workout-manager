# M1-04i · 활동 계획 연결·관측 영향 상세

상태: 완료. S09·V2-F14의 지도와 독립적인 관측 영향 상세를 구현했다.

## 구현과 해석

- `GET /activities/:id/context`는 인증된 소유자의 활성 활동과 명시 연결한 불변 계획 버전,
  세션·Block·현재 head ID·관측 부분 합계를 단일 SQL 스냅샷에서 읽는다.
  활동 revision과 삭제 이력을 포함한 collection revision 기준도 같은 스냅샷이다.
- 계획 head가 바뀌어도 연결한 과거 버전을 현재 버전으로 대체하지 않는다. 날짜나 종목으로
  링크를 추측하지 않는다. 연결 없음, 연결 대상 확인 불가, 지원 불가 달력 범위를 구분한다.
- 거리 차이는 두 값이 알려졌을 때만 실제−계획으로 계산한다. 0은 유효하고 미확인은 null이다.
  계획 시간에는 측정 정의가 없으므로 실제 timer/elapsed/moving 시간과 차이를 계산하지 않는다.
- 연결된 Block의 시간대·날짜 범위에서 모든 종목의 활성 정본 활동을 한 번씩 집계한다.
  다른 계획에 연결되거나 미연결인 기록도 포함한다. 부분 합계에 알려진/미확인 건수를 표시하고
  시간 정의별로 구분한다. 초기 수동 자기보고는 정정 수에 포함하지 않는다.
- 대상 활동의 실제 날짜를 Block 시간대로 투영하여 포함/범위 밖/시각 미확인을 구분한다.
  포함될 때만 이 활동 자체의 알려진 기여 값을 별도로 표시한다. 전체 합계를 한 건의 영향으로 표시하지 않는다.
- legacy year 0000과 시간대 투영 후 0001~9999 범위를 벗어나는 날짜가 있으면 계산 불가를 반환한다.
  날짜를 바꾸거나 미보고·0으로 숨기지 않는다. UUID 대소문자를 동등하게 해석한다.
  foreign/missing 링크는 노출하지 않으며, DTO 자체가 손상된 저장 보고는 검증 경계에서 거절한다.
- 활동 목록의 선택 상세는 새 context 응답에 든 활동과 계획을 함께 사용한다. 서로 다른 GET 결과의
  수정 번호를 섞지 않는다. 현재 버전에 연결된 경우만 Planner의 해당 날짜로 이동한다.
  과거 버전은 읽기 전용 정보로 표시한다. 기존 상세 오류·404·페이지 밖 선택 동작을 유지한다.
- 수집 완전성·계획 이행률·기여율·훈련 부하·부상 위험·회복 효능은 계산하지 않는다.
