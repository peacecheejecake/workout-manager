# M2-01k-t · 두 shell의 비공개 화면·계정 전환 수명

상태: **로컬 완료, phase 독립 검토 전**. 기준 `main` `41058a1`. `M2-01k-s`는 Next의 대시보드·웰빙·활동 편집과 Vite의 나머지 다섯 화면을 검증했지만 Vite의 세 화면 경로가 없었다. 이 노드는 두 shell의 제품 경로를 맞추고 P5 로컬 계정 수명 증거를 보강한다. 운영 OIDC, 물리 기기, OS foreground 전달은 별도 조건이다.

## 구현과 직접 검증

- Vite shell에 `/dashboard`, `/wellbeing`, `/activities/new`, `/activities/:id/edit`를 lazy route로 추가했다. Next와 같은 공통 모듈·인증 workspace를 사용하며 편집 ID는 활동 런타임 스키마로 검사한다. 새 workspace 의존성과 lockfile을 함께 갱신했다.
- 독립 phase 검토에서 Vite 활동 목록에 정정 화면 링크가 전달되지 않는 결함을 발견했다. Vite의 공통 `ActivityBrowser`에 생성·정정 경로를 연결하고, 실제 활동을 목록에서 선택해 정정 화면으로 이동하는 Next/Vite 브라우저 검사를 추가했다.
- `product-private-lifetime.spec.ts`는 Next/Vite 모두 활동 편집·계획·코칭·회복·자료·웰빙·대시보드의 저장된 Alice 값, 활동의 미저장 초안, 명시 로그아웃 후 과거 탭의 비공개 UI 제거, Bob 로그인 뒤 Alice 값 부재를 검사한다. 두 shell의 활동 생성 화면과 잘못된 편집 ID 경계도 직접 연다. 로그아웃 구간에는 합성 이벤트를 보내지 않는다. Headless 환경의 Bob 로그인 뒤 전경 재검증에는 합성 `focus`를 명시적으로 사용하므로 물리 OS 이벤트 전달의 근거로 쓰지 않는다.
- 기존 `course-account-switch.spec.ts`의 늦게 전달된 Alice 200 응답 차단, `M2-01k-q/r/s`의 cache·worker·draft 변이 증거는 유지한다. 이번 새 경로 검사만으로 전체 P5 행을 `passed`로 바꾸지 않는다.

## 로컬 검사와 한계

- Node 24.12.0에서 `pnpm install --lockfile-only --offline`과 `pnpm install --offline --frozen-lockfile`이 통과했다. `pnpm check:generated`, `pnpm format:check`, `pnpm lint`, `pnpm typecheck`(34/34), `pnpm build`(15/15), 전체 Vitest(360파일·4,249시험), 격리 PostgreSQL 통합(87파일·844시험)이 통과했다.
- 새 identity 집중 시험은 빌드 전 오래된 Vite preview 산출물, dashboard의 최근 체크인 상태, 중복 제목 locator를 각기 확인하고 수정했다. 최신 빌드와 locator에서 Next/Vite 네 시험 **4/4 통과**했다. 이 초기 실패들을 통과로 소급하지 않는다.
- 전체 identity E2E는 2회 각각 **310 통과·11 조건부 건너뜀·실패 0**이었다(각 14.6분). 최종 `pnpm format:check`, `pnpm lint`, `pnpm typecheck`(34/34), `git diff --check`, graph·매트릭스 JSON 파싱도 통과했다. phase 독립 검토는 이어서 수행한다.
- Aside skill의 설치 업데이트가 `fetch failed`여서 Aside 실행이 불가했다. Chrome 연결은 보였지만 Mac 네이티브 제어가 잠금 상태였고 수동 제품 관찰은 완료하지 못했다. Playwright가 이번 UI 변경의 브라우저 대체 도구다. 실제 OS focus·WKWebView·운영 Zitadel 동작은 `not_executed`로 남긴다.
- 독립 검토 `41058a1...d81ae02`는 **CHANGES REQUIRED**: Vite 활동 목록의 `editHref` 누락(P2). 수정 뒤 Vite build, Vite typecheck, 전체 format 검사가 통과했다. 첫 격리 E2E는 대체 포트에 맞춰 Next를 다시 빌드하지 않아 실제 Zitadel 화면으로 잘못 연결되며 4건 실패했다. 해당 빌드를 바로잡고 동일한 집중 E2E를 재실행해 Next/Vite **4/4 통과**했다. 이 첫 실패는 코드 통과 기록으로 취급하지 않는다. 수정된 diff의 독립 재검토는 아직 남았다.

`P5-logout-clear`는 이번 로컬 범위가 통과해도 운영 OIDC·실기기·OS focus가 남아 **partial**로 유지한다. 과거 `P8-coverage: failed`와 다른 외부 `not_executed` 판정은 변경하지 않는다. 부모 `M2-01k`는 계속 `in_progress`다.
