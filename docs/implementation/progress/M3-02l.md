# M3-02l · HealthKit 운동 등록 API 경계

상태: **in_progress**. M3-02k의 로컬 PostgreSQL 수용 뒤 등록·목록과 v2 수신 경로를 연결했다. 개별 등록 해제의 정리 중/완료 계약·삭제 수명주기·복원 및 최종 API 연결은 아직 완료하지 않았다.

## 등록·목록·v2 수신 준비(2026-10-05)

`healthkit-registration-routes.ts`는 등록·목록의 계정을 인증된 bearer principal에서 유도하고 runtime 입력·응답 계약, 상한, 동의/registry revision과 안전한 오류 매핑을 적용한다. cookie 인증은 BEARER_REQUIRED로 거절한다. 등록의 idempotency key는 저장소에 그대로 전달한다. configured API와 product routes에서 실제 등록 저장소를 연결했다.

`healthkit-ingestion-routes.ts`는 등록된 v2 batch/ACK를 검증하며 구형 v1을 저장소 호출 전 409 LEGACY_BATCH_UNSUPPORTED로 거절한다. 등록/list·수신 Fastify inject **2파일·13시험**, 기존 activity/binding/review **3파일·10시험**, 합계 **5파일·23시험 통과**. API typecheck, 변경 파일 ESLint·Prettier·diff 검사가 통과했다.

이 결과는 로컬 합성 API 경계의 검증이다. 실제 HTTPS·native·HealthKit 운동 선택·서명 iPhone 수용은 실행하지 않았다. 개별 해제는 관련 객체의 비동기 정리가 완료될 때까지 claim을 유지하고 pending_cleanup과 released를 구분하는 서버 계약·복원 경계가 먼저 필요하다. 전체 노드와 phase 검토는 남아 있다.
