# M3-02l · HealthKit 운동 등록 API 경계

상태: **completed (로컬 서버·계약 수용)**. 등록·목록·v2 수신과 개별 등록 해제의 runtime 계약/API·객체 정리 worker·복원·export를 구현했다. 루트가 결합 소스·실제 검증 기록을 확인했다. 운영 HTTPS·native 선택/수집·실기기 수용은 m/n/o/h의 별도 후속 조건이다.

## 등록·목록·v2 수신 준비(2026-10-05)

`healthkit-registration-routes.ts`는 등록·목록의 계정을 인증된 bearer principal에서 유도하고 runtime 입력·응답 계약, 상한, 동의/registry revision과 안전한 오류 매핑을 적용한다. cookie 인증은 BEARER_REQUIRED로 거절한다. 등록의 idempotency key는 저장소에 그대로 전달한다. configured API와 product routes에서 실제 등록 저장소를 연결했다.

`healthkit-ingestion-routes.ts`는 등록된 v2 batch/ACK를 검증하며 구형 v1을 저장소 호출 전 409 LEGACY_BATCH_UNSUPPORTED로 거절한다. 등록/list·수신 Fastify inject **2파일·13시험**, 기존 activity/binding/review **3파일·10시험**, 합계 **5파일·23시험 통과**. API typecheck, 변경 파일 ESLint·Prettier·diff 검사가 통과했다.

이 결과는 로컬 합성 API 경계의 검증이다. 실제 HTTPS·native·HealthKit 운동 선택·서명 iPhone 수용은 실행하지 않았다. 개별 해제는 관련 객체의 비동기 정리가 완료될 때까지 claim을 유지하고 pending_cleanup과 released를 구분하는 서버 계약·복원 경계가 먼저 필요하다. 전체 노드와 phase 검토는 남아 있다.

## 개별 해제와 실제 객체 정리 연결(2026-10-05)

096은 인증 계정·동의/registry revision·claim epoch·멱등 키를 검사하고 해당 운동의 raw/lineage/binding·private receipt와 HealthKit 소유 canonical 기록을 정리한다. 독립된 manual/FIT/Garmin 기록은 보존한다. 객체 정리가 끝날 때까지 `pending_cleanup` claim을 유지하고 목록·수신·binding 재진입을 차단한다. 실제 DB 정리 사실·lease·미인식 객체·관련 upload/publication fence가 충족된 뒤에만 `released`로 바뀌며 B의 명시 등록을 허용한다. 과거에 지워진 코스의 lineage가 없는 경우 같은 계정의 미완료 코스 정리를 보수적으로 기다린다.

API는 bearer principal에서 계정을 유도하고 요청/상태 조회만 제공한다. client finalize endpoint는 없다. 097의 private work queue와 DB 시계 lease/token 검증을 기존 cleanup worker에 연결했다. 일반 API role은 직접 finalize 실행 권한이 없고 worker는 좁은 lease/finish/failure-count 함수만 실행한다. 철회·계정 말소 시 작업은 FK로 정리되며 기존 094의 귀속 삭제 정책을 유지한다. 실패 20회 작업은 보존하고 상한 있는 건수로 계측한다.

batch receipt에는 실제 v2 생산자가 검증한 UUID membership을 보관한다. 해당 UUID를 포함한 batch와 해당 운동 command receipt만 삭제 억제한다. 혼합 batch는 전체 digest/membership을 삭제하되 무관한 batch의 원래 ACK·성공 재시도는 보존한다. 과거 membership 미상 receipt는 `RECEIPT_MEMBERSHIP_REQUIRED`로 원자적 거절하며, 원래 v2 payload의 정확한 digest 재시도만 membership을 채울 수 있다. 임의 backfill은 없다.

**과거 v1 자료 제한:** 미삭제 역사적 v1 receipt도 membership 미상으로 해제를 차단한다. v1은 정확한 v2 재시도로 membership을 복구할 수 없다. 이 계정의 안전한 기존 자료 처리 경로는 M3-02o의 감사·배포 준비에 남으며, 현재 API 수용으로 해결됐다고 세지 않는다.

export v30은 소유자에게 active/pending claim과 최소 operation 사실만 내보내며 epoch·digest·키·객체 scope·실행 가능한 replay payload를 노출하지 않는다. 역사적 v2–v29 계약을 보존한다. 암호화 suppression v3의 pending/released 사건은 owner-only exact replay에 연결했다. 원래 A 사건이 B 또는 A의 새 epoch를 삭제하지 않는지, 변경된 사건 재시도와 선행 pending 없는 released를 거절하는지 실제 PostgreSQL로 검증했다. 실제 운영 PITR·원격 객체·tail/ACK 복원은 이 결과에 포함되지 않는다.
