# M1-06a · 운영·계정 삭제·내보내기

확인일: 2026-09-16. 상태: **M1 운영 기반 완료**. 현재 구현된 계획·활동·동의 데이터를 대상으로 한다.
FUT-02와 기존 운영·권한·삭제 요구사항에 해당한다. 공식 provider, media/RAG, 운영 배포는 각 후속 task 범위다.

## 구현

`/account`에서 앱 내부 outbox 대기·처리 중·재시도·완료 수, 최근 내 데이터 작업 10개를 조회한다.
재시도 수는 대기 작업 중 이전 시도가 있는 부분집합이다. 내부 이벤트 개수를 운동 수행이나 provider
동기화 성공으로 표시하지 않는다. Garmin/HealthKit은 연결되지 않았다고 표시한다.

명시적으로 내보내기를 요청하면 현재 계정의 동의, 모든 계획 버전·head·history,
활동 정본·원본 revision·정정 revision·suppression을 JSON으로 내려받는다.
로그인 자격, token, command receipt, 내부 outbox payload는 내보내지 않는다.
고정된 SQL 테이블·열 allowlist와 단일 statement snapshot을 사용한다.
컬렉션별 1,000행 또는 전체 8 MiB 상한 초과는 오류이며 잘린 자료를 완전한 내보내기로 반환하지 않는다.
대용량 비동기 export는 후속 확장이 필요하다.

계정 삭제는 `DELETE MY ACCOUNT` 입력과 명시 버튼을 요구한다. API에서도 정확한 확인문구,
인증·세션 일치·Origin/CSRF를 검사한다. 하나의 거래에서 건강 자료와 계획 이력, 원본·정정,
동의·receipt·outbox, 앱 OIDC 계정 매핑과 모든 세션을 제거한다. 외부 OIDC/Garmin 계정은 삭제하지 않는다.
식별할 계정이 없는 미완료 OIDC 로그인 시도는 기존 짧은 만료 정책을 유지한다.

일반 tenant 거래의 공유 잠금과 삭제의 배타 잠금을 같은 lifecycle key로 잡고, 기존 command lock과
namespace를 분리했다. 실행 중인 쓰기가 끝난 뒤 삭제하며 이전 계정 ID를 가진 늦은 작업은 거절한다.
삭제와 동시에 로그인하는 경우도 이전 ID를 되살리지 않는다. 이후 로그인은 새 앱 계정이다.
삭제 방지를 위한 불투명한 과거 계정 ID·삭제 시각과 내용 없는 삭제 이벤트만 남긴다.
runtime은 이 원장을 변경하거나 immutable 계획 기록을 직접 지울 수 없다.

클라이언트는 계정·세션별 Query cache를 사용한다. export 자료는 Query cache나 브라우저 저장소에
보관하지 않는다. 다운로드 Blob은 교체·unmount·세션 종료 시 해제하고 지연 응답을 버린다.
삭제 실패 뒤에는 확인 문구를 다시 입력해야 한다. 계정 전환/만료를 확인하면 private cache를 비운다.

## 백업·복구

[운영 실행 기록](../operations-runbook.md)과 [실행 결과](../research/backup-restore-result.json)를 참고한다.
합성 자료만 사용한 실제 PostgreSQL custom dump/restore를 실행했다. 백업 뒤 삭제한 계정의 최신
삭제 원장을 별도로 보관해 복구 후 재적용하고, 모든 복구된 세션·로그인 시도를 폐기한 다음 runtime
접근을 시험했다. 다른 계정은 보존하며 삭제한 계정의 13개 건강/command 테이블과 identity 자료가
되살아나지 않는지 검사했다. 운영 backup 저장소·암호화·retention job·RPO/RTO의 검증은 아니다.

## 검증

정확한 실행 결과와 독립 Herdr 리뷰의 base/tree는 task 커밋 메시지에 기록한다.
`pnpm check` 332개, `pnpm test:integration` 실DB 47개, `pnpm test:identity` 5개,
Next/Vite/Storybook build 7개 task와 실제 backup/restore drill 8개 검사를 통과했다.
API 경계 시험은 계정 ID 주입 거절, 인증·CSRF·세션/확인문구, export 크기 오류와 로그 비밀 누출을 검사한다.
실DB는 tenant 격리, export 상한, immutable 기록 삭제, rollback, 동시 쓰기/로그인/삭제,
비-superuser definer의 FORCE RLS, stale write 차단을 검증한다.
실제 OIDC·API·DB E2E는 다운로드 내용, 두 탭 세션 폐기, 재로그인 시 새 ID/빈 활동,
320/767/768/1280px reflow를 검증한다. 과거 문서의 미실행 항목을 일괄 통과로 변경하지 않는다.
Aside 실 브라우저에서 로컬 합성 OIDC 계정으로 로그인해 운영 상태, 내보내기 준비와 다운로드 링크,
audit 갱신, 확인 문구 전/후 버튼 활성화, 삭제 후 로그인 화면 복귀를 확인했다.
