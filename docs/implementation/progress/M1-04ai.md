# M1-04ai · 사용자 세션 완료 원장·이동 보호 API

상태: 구현·검증 완료. 사용자는 명시적으로 확인하는 완료 상태를 추가하고 이동을 막기로 선택했다.

## 범위와 의미

- 완료는 계획 목표·actual 측정과 별도의 사용자 자기보고다. 사용자+stable session ID별
  revision 원장에 확인한 불변 계획 버전·일정·확인 시각·정정 사유를 보관한다.
- 활성 완료 확인이 있는 세션의 날짜·Block·시작 시각·시간대 변경과 삭제를 서버에서 막는다.
  거리·시간 합계를 생성하거나 실제 활동 연결에서 완료를 추정하지 않는다.
- 현재 저장 head와 보고 revision을 모두 확인한다. 완료 확인/철회와 계획 저장은 같은
  사용자 직렬화 lock을 사용한다. 중복 명령은 최초 영수증을 반환하며 추가 기록을 만들지 않는다.
- 철회와 재확인은 명시 정정 사유가 있는 별도 명령이다. 일반 초안 undo나 이전 계획 버전
  재사용은 완료 보고를 지우지 않는다. 새 ID로 복제한 세션은 완료 보고를 상속하지 않는다.
- 보고 없음은 미수행·실패가 아니다. 확인 시각은 실제 운동 종료 시각이 아니며 계획 날짜로
  실제 수행 시점을 추정하지 않는다. 현재 단일 계획 계보에서 session ID는 지속 식별자다.
- 읽기/API·RLS·전체 계정 export/erase를 포함한다. 완료 확인 UI는 M1-04aj,
  자식 포함 기간 날짜 이동의 영향 확인은 M1-04ak에서 연결한다.

## 검증

- `pnpm check --maxWorkers=2`: format/lint/typecheck 및 88개 파일의 1,038개 시험 통과.
  E2E와 병행한 첫 실행에서 기존 20k 활동 차트 시험이 5초 제한을 초과했다.
  다른 검증 종료 후 같은 명령으로 전체 재실행해 통과했다. 제한이나 규칙은 변경하지 않았다.
- `pnpm test:integration`: 실제 PostgreSQL 15개 파일 127개 시험 통과. 완료/이동 동시 요청,
  중복 영수증, 다른 tenant 차단, outbox 실패 rollback, 200자 ID, 102회 정정의 최근 100개 이력,
  완료 일정 보호·철회 후 이동·삭제·export를 포함한다.
- `pnpm build`: 7개 build task 통과.
- `pnpm test:identity`: 실제 OIDC/API/DB 전체 70개 E2E 통과. 새 완료 API 시험은 확인 응답 유실 후
  동일 키 재전송, 이동 차단, 다른 사용자 404, 철회 후 이동, 오래된 계획 충돌, 재확인을 검증한다.
- 백업/복원 drill: 13개 검증 통과. 복원 후 완료 보고·이력·영수증·일정 보호 유지와
  삭제 ledger 재적용 후 새 4개 테이블 제거, 남은 사용자 보존을 검증했다.
  [실행 결과](../research/backup-restore-result.json)의 이전 실행 기록도 보존했다.
- DAG: 76개 node의 참조·비순환 확인. UI 변경이 없어 이번 task는 Aside 대상이 아니다.
  UI와 실 브라우저 검증은 M1-04aj에 남아 있다.
- Herdr split-pane 독립 리뷰의 대상 base/tree, 결과와 수정 내역은 이 task 커밋 본문에 기록한다.

## 호환성과 운영

- migration 010과 runtime 권한을 추가했다. `grantSessionCompletions`는 필요한 읽기/쓰기 권한만
  부여하며 새 테이블도 강제 RLS·runtime owner 검사·계정 삭제 대상이다.
- 계정 내보내기는 완료 현재 상태·전체 이력을 포함하는 v3를 생성한다. 기존 v2 읽기는 유지하며
  v2에 없던 보고 자료를 임의 생성하지 않는다.
- 현재 계획에서 삭제된 세션의 보고는 현재 조회에 나타나지 않지만 내보내기 이력에 남는다.
  확인 시각은 서버 기록 시각이고, 미래 계획일의 확인도 실제 운동 시점을 주장하지 않는다.

규칙과 외부 출시 gate는 변경하지 않는다.
