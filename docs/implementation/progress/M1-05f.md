# M1-05f · 사용자 확인 필수 제약 원장·상담 UI

상태: **구현·검증 완료**. 선행 M1-05c·M1-06a 완료. S10/FUT-04의 사용자 필수 제약 기반.

## 구현

- 사용자가 직접 작성·확인한 문장(최대 2,000자, 활성 50개)을 별도 원장에 저장한다.
  미기록 head와 명시적으로 비운 원장을 구분한다. 의료 판단이나 자동 일정 규칙으로 해석하지
  않으며 기간별 운동 불가 날짜·가용 시간 및 세션 완료 상태와 별도다.
- POST/PUT/DELETE는 사용자 확인과 전체 head·항목 revision을 검사하고 원장·receipt·outbox를
  원자적으로 기록한다. 동일 키는 같은 결과 metadata만 반환한다. receipt에는 요청 해시만,
  outbox에는 ID/revision/삭제 여부만 보관한다. 정정은 현재 본문을 교체하고 삭제는 NULL로 비운다.
- Migration 014, FORCE RLS, 제한 DML, 불변 ID·삭제 tombstone, 계정 삭제 및 export v7의 두
  컬렉션을 연결했다. v2~v6 다운로드 읽기는 과거 컬렉션을 합성하지 않고 유지한다.
- 상담 화면의 제약 영역은 선택한 상담 유무와 무관하게 표시한다. 명시 검토·확인·취소,
  충돌 시 초안 보존과 최신 원장 검토, 응답 유실 시 같은 key/body 재확인을 제공한다.
- session별 메모리 Zustand 초안과 TanStack Query 응답을 분리한다. 재조회 중 이전 목록을
  숨기고 변경 성공 후 cache를 초기화하며 계정 교체/이탈 시 정리한다. 다른 항목 삭제가
  작성 중인 초안을 지우지 않는다. 서버 push는 없으므로 다른 창 변경은 최신 제약 확인으로 조회한다.
- backup drill은 최신 외부 owner/head/현재 행·tombstone 원장을 계정 삭제 적용 후 복원한다.
  불완전 원장·revision 역행·동일 revision의 본문 변경·tombstone 부활을 거절하고 rollback한다.
  실제 운영 보관·전달 인프라와 RPO/RTO가 완료되었다는 의미는 아니다.
