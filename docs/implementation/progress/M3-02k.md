# M3-02k · HealthKit 전역 UUID 귀속 원장·수신 차단

상태: **in_progress**. [계정별 운동 등록 ADR](../research/healthkit-account-registration-adr.md)와 [M3-02j 계약 기록](M3-02j.md)에 따른 서버 영속화 범위를 구현하고 합성 자료로 집중 검증했다. 기존 HealthKit 회귀·계정 내보내기·복원·안전한 rollback 검증과 후속 API/native 연결이 남아 있어 노드를 완료 처리하지 않는다. 이 기록은 과거 M3-02a–i 검증 결과를 소급 변경하지 않는다.

## 현재 구현 범위

- `packages/server/persistence/migrations/094_healthkit_workout_registration.sql`: 전역 `sample_id` 기본 키로 활성 UUID의 단일 귀속을 보장하는 claim, 계정별 registry head와 등록 idempotency receipt를 추가했다. 세 테이블에 tenant RLS와 `FORCE ROW LEVEL SECURITY`를 적용했다. `tenant_erasure` 삽입 후 실행되는 definer trigger가 계정 말소 시 세 테이블을 지운다. 기존 raw를 소유권 증거로 자동 backfill하지 않는다.
- `packages/server/persistence/src/healthkit-registration.ts`: 명시적 귀속 선언·동의 revision·registry revision을 검사하는 등록/목록 저장소다. 등록은 계정 명령 잠금과 현재 동의 확인 뒤 한 거래에서 처리한다. 전역 UUID 충돌은 계정 식별자를 노출하지 않는 `CLAIM_CONFLICT`로 반환한다. 동일 idempotency key의 동일 요청은 원래 claim epoch·revision을 반환하고, 다른 key로 활성 UUID를 다시 등록하면 충돌한다. 목록 cursor는 계정 digest와 registry revision에 묶어 다른 계정 재사용과 stale cursor를 거절한다.
- `packages/server/persistence/src/healthkit-ingestion.ts`: 구형 `schemaVersion: 1`과 무등록·타 계정·오래된 claim epoch 또는 동의 revision의 v2 이벤트를 receipt/raw 쓰기 전에 거절한다. 등록된 v2 이벤트의 ACK·raw 저장·삭제 tombstone은 기존 거래 경계 안에서 처리한다. 개별 운동 등록 해제는 구현하지 않았다.
- 루트 통합 변경인 `packages/server/persistence/src/migrate.ts`가 094를 등록하고 runtime role에 registry head `SELECT,INSERT,UPDATE`, claim과 registration receipt `SELECT,INSERT`를 부여한다. `packages/server/persistence/package.json`은 public `./healthkit-registration` subpath를 노출한다. 이 공유 파일들은 이 저장소 slice의 소유 범위 밖에서 통합됐다.
- 집중 검증 파일은 `packages/server/persistence/tests/healthkit-registration.integration.test.ts`다.

## 2026-10-05 실행한 검증

- `/private/tmp`의 일회용 실제 PostgreSQL 14에 `migrate()`와 runtime grants를 적용한 뒤 집중 Vitest **1개 파일·5개 테스트 통과**. 합성 UUID만 사용해 동시 A/B 단일 소유자·RLS, v1/미등록 수집 차단, 등록 멱등과 동일 owner의 다른 key 충돌, 계정 간/stale 목록 cursor, 계정 말소 후 B의 명시 재등록, 등록된 삭제 UUID의 tombstone을 확인했다. 임시 DB는 실행 종료 시 정지·삭제했다.
- `@workout/server-persistence` typecheck와 build, `@workout/api` typecheck, 변경 TypeScript 파일 ESLint·Prettier, `git diff --check` 통과. API typecheck는 새 v2 경로의 동작 검증이 아니다.
- 첫 실DB 시도에서는 테스트 기대값과 claim 조회의 `FOR SHARE` 권한 요구 때문에 5건 중 4건이 실패했다. 테스트의 registry revision·계정별 집계와 Promise 오류 기대값을 바로잡고, 계정 말소가 tenant gate로 직렬화되는 현재 정책에 맞춰 claim을 `SELECT`로 검사한 뒤 위 **5/5**를 재실행했다. 초기 실패를 통과로 세지 않는다.

## 남은 통합·정책 게이트

- 현행 `apps/api/src/healthkit-ingestion-routes.ts`는 여전히 v1 batch/ACK를 파싱한다. 새 저장소는 v1을 차단하므로 배포 전 M3-02l에서 등록·목록 및 v2 수신 경로와 안정적 오류 매핑을 연결해야 한다.
- 기존 `apps/api/tests/healthkit-ingestion-routes.test.ts`와 persistence 실DB 회귀 7개 파일(`healthkit-ingestion`, `healthkit-activity`, `healthkit-binding`, `healthkit-review`, `healthkit-consent-suppression-event`, `activity-tracks`, `dashboard`)은 v1 수신 성공을 가정한다. **이 파일들은 현재 변경에 맞춰 갱신하거나 재실행하지 않았다.** 과거 증거를 보존하면서 명시 등록 ACK→claim epoch→v2 fixture로 전환하고 v1 무기록 거절을 별도로 검증해야 한다.
- 계정 export v28의 `healthKitWorkoutSamples`·batch receipts에는 새 claim/head/registration receipt가 포함되지 않는다. UUID가 담긴 등록 receipt의 안전한 export projection·계약 버전, 동의 철회 때 claim/receipt를 유지하거나 지우는 정책, 백업 복원과 기존 raw 격리, 서버 선배포 rollback은 후속 통합 검증이 필요하다. 계정 **말소** 후 다른 계정 재등록 허용 결정만 확정됐다. 동의 철회 후 동일 UUID 재등록은 임의로 허용하지 않는다.
- AWS, 제품 iPhone, 서명된 HealthKit collector를 실행하지 않았다. M3-02h 실기기 수용은 **not_executed**다.
