# M1-04x · FIT 구간·시계열 상세 수입·저장 기반

상태: 완료. S09 / V2-F13의 지도 독립 상세 데이터 기반.

## 계약과 범위

- 기존 summary export v1과 source ID를 보존한다. 명시 opt-in 상세 export v2는
  source revision 2·별도 idempotency key로 같은 canonical 활동을 보완한다.
- stream 경계를 보존하고 global session ordinal은 기존 source ID와 일치시킨다.
- FIT summary timestamp는 기록 시각이며 구간 끝으로 사용하지 않는다. 시작 시각과
  elapsed duration이 있는 경우에만 시간 범위를 계산한다.
  [Garmin 공식 시간 범위 정의](https://forums.garmin.com/developer/fit-sdk/b/news-announcements/posts/important-fit-activity-file-message-change)를 따른다.
- record timestamp·거리·심박과 lap 시작/기록 시각·elapsed/timer·거리·심박을 보존한다.
  null/0·중복 timestamp·소스 순서를 보존하고 interpolation·실제 활동 분할을 하지 않는다.
- 다중 session의 누락/겹치는 범위나 record/lap 소속이 모호하면 명시 실패한다.
  단일 session stream의 timestamp 없는 record는 그대로 보존할 수 있다.
- 상세는 source revision의 nullable JSONB로 별도 저장한다. summary와 원자 저장하고
  현재 source revision만 조회한다. overlay로 원본 시간축을 자동 이동하지 않는다.
- 기존 receipt/동일 revision conflict·stale·suppression·RLS·계정 export/erase를 유지한다.
- record 20,000개·lap 1,000개·상세 JSON 4 MiB, 개별 import request 5 MiB,
  전체 import 파일 16 MiB로 제한하고 초과는 축약 대신 명시 실패한다.
  DB의 JSONB text 표현은 공백 증가를 고려해 5 MiB까지 허용한다.
  여러 session의 공유 경계에 관측이 있으면 유일 소속을 확정할 수 없어 실패한다.
  summary의 기록 순서나 timestamp로 소속을 추측하지 않는다.
- GPS는 이 형식에 포함하지 않는다. S09 상세 UI는 M1-04y,
  GPS/map 연동·coverage gate는 기존 후속 작업으로 남긴다.

## 검증

- 계약 50 tests(활동 기존+상세) 중 상세 14 tests를 검증했다. 실제 Python synthetic FIT
  export fixture를 TS runtime schema가 변경 없이 읽는다.
- Python 전체 57 tests와 전체 Ruff check/format 통과. binary FIT Summary First/Last와
  chained stream, 모호한/누락 소속·0/null·중복 timestamp·제한·원본 변경·overflow를 검증했다.
- 최종 실제 격리 PostgreSQL integration 13 files / 114 tests 통과.
  첫 실행은 migration 기대 목록이 8개여서 실패했고, 신규 9번째 migration 기대를 반영했다.
  기존 v1 receipt·동시 v2 보완·동일 revision 상세 충돌·stale·overlay 시간 보존·RLS,
  outbox 실패 시 전체 rollback·재시도·삭제 suppression·export 8 MiB 한도·계정 erase를 확인했다.
- API/수입 UI focused 95 tests 통과. import route만 5 MiB로 확장했으며 다른 write는
  기존 16 KiB 제한을 유지한다. 인증·CSRF·소유권·UUID/query/상세 schema를 검증한다.
- 최종 `pnpm check` 61 files / 778 tests, production build 7 tasks 통과.
  첫 check에서 계약 테스트의 Node 전용 파일 읽기가 browser package 경계에 걸렸으며,
  fixture JSON import로 바꾼 후 전체 검사를 통과했다. 규칙은 수정하지 않았다.
- 실제 OIDC/API/격리 DB E2E: 신규 상세 수입 1 test와 전체 54 tests 통과.
  v1 → v2 보완·16 KiB 초과 request·미리보기 무쓰기·같은 canonical 활동·집계 유지,
  새로고침·다른 사용자 404·기존 receipt·상세 conflict·삭제 억제를 검증했다.
- Aside에서 실제 synthetic Python export JSON 파일 업로드, 미리보기의 record/lap 개수와
  누락값, 명시 저장 전 0개/후 1개, 새로고침 후 활동 유지와 화면 캡처를 직접 확인했다.
  `setInputFiles`는 파일 배열 형태로 실행했다. 캡처:
  `activity-details-preview.png`, `activity-details-saved.png` (Aside 세션 로컬 artifacts).
- 최종 DAG·증거 경로·diff 검사 수행. Herdr 독립 리뷰의 정확한 base/tree와
  완료 판정은 이 task 커밋 메시지에 기록한다.
- 규칙과 외부 출시 gate는 유지한다. 전체 S09/GPS workbench 완료가 아니다.
