## 2. 항목 1 · 공개 CI artifact의 trace

### 2.1 결정과 근거

    둘 중 하나만 남아도 trace 값은 공개되지 않는다(2.3의 2×2 표).
- 디버깅 가능성: trace 대신 M2-01ad의 진단을 CI에서 켠다. 실패한 시험마다 가려진 `protocol.log`(그 시험의 CDP·API 기록),

## 3. 항목 2 · `sessionId` 가림 좁히기

- 앱 세션 id의 실제 형식: `identity_private.session.session_id uuid DEFAULT gen_random_uuid()`
  (`packages/server/persistence/migrations/002_identity.sql`), persistence에서 `z.string().uuid()`로 읽고 `/bff/v1/session`과
  `x-workout-session-id`로 오간다. csrfToken·cookie는 `randomBytes(32).toString('base64url')`(43자)이며 이번에 바꾸지 않았다.
- CDP flattened mode의 `sessionId`는 32자리 대문자 hex(하이픈 없음), 계획 훈련 도메인 `sessionId`는 `idSchema.max(200)`의 임의 문자열
  (`session-a`, `easy-run` 등)이다.
- 구현(`protocol-lines.ts`): `sessionId`를 `sensitiveKeys`에서 빼고, `key-value`·`serialized-property` 규칙의 key 자리에
  `sessionId(?=<구분자><UUID><따옴표>)`를 넣었다. 값 전체가 UUID이고 바로 따옴표로 닫힐 때만 가린다(대소문자 무시).
  규칙 개수·이름은 그대로(6개)이며 나머지 민감 key와 4개 규칙은 바뀌지 않았다.
  - 시험에서 넓은/좁은 규칙을 만들 수 있게 `buildRedactionRules(sessionIdValue)`를 내보낸다. 기본값이 `redactionRules`다.
- 남는 한계(안전한 쪽): planning draft store가 `crypto.randomUUID()`로 만든 계획 훈련 id는 UUID라서 key가 `sessionId`이면
  계속 가려진다. 모양만으로는 앱 세션과 구별할 수 없다. `plannedSessionId` 같은 다른 key는 원래부터 대상이 아니다.

## 6. 남은 것

- **key 없이 전달된 세션 값은 가리지 않는다**(독립 검토 N1). redaction은 key 기준이라 bare `page.evaluate` 인자
  (`{"value":"<uuid>"}`)나 URL 인코딩된 JSON(`%7B%22sessionId%22…`) 안의 세션 id는 남는다. M2-01ad 규칙에서도 같았고
  지금 그렇게 쓰는 spec은 없다. 이 진단 파일은 이제 공개 CI artifact로 자동 업로드되므로, 그런 형태로 세션 값을 넘기는
  spec을 더하면 값 기준 redaction(capture한 `/bff/v1/session` 응답에서 실제 세션 id·CSRF를 알아 가리기)을 함께 더한다.
- GitHub Actions 실제 run은 하지 않았다(push 금지). 업로드 목록은 `@actions/glob`을 같은 옵션으로 써서 모사했다. 실제 CI의
  첫 실패 artifact에서 파일 목록을 한 번 확인할 것.
- CI identity job은 이제 모든 run에서 진단을 켠다. M2-01ad의 재현 batch(28 시험 1.2 m)보다 긴 전체 run의 CI 시간 영향은
  재지 않았다(job timeout 20 m, 로컬 전체 run 약 7 m).
- 진단 가림은 알려진 형태에 대한 규칙이다. 공개 artifact에 올라가므로, 새 형태로 세션 값을 옮기는 spec(예: 다른 header 이름,
  URL query의 session id)이 생기면 규칙과 probe를 다시 확인해야 한다.
- `error-context.md`는 실패 시점 page의 aria snapshot이다. 앱이 세션 값을 화면에 그리지 않으므로 0건이었지만, 화면에 token을
  보여 주는 기능이 생기면 다시 봐야 한다.
- UUID인 계획 훈련 `sessionId`는 계속 가려진다(3절, 안전한 쪽).
