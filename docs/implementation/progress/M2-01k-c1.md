## 1. 설계 근거

### 1.1 접히는 경유점 목록(R-S13-S14, 07 §4)

07 §4의 Courses S13/S14 tablet 칸은 "지도+접히는 **경유점** 목록"이다. round 2 검토(B1)가 지적했듯 기존의 유일한
접기 control은 **코스** 목록을 접었다. 이 노드는 다음을 만들었다.

- **경유점 목록 자체가 접힌다(tablet만).** `course-waypoint-list.tsx`를 세 부분으로 나눴다.
  - `WaypointListEditor`: 상태 줄, 되돌리기/다시 실행, 목록, 추가 control을 조립한다(두 S14 화면이 공유).
  - `CollapsibleWaypointList`: 접기 상태를 가진다. `layout === 'tablet'`일 때만 "경유점 목록 접기/펼치기" 버튼
    (`aria-expanded`, `aria-controls`)을 보이고, 접으면 행을 `hidden`으로 숨겨 focus를 받을 수 없게 한다.
    접힌 동안 "경유점 N개 · 목록을 접었습니다…" 요약을 보인다. 상태 줄·되돌리기·추가 control은 접히지 않는다.
  - `WaypointEntries`: 행 렌더링만 한다. **M2-01k-i(drag)**는 이 컴포넌트에 drag를 더하면 되고, 접기·조립을
    건드릴 필요가 없다.
  - 접기는 draft가 아니라 이 목록의 표현 상태다(로컬 React state). draft revision을 올리지 않고, layout 전환을
    지나도 유지된다(tablet에서 접음 → desktop에서는 펼쳐 보임 → tablet으로 돌아오면 다시 접힘).
- **tablet에서 경유점 편집기가 지도 옆에 온다.**
  - `/courses/new`: tablet grid를 `지도 | 초안` 두 열로 했다(이전에는 한 열로 쌓였다).
  - `/courses/:id/edit`(및 `/courses`): tablet grid를 `[코스 목록(접힘, 위쪽 전체 폭)] / [지도 | 열린 코스]`로
    바꿨다. 코스 목록을 왼쪽 열로 두면 768px(작업 영역 약 720px)에서 16rem 목록 + 지도 15rem + 편집기 15rem이
    들어가지 않아 지도나 편집기가 최소 폭 아래로 떨어진다. 그래서 코스 목록을 위로 올리고(여전히 접힘) 지도와
    편집기를 나란히 두었다. **이것은 S13 tablet 배치의 변경이다.** `courses.spec.ts:416`의 tablet 단언을
    "목록이 지도 왼쪽·접으면 좁아짐"에서 "목록이 지도 위·접으면 낮아짐"으로 바꿨다. root/검토자가 이 배치를
    받아들이지 않으면 대안은 §5에 적었다.
  - 최소 폭은 이 화면의 track 크기에서 나온 container 조건으로 지킨다(07 §3): tablet 두 열은 31rem(→ 32rem 미만이면
    한 열), 새 코스 desktop은 15 + 1 + 28 = 44rem(→ 44rem 미만이면 한 열, **새로 추가**: 이전에는 420px pane에서
    새 코스 지도가 0에 가까워질 수 있었다). container query 미지원 시 한 열 fallback도 새 코스 grid에 더했다.
  - 새 코스 container 규칙은 `.newPanes` 정의 **뒤**에 둔다(같은 특이도에서 뒤의 규칙이 이기므로 앞에 두면 무효).
- `useLayoutModeFromViewport`를 `course-workbench.tsx`에서 `course-layout.ts`로 옮겼다. 목록이 스스로 layout을
  읽어야 하고, workbench ↔ waypoint-list 순환 import를 피하기 위해서다. 공개 export 경로에는 변화가 없다
  (이 hook은 package export에 없었다).

### 1.2 편집 단언 공백(제품 코드 변경 없음)

undo/redo 내용, 안전 문구, 늦은 옛 응답, 지도 상태 셋은 **이미 구현되어 있었고 단언이 없었다.** 제품 동작은
바꾸지 않고 실제 스택 E2E와 변이로 단언했다. 새 코스 초안 pane에 측정용 `data-pane="draft"`만 더했다.

- **늦은 옛 응답(V2-A35/FUT-07-2/P6):** 브라우저에서 실제 응답을 `route.fetch()`로 받아 **도착 시점만** 붙잡는다.
  엔진(harness의 결정적 fixture 포트)은 실제로 계산한다. 두 경우를 나눴다.
  1. 계산이 나가 있는 동안 초안이 바뀜: 새 초안(경유점과 그 직선 미계산 선)이 지도에 있는 상태에서 옛 답이
     도착 → 적용 안 됨, 상태 `uncomputed`(stale도 computed도 아님), 지도 좌표 목록 = 새 초안뿐, 옛 답의 꼭짓점 없음.
     이 경로를 지키는 것은 **store의 revision 검사 하나**뿐이다(요청 소유 검사는 통과한다: 새 요청이 없으므로).
  2. 새 경로가 먼저 적용됨: 느린 계산을 취소하고 다시 계산 → 새 경로 적용·검토 체크 → 취소된 요청의 답이
     도착 → 여전히 새 경로(계산 시각 = 새 답), 검토 체크 유지. 이 경로는 **취소 시 abort + 성공 경로의 소유 검사**
     두 겹이 지킨다(defense in depth). 하나만 뺀 변이는 살아남는다(§3 P2a, §8 P2b).
- **저장 실패(P5-states):** 두 가지를 구별해 단언한다.
  - 결과 불명: 서버가 저장한 **뒤** 연결을 끊는다(`route.fetch()` 후 `route.abort('connectionreset')`).
    화면은 "저장 결과를 확인하지 못했습니다…"를 말하고 초안·검토·지도 선을 유지하며 "저장된 것은 없습니다"라고
    말하지 않는다. 다시 저장하면 같은 idempotency key로 나가고 코스는 **1개**다.
  - 거절: 요청의 `reviewedGeometrySha256`을 바꿔 보내 서버가 실제로 `409 ROUTE_PREVIEW_CHANGED`를 내게 한다
    (엔진이 검토한 선을 재현하지 못한 경우를 대신한다. 서버 판정은 실제다). 화면은 "…저장된 것은 없습니다…",
    상태 `uncomputed`, 검토 그룹 없음, 지도는 점선 초안만, 저장된 코스 0개.
- **배경 없음:** 로컬 미리보기는 두 shell 모두 `basemap={null}`이다. 정확한 문구 "배경 지도 없이 경로를
  표시했습니다.", attribution 없음, `/map/basemap/` 요청 0건. 그 옆에 "배경 위에 그림"(정확한 문구
  "지도에 경로를 표시했습니다." + attribution)과 "배경 실패"(style.json 거부 → `unavailable`, "배경 지도를
  불러오지 못해…")를 같은 시험에서 단언해 셋을 구별한다. Vite shell은 배포 pointer가 없으면(404) 코스 지도도
  배경 없이 그린다는 것을 단언한다(Next는 서버에서 pointer를 읽으므로 브라우저에서 바꿀 수 없다).
- **부분 기록:** 두 `trkseg`로 끊긴 GPX → `data-state="partial"`("일부 데이터") "기록이 N회 끊겼습니다. 끊긴
  구간은 직선으로 잇지 않습니다." + 선이 그려짐. 끊김 없는 같은 기록에는 partial 표시가 없다.

## 8. 독립 검토(tree `8e3e4701`) 반영

검토는 승인(차단 0)이었고 사용자는 새 tablet 배치(코스 목록 위)를 수락했다. 다음을 반영했다.

- **N1(수정).** tablet에서 코스 목록은 펼친 채 시작하고 높이 제한이 없어, 900px 높이에서 코스 1개면 지도 상단이
  약 y=716–739, 13개면 약 y=1436–1459였다(검토자 측정). `.panes[data-layout='tablet'] .listPane`에
  `max-height: min(14rem, 35dvh)`, `overflow-y: auto`, `overscroll-behavior: contain`을 두었다. 코스가 몇 개든 목록은
  pane 안에서 스크롤되고 지도는 첫 화면에서 시작한다. **목록을 접힌 채 시작하는 안은 고르지 않았다**: S13은 목록
  화면이고, 도착하자마자 목록을 숨기면 모든 tablet 폭에서 코스 고르기가 한 단계 늘어난다. 높이 제한은 목록을 그대로
  보이면서 지도를 지킨다.
  - 시험 `course-editor-layout.spec` "keeps the map on the first screen at tablet width with many courses and the list
    open"(두 shell): 코스 12개, 768×900과 1024×900, `data-list=expanded`·목록 보임·"코스 목록 접기" 보임 상태에서
    페이지 스크롤 0, 지도 pane 상단이 0 이상이고 상단 + 160px ≤ 900, 목록 pane이 안에서 스크롤됨, overflow 0.
  - 변이 **H1** `max-height: min(14rem, 35dvh);` 줄 제거(단일 anchor): 잠금 아래 재빌드 후 세 새 spec 실행 → 두 shell 모두 **실패** "map top at 768x900"(지도 상단 + 160 = 1739 > 900). 나머지 16건 통과. 복원 `cmp-identical`, 재빌드는 turbo 전부 cache hit
- **N2.** P2b(성공 경로 소유 검사 `if (controller.signal.aborted || abort.current !== controller) return;`만 제거)도
  실제 브라우저에서는 **생존**한다. 취소 시 abort가 응답 전달 자체를 막기 때문이다. 이 E2E에서 요청 ID 절반은 두 anchor
  P2로만 죽고, 소유 검사의 단일 anchor kill은 jsdom(`course-editor.test.tsx:280/:568`)에만 있다. P2b는 이 이유로 따로
  돌리지 않았다(P2a와 같은 가림이며 논리로 확정된다) — 비공허성 근거로 쓰지 않는다.
- **N3.** 늦은 답·저장 실패 E2E는 `/courses/new`만 덮는다. 저장된 코스 편집기(`course-editor.tsx`)의 계산·소유 코드는
  jsdom이 덮고 P1의 store revision 검사를 공유한다.
- **N4.** undo/redo 시험은 각 편집 뒤 행을 바로 읽지 않고 기대 내용이 나타날 때까지 poll한다.
- **N5.** 결과 불명 뒤 재시도가 끊긴 시도가 저장한 **같은 courseId**의 편집 화면으로 가는지 단언한다(끊긴 응답 본문의
  id와 이동한 주소 비교).
- **N6.** `courses.module.css`의 접힘 주석("full width" → "full size")을 새 배치에 맞췄고, `.waypointList > div`를 전용
  class `.waypointRows`로 좁혔으며(F2 anchor도 그에 맞춰 갱신), `WaypointEntries`의 JSX 주석 들여쓰기를 고쳤다.
