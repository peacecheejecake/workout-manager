# M1-04ad · 저장된 계획 버전 조회·기간 비교

상태: 완료. S04 기간 상세의 변화 이력을 읽기 전용 버전 비교로 확장했다.

## 범위

- 인증된 사용자의 불변 계획 snapshot을 UUID로 조회한다. 미존재와 다른 사용자의 버전은
  같은 404로 응답하며 현재 계획·이력·receipt·outbox에 쓰지 않는다. 최근 100개 이력 목록은
  그대로 유지하고 목록 범위 밖의 소유 버전도 ID를 알면 조회할 수 있다.
- 이력에서 선택한 버전과 확인 시점의 현재 head ID를 URL에 고정한다. 새 head가 생겨도
  자동 교체하지 않으며 새로고침·뒤로/앞으로 탐색으로 같은 비교를 복원한다.
- 두 버전의 기간 ID 합집합에서 비교 대상을 선택한다. 각 버전의 하위 기간·Block·세션을
  독립적으로 찾고 한쪽에만 있는 기간, 세션 추가/삭제와 기간 안팎 이동을 구분한다.
- 단계 순서·null/0·단위·목적·잠금·시간대 및 legacy optional 값의 차이를 보존한다.
  조회는 기존 계획 초안·선택·actual을 변경하지 않는다. 복원·적용·branch·AI 비교는 별도 범위다.
- 두 snapshot 조회를 병렬로 수행하며 사용자/세션/버전별 캐시, 응답 ID 검증·취소·실패 복구로
  서로 다른 비교 요청의 결과가 섞이지 않도록 한다.
- 기존 snapshot 계약을 재사용하고 DB migration은 추가하지 않는다.

## 검증

- 순수 비교 10 tests, 신규 UI 7 tests와 기존 planning 24 tests, API 17 tests 통과.
  잘못된 주소·응답 ID 불일치·한쪽 실패·지연 응답·계정 캐시 분리, 두 병렬 조회의 일관된
  표시, 새 head에도 고정된 pair, 과거만의 기간·단계 순서·legacy 누락/null 구분을 검증했다.
- 실제 PostgreSQL integration 13 files / 115 tests 통과. 최초 신규 fixture가 snapshot
  100개를 직접 삽입하면서 head를 이전 버전에 둬 불변식을 깨뜨렸다. 실제 저장 명령을
  사용하도록 시험 데이터를 수정해 최신 head와 최근 100개 이력, 범위 밖 소유 버전 조회,
  소유권·legacy 본문 보존·조회 전후 receipt/outbox/history 불변을 확인했다.
- `pnpm check --maxWorkers=2`: generated/format/lint/typecheck 및 77 files / 914 tests 통과.
  기존 기본 병렬 차트 timeout 문제의 실행 worker 제한을 유지하고 규칙·설정은 바꾸지 않았다.
- production build 7 tasks 통과. 신규 실제 API/DB E2E 2 tests 통과.
