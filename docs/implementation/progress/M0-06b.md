## 구현 범위

`@workout/ui-spike/workspace`를 Next와 Vite의 `/ui-spike`, Storybook에서 공유한다.
사용자가 검증 도구를 열 때 지도·데이터·상호작용 패널을 각각 lazy load한다.
자료는 합성이며 서버·사용자 건강 자료와 연결하지 않는다. 입력은 컴포넌트 수명의 메모리에만 존재한다.
기존 제품의 Zustand draft / Query server cache 소유권은 바꾸지 않는다.

배포물 내부에 포함된 다른 소스·유료 확장까지 검토하거나 법적 사용 승인을 내린 결과는 아니다.
pnpm 기본 licenses 명령은 로컬 store index 누락으로 실패해 실제 설치 package를 직접 순회했다.

## 빌드와 경계

MapLibre 6의 worker와 shared ESM 파일을 각 shell의 `public/dist/maplibre`에 함께 복사한다.
LICENSE도 복사하며 생성 파일은 Git에 포함하지 않는다. Turbo build output에 해당 경로를 포함한다.
Next 해당 route 및 Vite production preview는 `worker-src 'self'`와 `connect-src 'self'`로 실행한다.
이는 worker/network 호환성 검증이며 전체 앱의 script nonce 등 CSP 강화 완료를 뜻하지 않는다.
[MapLibre 문서](https://maplibre.org/maplibre-gl-js/docs/)와
[v6 migration](https://maplibre.org/maplibre-gl-js/docs/guides/v5-to-v6-migration-guide/)의 ESM·WebGL2 조건을 따른다.

Vite production lazy chunk는 지도 약 1,014 kB / gzip 276 kB, 데이터 패널 약 955 kB / gzip 315 kB다.
500 kB 경고가 남는다. lazy load는 첫 진입 비용을 분리하지만 제품 성능 budget 통과 증거는 아니다.
1,000행은 bounded 기능 검증이며 가상화·저사양 기기 성능을 검증하지 않았다.

## 추가 성능 측정

[측정 결과](../research/ui-spike-performance-result.json)는 기존 Next production build의 합성 UI를
Playwright Chromium 153 headless에서 실행한 결과다. Apple M3 Pro/arm64, 1440×900 및 390×844,
각 3회 독립 context, CDP CPU 4배 감속을 사용했다. 외부 네트워크 요청은 차단했고 시도도 0건이었다.

패널 준비 784–921ms, 1,000행 표시 377–445ms, 내림차순 정렬 623–737ms, 1행 검색 97–126ms를
관측했다. 측정값은 action 직전부터 DOM 정합성 assertion 완료까지이며 driver·스크롤·자동 대기 비용을
포함한다. INP나 순수 React render 시간, 실물 저사양 기기 성능으로 해석하지 않는다. 수치만으로
제품 성능 예산을 통과 처리하지 않는다. 1,000행 전체 DOM/차트 재계산 비용이 있어 제품 adapter에서는
실제 화면의 행 수·페이징/가상화·차트 해상도에 맞춘 측정이 필요하다.

`node --import tsx scripts/probe-ui-performance.mts --execute`로 명시 실행한다. 인자 없는 실행은
안내만 출력한다. localhost 고정 경로를 사용하고 브라우저와 context를 종료하며, 재실행은 기존 기록을
`previousRuns`에 보존한다. 최초 tsx CLI 시도는 sandbox IPC 제한으로 실행되지 않아 Node import 경로와
브라우저 실행 권한으로 검증했다.

TypeScript 검사를 통과했다. 이 변경은 기존 UI 제품 코드를 바꾸지 않으며 전체 task 상태는 진행 중이다.
최종 커밋 본문에 독립 Herdr 리뷰의 base/tree와 결과를 기록한다.

## 음성 대조군 판정 후속 검증 · 2026-09-17

기존 `NEG-SYN-01`의 제한된 단일 진단에서 공급자가 `(0,0)` 요청을 별도로 거절한다는 응답을
확인했다. 원문 메시지는 보관하지 않고 [진단 기록](../research/routing-negative-control-diagnostic.json)에
실제 요청 옵션·해시와 제한된 분류를 남겼다. 기존 ID는 이력으로 유지하고, 429/timeout fixture용
`NEG-SYN-02`와 겹치지 않는 `NEG-SYN-03`을 새로운 해양 대조군으로 추가했다.

probe는 옵션 거절·snap 실패·경로 탐색 실패·전송 실패를 구분하고, 음성 대조군 기대 결과를
별도로 기록한다. `InvalidOptions`, 전송 오류, 비정상 HTTP 상태는 대조군 검증 근거로 인정하지
않는다. 요청 옵션과 좌표 순서에 따른 해시도 기록한다. 원래의 결과 필드와 과거 실행 이력은 보존한다.

15초 timeout, 512 KiB 응답 상한, 재시도 없음 조건을 유지했다.
