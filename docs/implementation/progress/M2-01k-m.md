## 설계 근거

1. **분류기를 만들지 않았다.** 저장소에 활동의 목적·강도를 추정하는 출처가 없다(`estimate|confidence|classif`
   검색: 활동 추정 계약 없음). 출처가 있는 분류는 사용자가 **연결 계획 세션에 적은** `purpose`와
   `intensityLabel`(A·B·C)뿐이다. 그래서 분류·추정 절은
   - 목적 분류·강도 분류: 연결 계획 세션 값이 있으면 **출처(연결 계획 세션, 사용자 작성)·버전(계획 버전 번호·id)·
     불확실성(계획 당시 분류이며 실제 수행 여부는 확인하지 않음)** 을 함께 표시한다. 없으면 "추정 없음 — 이유".
   - 기록 기반 목적·강도 추정: 항상 "추정 없음 — 이 활동의 기록에서 목적이나 강도를 추정하는 검증된 분류 출처가
     없습니다. 추정값을 만들지 않습니다."
   - 렌더러(`ClassificationItem`)는 출처·버전·불확실성 중 하나라도 비면 값을 숨기고 "추정 없음"으로 둔다. 타입도
     `classified`/`none` 판별 합집합이라 출처 없는 값이 들어올 자리가 없다.
2. **기여율 대신 부분 합계.** 계약상 `coverage`는 항상 `'unknown'`이라 분모가 불완전하다. 비율은 계산하지 않고,
   관측·계산 절의 기존 Block 부분 합계(알려진 수·미확인 수)를 그대로 쓴다. 분류·추정 절에 그 이유를 한 줄로 적었다.
3. **관측·계산 절**은 기존 `ActivityContextPanel`이다. 사양 표의 "보고한 RPE"가 빠져 있어 추가했다(없으면
   "없음. 0으로 채우지 않습니다"). 출처 줄(기록 값의 출처·원본 수정, 계산이며 추정이 아님)을 추가했다. 제목은
   `관측·계산`. 다른 명세가 쓰는 region 이름 `계획 연결과 관측 영향`은 유지했다(주소·연결 Block 명세 호환).
4. **상담 절은 읽기만 한다.**
   - 검토 항목: 관측값에서 고정 규칙(`activity-impact-consultation-v1`)으로 고른 문장(거리 범위 미만/초과·차이,
     거리 미확인, 시간 측정 정의 없음, RPE 미보고·목표 RPE와 다름, Block 합계 제외, 과거 계획 버전). 예측·점수·
     인과 수치는 없다.
   - 관련 제안: 기존 코치(S10) 흐름을 재사용한다. ① 현재 계획 버전이면 `/coach?planVersion=&scopeKind=block&
targetId=`로 연결 Block 검토를 여는 링크(코칭 모듈 `search.ts`가 이미 읽는 주소). ② 기존
     `GET /bff/v1/coaching-threads`(최신 100개)에서 같은 계획 버전의 이 Block·세션 상담을 골라 `/coach?thread=`로
     연결. 100개보다 많으면 "최근 N개만 확인"이라고 적는다. 과거 계획 버전이면 검토 링크를 만들지 않는다.
   - 제안 생성·승인은 코치 화면의 기존 흐름 그대로이며, 이 절은 어떤 쓰기 요청도 보내지 않는다(승인 흐름 불변).
   - 모듈 경계: activities 모듈은 coaching 모듈을 import하지 않는다. 계약(`@workout/contracts/coaching-threads`)과
     transport만 쓰고, 코치 주소는 shell이 `coachingHref`로 만든다.
5. **화면 전체 부정 단언.** 퍼센트(`\d%`), 위험·확률·가능성 옆 숫자, 기여율·기여도·비중 옆 숫자, "때문에 … 숫자"
   패턴이 body 전체 텍스트에 없어야 한다. 기존 안내문 "기여율·…·부상 위험…을 계산하지 않습니다"는 숫자가 없어
   걸리지 않는다.

## E2E가 단언하는 것 (`tests/identity/activity-impact-split.spec.ts`, Next·Vite 각각)

실제 OIDC 세션·API·PostgreSQL. 목적 `유산소 기반 유지`, 강도 라벨 B, 목표 RPE 5, 거리 5000m인 계획 세션을 저장하고,
연결한 수동 활동(4200m, RPE 7)과 연결하지 않은 활동, 이 Block을 대상으로 한 코치 상담 1건을 만든다.

- 세 region(`계획 연결과 관측 영향`·`분류·추정`·`상담`)이 각각 h3 `관측·계산`·`분류·추정`·`상담`을 갖는다.
- 세 출처 줄이 각자의 절에만 있다(관측: "출처: 이 활동의 기록 값(출처 수동 기록…", 분류: "출처 표시: 항목마다
  출처·버전·불확실성…", 상담: "출처: 관측·계산 절의 값에서 고정 규칙(activity-impact-consultation-v1)…제안일
  뿐이며 계획을 바꾸지 않습니다."). 분류 절의 항목 출처 `출처: `는 정확히 2개.
- 목적·강도 분류 각각에 출처·버전(`계획 버전 N · id`)·불확실성이 붙는다. 기록 기반 추정은 "추정 없음 — 이유".
- 상담: 검토 항목(800m 짧음, RPE 7 대 목표 5), 코치 검토 링크의 주소, 관련 상담 링크(`/coach?thread=<id>`).
- **부정 단언:** body 전체 텍스트에 위 네 패턴이 없다(연결·미연결 두 화면 모두).
- **쓰기 없음:** 탭을 보는 동안 `/bff/v1/`로 GET 아닌 요청이 0건이고, 계획 head가 테스트가 저장한 버전 그대로다.
- 미연결 활동: 목적·강도 "추정 없음 — 연결한 계획이 없어…" 2건, 항목 출처 0건, 코치 검토 링크 없음.
