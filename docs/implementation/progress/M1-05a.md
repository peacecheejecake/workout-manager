# M1-05a · 기존 원장 근거 의존성 캡처·비교

상태: 완료(기존 원장 의존성 캡처·비교 기반). FUT-02, V2-A45 및 근거 최신성 검사 기반에 해당한다.
M1-05의 근거 저장·후보·명시 승인·원자적 쓰기를 완료한 것으로 간주하지 않는다.

## 독립 착수 범위

기존 M1-01 동의, M1-02 계획, M1-03 활동, M1-04a 체크인, M1-04ai 사용자 완료 원장이 입력이다.
S05 “계획 종류”나 계획 내용을 해석하지 않고 저장된 원장의 변경 여부를 캡처하므로 이 기반만 분리했다.
부모 M1-05의 M1-04 의존성과 나머지 통합·출시 gate는 유지한다.

`core-ledgers-v1` manifest는 사용자, 캡처 시각, training plan head의 존재/부재, 전체 canonical
활동 수·revision 합계, 체크인·완료 보고 collection head의 존재/부재 및 revision, 실제 읽은
AI 동의의 존재/부재·revision·granted를 보존한다. 활동에는 삭제 tombstone도 포함한다.
빈 활동 집합은 관측된 count/sum `"0"`이며, head 부재를 가상의 revision 0으로 채우지 않는다.
정수 문자열은 길이·형식·합계 정합성을 검사해 JavaScript number의 정밀도 손실을 피한다.

모든 원장 값을 tenant/RLS 경계 안의 단일 SQL statement snapshot에서 읽는다. 클라이언트가 revision을
제공하는 endpoint나 새 쓰기·영속 테이블은 추가하지 않는다. 실제 근거 내용·snapshot 저장은 후속 통합에 남는다.
근거 내용과 manifest를 따로 조회해 서로 다른 시점의 자료를 결합하지 않도록, 후속 생성 경로는
본문과 의존성을 같은 일관된 읽기 snapshot에서 얻어야 한다.

순수 비교는 `fresh`/`stale`와 결정론적인 변경 필드, 또는 `unsupported`를 반환한다. 알려지지 않은
schema/scope/추가 필드·잘못된 값은 조용히 무시하지 않는다. 서로 다른 사용자는 비교하지 않는다.
`capturedAt`은 revision 동등성 비교에서 제외하며 나이/만료 정책을 구현한 결과가 아니다.

## 통합 시 유지할 조건

이 캡처는 전체 tenant 원장 기준으로 보수적으로 변경을 감지한다. 활동 상세·provider head,
영양·보강·루틴·회복 head, 정책·선호·제약·대화·자료 및 실제 계산 정의 의존성을 완성하지 않았다.
지원하지 않는 의존성을 이 manifest에 넣어도 무시하지 않고 거절한다. `fresh`는 이 제한된 원장
stamp가 같다는 뜻이며 승인 권한·완전한 coaching expectedBasis 또는 생리학적 타당성이 아니다.

EvidenceSnapshot → Decision → Proposal → PlanVersion 통합에서는 실제로 읽은 모든 근거를 포함하고,
쓰기 직전 같은 승인 transaction 안에서 최신성·권한·동의·정책을 재검사해야 한다. 조회 후 저장 사이의
경쟁을 이 읽기 도구만으로 막았다고 주장하지 않는다. idempotency·원자적 history/outbox도 부모 작업에 남는다.

## 검증

- 계약 테스트 22개: 부재/존재, 잘못된 정수·revision·합계, 비정규 UUID, 알 수 없는 schema/scope/필드,
  사용자 불일치, 시각만 바뀐 경우, 모든 원장 변경 및 고정 순서의 비교 결과를 확인했다.
- 실제 PostgreSQL에서 plan head 생성·새 버전, 활동 import·오래된 provider revision 무시·정정·삭제
  tombstone·기존 receipt 재실행, 체크인 CRUD, 완료 확인·철회, AI 동의 grant/revoke,
  다른 tenant와 계정 삭제 후 캡처 거절을 확인했다.
- 캡처의 첫 실제 SELECT가 반환된 뒤 다른 실제 DB transaction이 AI 동의와 체크인 head를 함께
  커밋하도록 조율했다. 첫 캡처는 전부 이전 값, 다음 캡처는 전부 새 값이며 캡처당 SELECT는 1회다.
  임의 sleep이나 mock DB 성공을 단일 snapshot 증거로 사용하지 않았다.
- 최초 DB 시험은 모든 자기보고 값을 null로 만든 잘못된 체크인 fixture가 거절되어 실패했다.
  fatigue 0→1 정정으로 수정한 최종 통합 검사는 159개/20 files 모두 통과했다. 임시 DB는 종료·정리됐다.
- `pnpm check --maxWorkers=2`의 생성물·Prettier·ESLint·전체 consumer typecheck·unit/component
  1,485개/134 files를 통과했다. 최종 fixture 수정의 scoped lint/typecheck도 확인했다.
  새 브라우저 동작이나 HTTP endpoint는 없으며 UI·브라우저 실행을 새 증거로 주장하지 않는다.

그래프의 M1-05a만 완료했다. M1-04와 부모 M1-05, 통합·출시 gate는 완료 처리하지 않았다.
독립 Herdr 리뷰의 base/tree와 결과는 커밋 본문에 기록한다.
