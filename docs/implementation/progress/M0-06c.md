# M0-06c · Native feasibility

확인일: 2026-09-16. 상태: **진행 중**. 임시 Simulator 실행 증거를 추가했으며 실기기 gate는 미확인이다.
사용자 지시(2026-09-16): 지금은 Simulator 검증만 진행한다. 실기기 작업은 보류하며 Simulator 결과로 대체하지 않는다.
FUT-05, V2-A04–A06/A26–A30/A47–A50과 관련된 사전 검증으로, 이 수용 항목 전체를 통과 처리하지 않는다.

## 로컬 준비 상태

Xcode 26.2 / iOS SDK·Simulator runtime 26.2가 설치돼 있다. 유효한 code-signing identity가 있다는
것만 확인했으며 개인 이름·식별자·profile은 기록하지 않았다. 프로젝트 HealthKit 서명이 가능한지는
미확인이다. 조회 당시 연결 가능한 physical iOS 기기는 0개였다. Apple 계정 로그인이나 provisioning,
개인 건강 자료 조회·전송은 하지 않았다.

## 실행한 제한된 실험

`scripts/fixtures/native-spike`의 standalone Swift 앱을 `scripts/probe-native.mjs`로 빌드한다.
UIKit·HealthKit·WebKit을 링크하고 Simulator용 ad-hoc 서명을 사용한다. 개인 signing identity를
선택하지 않는다. 새 private device set에 임시 iPhone Simulator를 생성해 설치·실행하고 정리한다.
기존 Simulator나 사용자 앱을 변경하지 않는다.

```bash
node scripts/probe-native.mjs           # 설명만 출력
node scripts/probe-native.mjs --execute # Xcode/macOS의 격리된 Simulator probe
```

`HKHealthStore.isHealthDataAvailable()` 반환값만 확인한다. 이 값은 해당 환경의 API 지원 여부이며
읽기 권한·sample 존재·background 수집 성공을 뜻하지 않는다. 권한 요청과 sample query는 하지 않는다.
probe에는 건강 데이터를 다루는 entitlement·사용 목적 승인 흐름이 없다.

WKWebView는 비영속 store와 자체 로컬 scheme의 합성 HTML만 사용한다. frame과 origin, 메시지
형태·version을 검증한 뒤 boolean 지원 상태만 반환하고 JavaScript acknowledgement를 받는다.
잘못된 메시지, 다른 frame·origin, 외부 navigation 거절을 실제 WebKit 실행에서 관측한다.
네트워크 tile/API나 실제 건강 기록·인증 자격을 bridge에 싣지 않는다.

실행 결과는 [native-simulator-result.json](../research/native-simulator-result.json)에 기록한다.
deployment target 15.0으로 컴파일했지만 실제 실행 runtime은 26.2다. iOS 15 실행 검증이 아니다.
최종 Simulator 실행에서 7개 관측을 통과했다. 정상 메시지·제한된 상태 왕복, 잘못된 version·boolean
version 거절, 다른 iframe·main-frame origin 거절, 외부 navigation 취소를 각각 확인했다.
Swift 소스 SHA256을 보고서와 대조했고 실제 컴파일·plist 검사·스크립트 구문/ESLint/포맷 검사를 통과했다.
소유한 Simulator와 임시 파일 정리를 확인했다. 실패한 정리 단계를 성공으로 기록하지 않도록 했다.

## 공용 Vite 화면의 Capacitor Simulator 실행

Capacitor core/cli/ios **8.5.2**를 root 개발 의존성으로 정확히 고정했다. 임시 project에서 설치된
CLI로 iOS SPM project를 생성·sync하고, 공식 `capacitor-swift-pm`의 exact 8.5.2를 확인한다.
개인 signing을 끈 Xcode build와 별도 private device set을 사용한다. 제품 native host를 추가한 것은 아니다.

```bash
pnpm --filter @workout/mobile-web build
node scripts/probe-capacitor.mjs           # 설명만 출력
node scripts/probe-capacitor.mjs --execute # 공식 SPM 의존성 다운로드가 필요할 수 있음
```

기존 `apps/mobile-web/dist`를 복사한 앱을 iOS Simulator 26.2에서 실제 설치·실행했다.
임시 SceneDelegate 계측으로 로컬 `capacitor://localhost` main frame의 제목, 개발 fixture 고지,
문서 내 버튼 5개, `Capacitor.getPlatform() === 'ios'`, native platform 상태를 관측했다.
버튼 개수는 문서 전체이며 버튼 동작·로그인·건강 자료 연동 성공을 뜻하지 않는다.
계측 소스·web index·screenshot hash와 정리 결과는
[capacitor-simulator-result.json](../research/capacitor-simulator-result.json)에 기록했다.
소유한 Simulator·임시 project는 정리했고 screenshot만 로컬 임시 증거로 남겼다.

Screenshot을 직접 확인한 결과 공용 활동 화면은 표시되지만 **상단 제목이 status bar/Dynamic Island와
겹친다**. 따라서 render/bridge 호환성은 통과이고 safe-area 배치는 미해결이다. 단순 DOM 관측을
native UI 전체 수용 통과로 취급하지 않는다. 이 앱은 제품 API와 연결되지 않은 기존 개발 fixture다.

추가 의존성 설치 후 frozen/offline lockfile 확인 및 전체 workspace build 7개를 통과했다.
실기기·HealthKit 권한 요청·sample query·provisioning은 실행하지 않았다.

## 남은 완료 조건

- 임시 spike에서 확인한 Capacitor/Vite 조합의 제품 native host 통합과 safe-area 배치 수정·검증.
- 프로젝트 team·HealthKit entitlement·유형별 설명을 가진 서명된 실기기 실행.
- 허용된 테스트 자료로 권한·빈 결과·추가/삭제, durable outbox/anchor/ack·재설치·중단·재전송 검증.
- 실제 background delivery, safe area·IME·back·foreground 수명주기 및 계정 전환 검증.

현재 연결된 실기기와 프로젝트 서명 증거가 없으므로 M0-06c 완료나 M3 준비 완료로 표시하지 않는다.
규칙·기존 수용 조건은 변경하지 않았다. Simulator 결과로 HealthKit 실기기 동작을 대신하지 않는다.
