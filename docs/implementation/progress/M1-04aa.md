# M1-04aa · 활동 일괄 계획 연결·해제

상태: 구현·검증 완료. S07 / V2-F12의 명시적인 대량 계획 연결을 기존 overlay API에 연결했다.

## 범위

- M1-04z 다중 선택을 공유하며 최대 100개와 사용자·세션 수명, 작업 간 선택 잠금을 유지한다.
- 현재 저장된 계획에서 정확한 immutable version/session을 고르거나 연결 해제를 명시한다.
  날짜로 추정하지 않고 계획 head 변경 시 확인한 연결을 최신 버전으로 바꾸지 않는다.
- 미리보기 전에 현재 활동을 조회하여 선택 당시 revision과 대조한다. 충돌·조회 실패·부재와
  이미 같은 연결을 구분하며 자동으로 revision을 올려 재시도하지 않는다.
- 전체 report 교체 API에서 기존 RPE·메모를 보존하고 planLink만 변경한다. RPE 미확인을
  0으로 채우지 않고 같은 RPE의 보고 시각을 보존한다. 거리·시간·원본은 변경하지 않는다.
- 항목별 idempotency key와 요청을 고정한 뒤 명시 확인으로 순차 적용한다. 부분 성공과
  충돌·인증·응답 불확실을 표시하며 재시도는 같은 요청을 사용한다. receipt를 최신 값으로
  캐시에 넣지 않고 활동·관측 영향·Block 필터를 재조회한다.

## 검증

- 실행기 14 tests, 확인 UI 8 tests, 기존/신규 목록·삭제 연결 50 tests 통과. 실제 transport의
  인증 만료·세션 비활성화 중단, 준비 취소·늦은 응답, 고정 요청 재시도, 계획 head 재조회 후
  선택 보존, 계획 조회 실패 중 연결 해제, 삭제와 양방향 잠금을 확인했다.
- generated/Prettier/ESLint/typecheck 통과, production build 7 tasks 통과.
  기본 worker 설정의 전체 검사 두 번은 기존 20,000개 원본 workbench 테스트에서 5초 제한을
  넘었다. 규칙·timeout·assertion을 바꾸지 않고 `pnpm test --maxWorkers=2`로 전체 71 files /
  865 tests를 통과했다. 기본 병렬 실행의 시간 초과는 해소된 것으로 주장하지 않는다.
- 실제 API/격리 DB 신규 E2E 1 test 통과. 미리보기 뒤 계획 head 변경과 동시 활동 정정,
  서버 저장 후 응답 유실을 재현했다. 고정 옛 버전 연결, 409와 부분 성공, 같은 key/body 재시도,
  null/0·메모·RPE 보고 시각·원본·거리/시간 보존과 일괄 해제를 확인했다. 이미 해제된 항목은
  쓰지 않고 타 계정 계획 연결은 거절한다. 14개 viewport 입력/포커스·reflow도 확인했다.
- 첫 E2E의 Block 집계 기대값을 수정했다. Block 기간 내 관측 3개와 명시 연결 필터 2개를
  구분해야 하며, 기존 기간 집계 정책은 변경하지 않았다.
- 전체 실제 OIDC/API/격리 DB E2E 57 tests 통과.
- Aside에서 합성 계획의 4단계 기간·세션 생성과 명시 저장, 활동 JSON 2개 업로드·저장,
  일괄 연결 미리보기·적용·재선택·연결 해제와 결과 닫기 포커스 복귀를 확인했다.
  `batch-link-preview.png`, `batch-unlink-result.png`를 직접 열어 확인했다. Aside의 role
  locator 한 번이 찾기 오류를 반환했으며 새 snapshot의 ref로 입력·후속 화면을 확인했다.
  테스트 탭과 이번 검증용 서버·격리 DB를 종료했다. 실제 OS IME 검증을 주장하지 않는다.
- DAG 66개·완료 의존성·증거 경로와 diff 검사 통과. 커밋 전 Herdr 독립 리뷰의
  base/tree·완료 판정과 추가 수정은 task 커밋 본문에 기록한다.

규칙 및 지도·실기기·공식 Garmin 출시 gate는 변경하지 않는다.
