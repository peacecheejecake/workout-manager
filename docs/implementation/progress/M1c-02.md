# M1c-02 · 스트레칭 수동 core

상태: **운영 런타임 권한 검토 대기**. S34의 스트레칭을 기존 보강 운동 catalog와
canonical Activity에 연결했다. 새 `stretching` family와 버전별 StretchProfile을
같은 동작 원장에 저장하며, 기존 mobility 동작을 자동 재분류하지 않는다. 정적
유지시간과 동적 반복, 좌우/전체 기준, 선택적 휴식, 불편감·중단·미확인을 별도
필드로 저장한다. 계획 세트가 있으면 기존 보강 세션의 고정 버전을 검증해
참조하고, 계획 없는 단독 Activity에도 실제를 연결할 수 있다.

실제 기록은 사용자 확인 명령으로만 확정하고 revision·멱등 키로 정정/삭제한다.
타이머나 provider 요약으로 좌우 값·유지시간을 만들지 않는다. Activity 안의
구간은 확인된 시각만 배정하며 단계 시간은 Activity 총시간에 다시 합산하지
않는다. S34 웹·mobile-web 화면과 일반 Activity 상세에 같은 실제 원장을
표시한다. 운동 동작의 전문 자료·코칭, 자동 자세/ROM 측정과 효능 검증은 M2 및
FUT-08/14의 후속 범위다.

024 migration은 새 테이블에 FORCE RLS, 버전/개정 불변성, 계정 말소 연동을
제공한다. 기존 `erase_account(text)`를 감싼 새 함수의 EXECUTE 권한은
migration 뒤 `grantOperations` 재실행이 필요하다. 운영용 런타임 GRANT는
앞선 동일 종류 변경의 자동 승인 거절을 준수해 적용하지 않았다. 필요한 최소 권한은
런타임 역할에 `stretch_profile`의 SELECT·INSERT,
`stretching_log`의 SELECT·INSERT·UPDATE,
`stretching_log_revision`의 SELECT·INSERT다. DELETE 권한은 요청하지 않는다.
임시 E2E fixture의 GRANT는 테스트 뒤 폐기되는 격리 DB 역할에만 적용했다.

검증: 루틴 작업과 함께 전체 `pnpm check`의 포맷·lint·23개 패키지 타입 검사,
188개 파일/1,953개 단위 테스트, 격리 PostgreSQL 32개 파일/272개 테스트,
전체 production build가 통과했다. 실제 OIDC·임시 PostgreSQL·Chromium E2E는
좌우 정적 유지 로그를 하나의 Activity에 저장하고 총시간 불변, 웹에서
mobile-web 320px로 이동한 표시/가로 넘침 여부를 확인했다. Aside CLI 업데이트
확인은 `fetch failed`였고 Chrome용 Orca 데스크톱 런타임은 실행 시간 초과로
접근할 수 없어 Playwright Chromium으로 검증했다. 실기기·실제 Garmin·콘텐츠
임상/효능 검증은 수행하지 않았다.

Herdr split-pane 독립 리뷰는 기준 HEAD
`25cd76f29cbe9637594b177c4b31bc664103c572`와 최초 staged diff SHA-256
`d9522fd958dc4829be9d9fc9fdb85f6256a02312bcfbb365122369063e75cd60`에서
삭제 후 이전 receipt 재생, Activity 구간의 durationKind 해석, 정정 시
초·밀리초 손실 P2 세 건을 발견했다. 삭제된 로그에 대한 과거 create/correct
재시도를 충돌로 처리하고, 명시적 elapsed 구간 또는 검증된 Activity Details V3
parent 구간만 경계 확인에 사용하며, 편집하지 않은 시각은 원래 ISO instant를
보존하도록 수정했다. PostgreSQL·UI 모델·OIDC/Chromium 회귀를 추가하고 전체
검사와 빌드를 다시 실행했다. 진행 기록과 task graph를 제외한 staged code diff SHA-256은
`3a06c1a2e19b7d76c4b6ffb20f48e0a65ada86c1c6cc63f8dcfc769e2d8c8a78`이다.
독립 재검토에서 P2 세 건이 해결됐고 코드의 추가 actionable finding은 없었다.
리뷰어가 지적한 해시 설명의 제외 대상도 정확히 고쳤다. 리뷰어는 테스트를
재실행하거나 파일·index를 변경하지 않았다.
