# M1-05j3b · 부분 요청 새 후보·최신성 표시

상태: **completed**. M1-05j3a의 검증된 후보에서 사용자가 diff 항목 일부를 선택하면
서버가 현재 근거·계획·완료 보고를 잠금 아래 다시 확인하고 부분 초안을 재투영·검증한다.
새 Proposal/Candidate는 원본과 같은 Decision에 속하고 `parentCandidateId`를 본문,
digest, 외래 키에 결합한다. 기존 후보와 현재 계획은 변경하지 않는다. 선택에 없는
diff ID, 선택 없는 요청, 현재 계획과 맞지 않는 후보는 거절한다. 요청 receipt에는
선택 내용 대신 해시와 새 후보 ID만 남긴다. 실행별 후보는 원본을 포함해 100개로
제한해 유효한 목록이 상한을 넘어서 갑자기 비지 않도록 한다. 한도에서 성공 키
재시도는 기존 후보를 반환한다.

소유자 전용 상태 API는 `current`/`stale`/`withdrawn`과 ID만 반환한다. 같은 날
계획이 변경돼도 상세·목록·멱등 재전송·부분 요청에서 오래된 본문을 숨긴다. 동의
철회나 근거 회수 후에는 메타데이터만 남는다. 계획 반영은 M1-05k의 명시 승인
transaction이다.
