# M2-04c · URL 수집과 parser lifecycle

상태: **완료**. M2-04b의 private object storage와 durable cleanup 위에 URL ingestion 원장,
SSRF 방어, bounded parser, immutable provenance·locator, raw/parsed 파생물 삭제를 연결한다.
색인·검색·인용, 공유·reviewed 전환, `includeForCoach` 활성화는 M2-04d/M2-05 범위이며 이 작업의
fetch 또는 parse 성공으로 자동 활성화하지 않는다.

## 고정한 경계

- URL 자료는 text/file과 구분되는 `sourceKind=url`이다. 입력은 HTTPS absolute URL만 허용하고
  userinfo와 fragment를 거절한다. 문법 검증은 네트워크 접근 승인으로 간주하지 않는다.
- 운영 fetch는 명시된 exact-host allowlist를 통과해야 한다. 각 redirect hop에서 DNS의 모든 주소와
  실제 socket remote address를 다시 검사하며 private, loopback, link-local, CGNAT, multicast,
  reserved/documentation 및 IPv4-mapped private 주소를 fail closed로 차단한다.
- API transaction은 ingestion 예약과 outbox만 기록한다. DNS, 원격 fetch, object I/O와 parser는 전용
  worker가 DB transaction 밖에서 수행하며 DB-clock lease token으로 stale 결과를 차단한다.
- 원격 응답과 parser 입력·출력은 시간, redirect, header, compressed/decoded byte, token/depth,
  fragment 수·길이를 제한한다. HTML의 script/style/form 등 실행성 내용은 실행하거나 렌더하지 않는다.
- 성공한 raw capture와 parsed snapshot은 immutable version·parser identity·hash·locator에 고정한다.
  실패, bookmark-only, pending, cancelled와 parsed를 구분하며 데이터 공백을 성공이나 0으로 바꾸지 않는다.
- public DTO와 로그에는 storage ref, DNS 주소, headers/cookies, lease token, parser exception을 포함하지
  않는다. 사용자에게 보여 주는 URL은 query를 제거한 display URL을 사용한다.
- soft delete와 계정 말소는 실행 중 ingestion을 취소하고 알려진 temporary/raw/parsed object를 기존
  durable cleanup manifest에 원자적으로 넣는다. 늦게 도착한 worker 결과는 resource version에 연결하지
  않는다.

## 구현·검증 기록

계약과 계정 export v14, 순수 URL policy/fetch/parser, PostgreSQL ingestion 원장과 migration 029,
API, one-shot worker, object lifecycle, 자료실 UI를 구현했다. 예약 transaction은 outbox를 함께 쓰고,
worker는 raw capture를 먼저 불변 object로 publish한 뒤 별도 claim에서 파싱한다. retryable failure는
DB 시각과 lease로 재개하며 5회 뒤 닫힌다. parsing failure는 raw bookmark를 보존하고, 성공한 parsed
snapshot은 parser identity·digest·UTF-16 locator와 함께 고정한다. URL raw/parsed object는 resource
quota에 포함한다.
