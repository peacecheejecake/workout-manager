# M3-02h · 서명된 iPhone HealthKit 전체 경로 검증

상태: **not_executed**. 2026-09-28 연결·빌드 사전 확인만 수행했다. 합성 표본 수집, 삭제, background wake, offline ACK 재시도, 재설치, 계정 전환, 공통 화면 검증을 완료한 것으로 판정하지 않는다.

## 2026-09-28 사전 확인

- `devicectl`에서 iPhone 15 Pro Max(`iPhone16,2`) 물리 기기 1대가 `connected`였다. 제품 bundle `org.workoutmanager.app`은 설치돼 있지 않았다.
- Node 24.12.0에서 phase 작업 트리의 잠금 파일 고정 설치를 완료하고 `pnpm build` 15/15를 통과했다. `cap copy ios` 뒤 `mobile-web/dist/index.html`과 iOS `public/index.html`의 SHA-256이 일치했다.
- 첫 모바일 빌드는 오래된 작업 트리 의존성 링크 때문에 실패했다. 오프라인 설치는 캐시에 `fastify` tarball이 없어 실패했고, 잠금 파일 고정 설치를 다시 실행해 완료했다. 모바일 빌드 재시도는 오래된 contracts `dist` export 때문에 실패했으며, 전체 `pnpm build`가 의존 패키지를 먼저 빌드한 뒤 15/15로 통과했다. 앞선 실패를 통과로 소급하지 않는다.
- Apple Development 인증서 1개가 있었지만, 제품 iPhone Debug 서명 빌드는 앱 ID의 개발 프로비저닝 프로필이 없어 실패했다. `-allowProvisioningUpdates`로 다시 실행한 결과 Xcode가 `No Accounts`와 동일한 프로필 부재를 보고했다. 따라서 제품 앱 서명·설치·실행은 **not_executed**다.
- 제품 `Info.plist`의 `WMNativeAPIOrigin`과 `WMNativeIdPOrigin`은 비어 있다. `NativeAuthConfiguration`은 정확한 HTTPS origin을 요구하므로, 현재 localhost OIDC 스택만으로 제품 앱 로그인·서버 동의·업로드를 실행할 수 없다.
- `HealthKitWorkoutCollector`의 observer/anchored 운동 조회는 표식으로 제한되지 않는다(`predicate: nil`). 기존 개인 운동이 있는 기기에서 읽기 권한을 주면 사용자가 허용한 표식 있는 합성 표본 범위를 넘을 수 있다. 기기의 격리 여부를 확인하기 전에는 제품 앱 HealthKit 읽기 권한을 요청하지 않았다.

실행 로그는 Git 제외 임시 경로에만 두었다. 기기 원본 운동 자료·토큰·개인 위치 데이터는 읽거나 저장하지 않았다. 실제 서명과 안전한 표본 범위, HTTPS 시험 서버가 준비되면 이 노드의 실기기 수용 경로를 별도로 실행한다.
