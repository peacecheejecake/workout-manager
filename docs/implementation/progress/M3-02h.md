# M3-02h · 서명된 iPhone HealthKit 전체 경로 검증

상태: **in_progress**. 서명된 iPhone 빌드·설치·기본 실행의 사전 확인과 Debug 합성 표본 경로 구현을 진행했다. 제품 로그인과 HealthKit 실기기 수용 행은 **not_executed**다. 합성 표본 수집, 삭제, background wake, offline ACK 재시도, 재설치, 계정 전환, 공통 화면 검증을 완료한 것으로 판정하지 않는다.

- 초기 모바일 빌드는 오래된 작업 트리 의존성 링크 때문에 실패했다. 오프라인 설치는 캐시에 `fastify` tarball이 없어 실패했고, 잠금 파일 고정 설치를 다시 실행해 완료했다. 모바일 빌드 재시도는 오래된 contracts `dist` export 때문에 실패했으며, 전체 `pnpm build`가 의존 패키지를 먼저 빌드한 뒤 15/15로 통과했다. 앞선 실패를 통과로 소급하지 않는다.

실행 로그는 Git 제외 임시 경로에만 두었다. 기기 원본 운동 자료·토큰·개인 위치 데이터는 읽거나 저장하지 않았다. 안전한 표본 범위와 HTTPS 시험 서버가 준비되면 이 노드의 실기기 수용 경로를 별도로 실행한다.

독립 phase 검토는 `main` `fa3eb54` → `phase/m3-02` `410b574` 전체 문서 diff에 **APPROVE**를 주었다. JSON·링크·diff 정합성을 확인했고, 기기 상태나 임시 실행 로그를 직접 재검증하지는 않았다. 이 검토 결과를 기록하는 커밋은 다시 검토받는다.

## 기존 운동이 있는 기기의 안전한 후속 검증 범위

읽기 전용 코드 감사에서 observer와 anchored 조회 모두 `predicate: nil`임을 재확인했다. 자동 시작과 foreground 재개도 이 경로에 도달할 수 있다. 따라서 현재 제품 빌드에 운동 읽기 권한을 부여하거나 표본 수집을 시작하지 않는다.

초기 설계안은 실행마다 다른 표식과 앱 자체 source를 **AND**로 결합해 observer와 anchored query에 적용하는 것이었다. 코드 안전성 감사에서 이 조건은 삭제 이벤트를 누락할 수 있다고 확인했다. [Apple의 `HKDeletedObject.metadata` 설명](https://developer.apple.com/documentation/healthkit/hkdeletedobject/metadata)에 따르면 삭제 객체에는 원본의 사용자 정의 표식이 남지 않고 sync identifier/version만 복사된다. [UUID 조회 조건](https://developer.apple.com/documentation/healthkit/hkquery/predicateforobjects%28with%3A%29)은 저장된 단일 표본 UUID로 범위를 좁힌다. 따라서 현재 Debug 구현은 **계정별로 저장한 단일 UUID 조건**을 observer와 anchored query에 동일하게 사용하고, 반환된 살아 있는 표본은 UUID·앱 자체 source·실행 표식을 다시 검증한다. 삭제 이벤트는 저장한 UUID와 일치할 때만 받아들인다. 실제 삭제 API 조건은 앱 자체 source **AND** 표식 **AND** 저장된 UUID다. UUID 조건에서 실제 기기 삭제 이벤트가 반환되는지는 **not_executed**이며, 이벤트 부재를 삭제 성공으로 바꾸지 않는다.

Debug 경로는 서버가 확인한 현재 계정에서만 작동한다. 합성 운동 생성은 쓰기 권한만 요청하며 읽기·observer 조회를 시작하지 않는다. 별도의 화면 확인 뒤 운동 읽기 권한을 요청할 수 있지만, OS 권한은 운동 유형 전체에 적용된다는 사실을 먼저 보여 준다. 읽기 요청이나 앱 재실행이 권한 허용의 증거는 아니다. Debug 구현은 제품 collector의 자동 전체 조회를 막고, 계정별 보호 파일에 표식·UUID·anchor·진행 상태만 보존한다. 제품 outbox/API 업로드와 HealthKit background delivery 등록은 이 진단 경로에서 실행하지 않는다. 저장·삭제 결과가 불확실하면 UUID를 보존하고 새 표본 생성을 막는다. 합성 표본 쓰기·읽기·삭제, 삭제 이벤트, 범위 밖 표본 분리, cold/foreground 재개, 계정 전환의 실기기 결과는 모두 **not_executed**다. 개인 운동은 수용 자료로 사용하지 않는다.

표식 범위의 제품 경로가 통과하더라도 외부 앱 변경에 따른 background wake와 일반 제품 수집 전체를 자동으로 입증하지는 않는다. HTTPS 시험 서버와 정확한 native API/IdP origin, 실기기에서 각 수용 동작의 별도 증거가 필요하다.

## 2026-09-30 · Debug 삭제 이벤트 재조회 보완

- 독립 phase 검토에서 읽기 권한이 거부된 동안 삭제 API가 성공하면 빈 anchored 조회가 cursor를 전진시킬 수 있고, 삭제 확정 상태의 명시적 읽기 재시도가 그 cursor를 초기화하지 않아 뒤늦게 권한을 허용해도 삭제 이벤트를 놓칠 수 있다는 P2를 확인했다. 현재 내용은 명시적 읽기 요청 때 삭제 확정 여부와 무관하게 같은 저장된 UUID의 anchor를 nil에서 다시 시작한다. 빈 조회는 권한이나 삭제 이벤트 부재의 증거로 간주하지 않고 cursor를 전진시키지 않는다. 실제 UUID/source/표식/계정 조건과 삭제 API 조건은 유지한다.
- 합성 상태 전이 Swift harness에서 읽기 거부 → 단일 UUID 삭제 성공 → 빈 삭제 조회 → 명시적 재허용 → 삭제 이벤트 관측, 이전 upsert cursor가 있는 경우의 거부·재시도, 빈 페이지가 성공 증거가 되지 않는 경우를 확인했다. macOS에서 harness 실행 통과, iOS Simulator SDK 타입 검사 통과, 서명 없는 Simulator 전체 앱 빌드 통과. 기존 `HKWorkout` 생성자의 deprecated 경고는 남아 있다. 첫 빌드는 sandbox의 CoreSimulatorService·Swift 캐시 접근 제한으로 실패했고, 접근 가능한 환경에서 동일한 서명 없는 빌드가 통과했다.
- 이 평가는 구현자의 코드·하네스 검증이며 실제 HealthKit 권한 거부/재허용과 삭제 tombstone 전달 증거는 아니다. 이 시점에는 서명된 새 iPhone 빌드·설치·제품 로그인·실제 HealthKit 읽기/쓰기/삭제 및 전체 M3-02h 수용이 **not_executed**였다. 이후 새 빌드 결과는 아래에 별도로 기록한다. P2의 독립 FIXED 판정은 [단계 검토 기록](M3-02-phase-review.md)의 여섯 번째 검토에서 확인됐다.

## 2026-09-30 · 기존 개인 운동이 있는 iPhone의 읽기 범위 재감사

- 제품 `HealthKitWorkoutCollector`의 observer와 anchored query에는 여전히 `predicate: nil`이 있다. 일반 제품 수집은 운동 유형 전체를 대상으로 하므로 이 기기의 개인 기록을 읽을 수 있다. 이 기기에서 Release 제품 수집으로 M3-02h를 검증하지 않는다.
- Debug 빌드에는 `SWIFT_ACTIVE_COMPILATION_CONDITIONS = DEBUG`가 설정된다. 이 빌드에서 제품 collector의 launch·foreground 수집 예약, 제품 읽기 권한 요청, observer 등록이 각각 컴파일 조건으로 차단된다. `SceneDelegate`의 별도 Debug 확인 화면은 읽기 권한이 운동 유형 전체에 적용됨을 알린 뒤 명시적 선택을 요구한다.
- Debug probe의 observer와 anchored query는 계정별로 보존한 단일 합성 표본 UUID 조건을 사용한다. 살아 있는 표본은 UUID·이 앱의 source·실행 표식을 재검증하고, 삭제 이벤트는 보존한 UUID가 일치할 때만 수용한다. 삭제 API에도 source·표식·UUID의 결합 조건을 사용한다. 계정이 바뀌거나 표본 UUID가 없으면 조회를 시작하지 않으며, 이 진단 경로는 제품 업로드를 실행하지 않는다.
- 로컬 `swiftc -D DEBUG` 빌드와 `HealthKitWorkoutDebugProbeHarness` 실행이 통과했다. 초기 시도는 Swift 모듈 캐시 쓰기 권한으로 실패했고, 임시 경로에 캐시를 둔 재시도가 통과했다. 기존 `HKWorkout` 생성자 deprecation 경고는 남아 있다. 이 확인은 순수 범위·상태 전이만 검증한다. 새로운 서명 빌드·기기 설치·권한 요청·HealthKit 표본 수집 및 M3-02h 실기기 수용은 **not_executed**다.
