## 1. 범위

M2-01 phase review(Codex, round 2 APPROVE)가 남긴 비차단 finding 둘.

1. **M14는 등가 변이가 아니다.** `M2-01as.md` §13.3이 "claim이 자기 advisory lock을 잡지 않음"(054의
   `claim_course_share_budget`)을 등가로 판정했지만, 겹치는 **서로 다른 새 구역 둘**의 첫 claim이 동시에 오면 잠금 없이는

2. **확인 화면의 구역별 제거 정점 수가 원래 좌표로 세어졌다.** 반올림(소수 5자리)만으로 원 안에 들어간 끝은 제대로 잘리지만
   화면은 그 구역에서 "정점 0개 제거"라고 말할 수 있었다.

## 2. 설계 근거

### 2.1 M14 (시험과 문서만)

claim은 (1) 잘린 각 구역의 행을 `INSERT … ON CONFLICT DO NOTHING`으로 만들고, (2) 장소(겹치는 모든 행)를 고르고, (3) 그 행들을
`FOR UPDATE`로 잠근 뒤 최대를 읽어 모두 최대 + 1로 올린다. 두 claim이 **이미 커밋된 행을 공유하면** 행 잠금이 직렬화한다.
하지만 E·F가 둘 다 새 구역이면:

- 세션 1: E 행 삽입(미커밋), 장소 = {E}(F 행은 아직 없음), 최대 0 → E = 1.
- 세션 2: F 행 삽입(미커밋, E와 키가 달라 기다리지 않음), 장소 = {F}(E 행은 보이지 않음), 최대 0 → F = 1.

두 링크가 나갔는데 장소의 수는 1이다. 뒤따르는 claim은 E·F를 모두 보고 최대 1에서 시작하므로 9개가 더 허용되어 **한 장소에
11링크**가 된다. claim 안의 `pg_advisory_xact_lock(hashtextextended(tenant,0))`이 세션 2를 세션 1의 커밋까지 세워 두므로
세션 2는 E = 1을 보고 둘 다 2로 올린다. 제품 경로(`createShare`)는 같은 잠금을 이미 쥐고 있어 실제로는 일어나지 않지만, claim
함수의 계약으로는 이 잠금이 필요하다 — 심층 방어가 아니라 이 경우의 유일한 방어다.

production 잠금은 이미 있으므로 **마이그레이션은 바꾸지 않는다**. 시험과 문서만 고쳤다.

### 2.2 제거 정점 수 (코드)

`disclosureChoices`는 선을 `settleRounding`으로 공개 정밀도(소수 5자리)에 맞춘 뒤 그 좌표로 분류·절단한다(phase review
finding 1). `removedVerticesPerCircle`도 이제 **같은 settle 결과**로 센다(`packages/server/courses/src/disclosure.ts`).
`settleRounding`이 수렴하지 않으면(실제로는 일어나지 않음) `disclosureChoices`는 그 선을 막으므로(blocked), 셈은 한 번 반올림한
좌표로 대신하고 500을 내지 않는다. 경로(`apps/api/src/course-disclosure-routes.ts`)는 바꾸지 않았다 — 같은 함수를 부른다.
뜻("이 구역 원 안의 정점 수", 연장 절단분은 세지 않음)은 그대로다.

- `waiting` — 세션 2의 backend(`pg_backend_pid()`)가 `pg_stat_activity`에서 `state='active'`, `wait_event_type='Lock'`,
  claim을 실행 중(production: advisory lock에서 기다림, 커밋 뒤 E 행을 봄);
- `returned` — 세션 2의 claim이 세션 1 커밋 **전에** 이미 돌아옴(잠금 없는 변이: E 행을 못 본 채 끝남 → `1, 1`).

두 경로 모두 결정적이다: 고정 지연(r1의 300 ms)에 기대지 않으므로 세션 2가 늦게 시작해도 세션 1은 커밋하지 않고 기다린다
(M2-01 phase delta review, 9fd0538 REQUEST CHANGES의 지적). 단언:

1. 두 claim 모두 `true`;
2. 두 행 모두 `links_cut` **2**(장소 합계가 맞음);
3. 이어서 E·F를 번갈아 12번 claim하면 허용이 8번뿐 — 장소 전체 **10**(`shareLinksPerAreaLifetime`);
4. 관찰된 상태가 `waiting`(잠금이 한 일) — 변이에서 과소 계수 자체가 먼저 판정되도록 마지막에 단언.

## 7. 미해결

- 054의 SQL 주석(claim 본문 안, `prosrc`에 들어감)이 여전히 "the concurrency tests pass with or without this line"이라고
  말한다. 이제 틀린 문장이지만 054는 main에 적용된 마이그레이션이고, 주석 하나를 위해 함수 본문을 바꾸는 056을 만드는 것은 이
