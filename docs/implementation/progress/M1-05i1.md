# M1-05i1 · 코치 실행 상태·요청 계약

상태: **completed**. 선행 M1-05h 완료.

버전 1 생성 명령은 근거 ID, 기대 상담 revision, 멱등 키만 받는다. thread ID는 경로,
정책과 모델 출처는 서버가 정한다. 실행 결과 계약은 결정론 fixture와 실제 provider 출처를
구분한다. `queued`·`running`의 사용자 의미 진행 단계, `needs_question`,
`unable_to_evaluate`, `cancelled`, `analysis_ready`, `validated_final`을 엄격한 구분
상태로 표현한다.

`analysis_ready`는 미검증 출력 ID만 갖는 승인 불가 상태다. 이후 `running`의 후보 검증
단계를 거쳐야 검증된 결정 ID를 갖는 `validated_final`로 이동한다. 잠정 문장은 결정으로 위장할 수
없으며, 질문·실패·취소·검증 완료 상태는 종료 상태다. 답변 또는 재시도는 후속 실행을
새로 만들어야 한다. 스키마와 순수 전이 함수는 상태를 정의할 뿐 실행을 지속하거나 계획을
승인하지 않는다.

검증: 상태·전이·strict 생성 명령·모델 출처·입력 경계 단위 시험 7개, contracts
typecheck/build, 변경 파일 ESLint·Prettier, DAG·문서 링크·diff 검사. 실DB 원장,
실제 모델, API, 브라우저 및 승인 transaction은 M1-05i2 이후의 작업이다.

Herdr 분할 pane 리뷰의 base/tree identity와 최종 결과는 이 task 커밋 본문에 기록한다.
