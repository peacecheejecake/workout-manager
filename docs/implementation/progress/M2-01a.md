# M2-01a · Track 계약·정규화

상태: **계약·파서·정규화 구현 완료, 검증은 아래 수치와 테스트 이름까지만**. 서버 저장,
API, worker 배선, UI, 실제 지도 표시는 이 작업에 **포함되지 않았다**(b/c/d/e의 범위).
기준 HEAD `0bf41ca`. 계획 문서는 [map-implementation-plan.md](../map-implementation-plan.md)
3·4·7·8절이다. `task-graph.json` 상태는 root가 소유하므로 바꾸지 않았다.

## 고정한 경계

- **track 계약은 상세 계약과 분리했다.** `packages/contracts/src/tracks.ts`를 새로 만들었고
  `activity-details.ts`는 **한 글자도 고치지 않았다**. 상세 v1~v3 record는 여전히
  `index/timestamp/distanceMeters/heartRateBpm`만 허용하고 좌표를 strict 거절한다. 연결은
  한 방향으로만 존재한다: track sample의 `detailLink`가
  `{detailSchemaVersion, streamIndex, sessionIndex, recordIndex}`로 상세 record를 가리킨다.
  `trackDetailLink.recordIndex` 상한은 `activityDetailLimits.records`에서 가져온다.
- **provenance union.** 로컬 preview는 `local-file`(format·fileSha256·fileByteLength·parserId·
  parserVersion·streamIndex·sourceItemIndex·streamLabel)이고 저장된 track은
  `activity-source`(activityId·sourceId·sourceRevision·trackRevision)다. 두 쪽 모두
  `strictObject`라서 로컬 preview에 `activityId`를 넣으면 거절된다. **preview는 Activity ID를
  만들지 않는다.**
- **좌표는 WGS84 `[longitude, latitude]` 2차원 tuple뿐이다.** `z.tuple([lon, lat])`이므로
  세 번째 차원(시간·심박·고도)을 넣을 수 없다. 유한 수·범위(±180/±90) 검증을 한다.
- **sampleId는 `${streamIndex}:${sourceIndex}`**이고 계약이 "id가 자기 sourceIndex를 담을 것",
  "중복 없음", "원본 순서 증가", "모든 sample이 정확히 한 segment에 속할 것"을 refine으로
  강제한다. 같은 bytes를 두 번 파싱하면 같은 id·같은 출력이 나온다(테스트로 확인). 재파싱에서
  대응이 달라지면 새 revision이라는 규칙은 **계약 주석과 `trackRevision` 필드로 표현했을 뿐,
  아직 그것을 강제하는 서버 쓰기 경로가 없다**(아래 미검증 목록).
- **결손은 0이나 추정치로 채우지 않는다.** 좌표가 없는 sample은 삭제되지 않고 심박·거리·시각을
  그대로 유지한 채 자기 segment(`missing-position`)에 남으며, 앞뒤 좌표는 **연결되지 않는다.**
- **segment 분할 사유는 데이터다.** `stream-start / gpx-trkseg / fit-session / fit-event-stop /
missing-position / time-gap / position-gap / time-reversal / duplicate-timestamp /
antimeridian-crossing`. 분할 정책(`{version:1, maxGapSeconds:60, maxGapMeters:200}`)을 track에
  같이 저장하므로 나중에 정책이 바뀌어도 과거 track의 해석이 흔들리지 않는다.
- **한 점은 선이 아니다.** MapPath는 좌표가 2개 미만인 segment를 `points`와
  `insufficient(single-point | no-position)`로 보고하고, 계약이 1개짜리 line 자체를 거절한다.
  경도 경계 횡단은 segment를 끊고 `crossesAntimeridian`을, web-mercator 표시 한계(±85.05112878)
  초과는 `outsideDisplayLatitude`를 세운다.
- **거리는 네 가지가 서로 다른 값이다.** `distances.deviceReportedMeters`(기기 보고),
  `distances.recomputedFromPositionsMeters`(segment 내부 좌표쌍 haversine 합),
  `mapPath.displayedPolylineLengthMeters`(그려진 선 길이), routing 예상 거리(Course/RouteRevision,
  이번 범위 밖). 단순화는 **표시 선 길이만** 바꾸고 집계는 바꾸지 않는다.
- **집계 출처 우선순위 유지.** `trackAggregates`의 페이스는 기기 보고 거리로만 계산하고, 기기
  거리가 없으면 GPS 재계산 거리로 대체하지 않고 `null`로 둔다. 평균 심박은 device session
  평균이 아니라 sample 비가중 평균이라고 이름과 주석에 적었다.
- **GPX track / route / waypoint는 섞이지 않는다.** `trk`는 `recorded`, `rte`는
  `plannedRoute`(`sourceKind: 'gpx-rte'`), `wpt`는 `waypoints`로 따로 나온다. route가 실제
  기록으로 승격되는 경로는 없다. 파일에 track/route가 2개 이상이면 `requiresSelection`이
  true가 되고, 계약 refine이 이 값과 실제 개수의 불일치를 거절한다. 임의 병합은 하지 않는다.
- **FIT 다중 session.** session마다 별도 track이 되고(`sourceItemIndex`로 구분), record가 어느
  session에도 유일하게 속하지 않으면 추측하지 않고 `TRACK_SESSION_ASSIGNMENT_AMBIGUOUS`로
  실패한다. chained stream은 `streamIndex`가 달라 sampleId가 겹치지 않는다.
- **한도는 일한 만큼 청구한다(추정 회계이지 메모리 상한이 아니다).** 파싱 예산(`ParseBudget`)이
  (1) 입력 buffer, (2) decode할 텍스트(UTF-16 최악값 2배), (3) 원본 sample, (4) 정규화 sample을
  단가 256 B로 청구하고 넘으면 `TRACK_PARSE_MEMORY_LIMIT`로 실패한다. 큰 배열이 늘어나는
  지점마다 **그 항목을 만들기 직전에** 청구하지만, XML scanner의 임시 문자열·attribute map,
  Zod가 parse에서 만드는 사본 같은 중간 객체는 **청구되지 않는다**. 즉 "프로세스가 N byte를 넘게
  쓰지 않는다"는 보장이 아니라 "작업량이 한도를 넘으면 더 진행하지 않는다"는 보장이다.
- **정규화 출력은 부분마다, 문서가 만들어지기 전에 청구한다.** sample·segment·route point·
  waypoint는 각자 **정확한 직렬화 byte**로 청구하고, 배열 구분자는 **항목 사이에만** 더한다
  (첫 항목 0, segment의 첫 id는 따옴표만). track·route의 자체 구조와 문서 skeleton은 배열을
  비운 객체의 정확한 직렬화로 청구한다. escape(따옴표·역슬래시·비ASCII)는 `JSON.stringify`
  결과를 UTF-8로 재는 방식이라 그대로 포함된다. 따라서 누적 합은 실제 문서 크기 **이상**이면서
  거의 같고, 한도를 넘는 문서는 만들어지기 전에 거절된다(긴 이름 route, 4,000점 track, escape가
  필요한 이름, 다중 track/route/waypoint, 2,000 segment 다섯 fixture에서 차이 8 B 이하 확인).
- **확장자·MIME을 믿지 않는다.** `detectTrackFormat`이 내용을 보고 FIT(`.FIT` magic)과 XML을
  구분하며, ZIP/gzip/7z/rar/xz magic은 `TRACK_ARCHIVE_REJECTED`로 거절한다(archive 미수용).
  FIT은 framing·header CRC·**trailer CRC**를 값 해석 전에 검증한다. "CRC 0은 생략"은 FIT 명세상
  **header CRC에만** 허용되므로 trailer를 0으로 채운 파일은 통과하지 못한다. GPX는 **root의 실제
  namespace**(prefix를 scope에서 해석)가 GPX 1.0/1.1이고 local name이 `gpx`일 것을 요구하며,
  두 번째 root, 잘못된 부모 아래의 `trk/trkseg/trkpt/rte/rtept/wpt`, 다른 namespace의 동명
  element를 각각 거절하거나 무시한다.
- **빈 값은 0이 아니다.** `lat=""`·`lon=" "`처럼 비어 있는 좌표는
  `TRACK_COORDINATE_INVALID`로 거절하고, `<ele/>`·`<time/>`·`<hr/>`처럼 빈 선택 측정치는
  `null`로 남긴다. 어느 쪽도 0으로 채우지 않는다.
- **FIT timer stop은 모든 정지 유형을 인식하고, 시각이 아니라 파일 순서로 판정한다.**
  event_type 1(stop)/4(stop_all)/8·9(stop_disable 계열)이 segment를 끊는다. 폐기된(deprecated)
  `end`/`end_all` 계열과 다른 alert event는 기록 중단의 근거가 아니므로 포함하지 않는다.
  판정 기준은 **message 순서**다: stop message가 두 record message 사이에 있으면 끊고, 같은
  1초 timestamp를 공유해도 순서가 결정한다. 첫 record 앞의 stop은 끊지 않는다. TypeScript
  리더(message ordinal)와 Python export(`_message_ordinal`) **양쪽 모두** 같은 규칙이다.
- **lap 대응은 살릴 수 있으면 살린다.** lap 구간은 닫힌 구간([start, end])이고, 어떤 시각을
  정확히 하나의 lap만 포함하면 다른 lap끼리 겹치더라도 그 관계를 유지한다. 둘 이상이 포함하는
  시각(공유 경계 포함)만 `null`(미상)이며 임의로 고르지 않는다. 이 정책은 stream당 한 번 만드는
  포함 관계 표로 구현하고 테스트로 고정했다.
- **중첩 root와 확장 namespace.** GPX 안에 다시 나타나는 `gpx`는 거절한다(내부 요소가 root의
  자식처럼 보여 작성 중이던 track을 덮어쓸 수 있다). 열려 있는 track/route/point가 있는데 같은
  종류가 또 열리면 거절한다. 심박은 `trkpt > extensions > TrackPointExtension > hr`이고
  Garmin TrackPointExtension v1/v2 namespace일 때만 읽는다. `extensions`가 **해당 trkpt의 직계
  자식**인지까지 확인하므로 중간에 다른 namespace의 wrapper를 끼워 넣어도 읽히지 않는다. XML attribute는 중복을 거절하고,
  self-closing element도 depth 한도에 포함한다.
- **−180°는 실제 좌표다.** sint32 invalid sentinel은 `0x7FFFFFFF` 하나뿐이므로 `-2^31`
  semicircle은 정확히 경도 −180°로 보존되고(위도로 쓰이면 범위 초과로 거절), 두 파서가 같은
  해석을 한다.
- **XXE 차단.** 자체 XML scanner는 DOCTYPE/ENTITY 선언을 만나면 즉시
  `TRACK_XML_DTD_BLOCKED`, 미리 정의된 5개 외의 entity 참조는 `TRACK_XML_ENTITY_BLOCKED`로
  거절한다. 외부 DTD·외부 엔티티·namespace URL을 **가져오지 않는다**(네트워크 호출 자체가 없다).
- **파일명·메타데이터의 control/XSS.** 계약의 `trackTextSchema`는 C0/C1·bidi override·`<`/`>`를
  거절하고, 파서의 `sanitizeMetadataText`는 control/bidi를 제거한 뒤 남는 것이 없으면 `null`로,
  `<`/`>`가 있으면 `TRACK_TEXT_UNSAFE`로 거절한다.

| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 좌표는 `[lon, lat]`·유한·범위 검증               | contracts `track coordinate contract > accepts WGS84 …`, `> rejects non-finite coordinates`                                                                                                                                                   |
| 시간/심박을 좌표 차원에 넣을 수 없다             | contracts `> refuses extra coordinate dimensions so time and heart rate cannot hide in geometry`                                                                                                                                              |
| preview가 Activity ID를 만들지 않는다            | contracts `track provenance > keeps a local preview free of any Activity identity`                                                                                                                                                            |
| 저장 track은 activity/source/track revision 필요 | contracts `> requires activity, source and track revisions for a stored track`                                                                                                                                                                |
| sampleId가 자기 원본 index를 담고 유일·증가      | contracts `sample identity and segments > requires the sample id to encode…`, `> rejects duplicate ids…`                                                                                                                                      |
| 모든 sample이 정확히 한 segment에 속한다         | contracts `> requires every sample to belong to exactly one segment`                                                                                                                                                                          |
| 한 점은 선으로 그려지지 않는다                   | contracts `map path contract > refuses a one-vertex line…`, ingestion `> reports a single-point recording as a point, not a line`                                                                                                             |
| vertex→sample 매핑 누락 거절                     | contracts `map path contract > accepts a mapped line and rejects a mapping that misses a vertex`                                                                                                                                              |
| 파일명·메타데이터 control/XSS 거절               | contracts `untrusted metadata text > rejects control, bidi-override and angle-bracket characters`, gpx `> rejects angle brackets that survive entity decoding in metadata`, `> strips control and bidi characters from the original filename` |
| 상세 v1~v3 replay 동일·GPS 여전히 거절           | contracts `link to the GPS-free detail contract > leaves the existing detail versions unchanged and still GPS-free`                                                                                                                           |
| Python export가 계약을 실제로 만족               | contracts `the Python FIT producer matches this contract > validates the exported track payload`, `> is also a valid single-track parsed file`                                                                                                |
| RawTrackFile 계약(서버 생성 key·출처 union)      | contracts `raw track file record > accepts an upload and an activity-linked original…`                                                                                                                                                        |
| FIT semicircle → degree 변환                     | fit `> converts semicircles to WGS84 degrees and keeps [longitude, latitude] order`, python `test_semicircles_become_degrees_in_longitude_latitude_order`                                                                                     |
| invalid sentinel은 null이고 다른 측정은 보존     | fit `> turns the invalid coordinate sentinel into null and keeps the other measurements`, python `test_invalid_position_sentinel_is_null_and_keeps_other_measurements`                                                                        |
| 손상 FIT(파일 CRC·헤더 CRC·절단) 거절            | fit `> rejects a corrupt file CRC, a corrupt header CRC and a truncated stream`                                                                                                                                                               |
| 확장자/MIME 불신, archive 거절                   | fit `> does not trust the extension…`, `> rejects archives instead of unpacking them`                                                                                                                                                         |
| FIT 다중 session은 명시 선택 요구·임의 병합 없음 | fit `> keeps two sessions as two tracks that require an explicit selection`, `> refuses to guess an owner when a record belongs to no unique session`                                                                                         |
| FIT session/event 경계가 segment를 만든다        | fit `> starts a new segment after a timer stop event`                                                                                                                                                                                         |
| chained stream의 sampleId가 겹치지 않는다        | fit `> reads chained streams as separate tracks with disjoint sample ids`                                                                                                                                                                     |
| XXE(DOCTYPE/외부 엔티티) 차단                    | gpx `> blocks DOCTYPE and external entity declarations (XXE)`, `> blocks a reference to a custom entity even without a DOCTYPE`                                                                                                               |
| GPX root/namespace 검증                          | gpx `> requires a GPX root element and a known GPX namespace`                                                                                                                                                                                 |
| `trkseg`가 별도 segment                          | gpx `> keeps each trkseg as its own segment`                                                                                                                                                                                                  |
| route/waypoint가 실제 기록으로 승격되지 않음     | gpx `> never promotes a route or a waypoint into a recorded track`                                                                                                                                                                            |
| 다중 track은 명시 선택 요구                      | gpx `> requires explicit selection when a file holds several tracks`                                                                                                                                                                          |

| 경도 경계 횡단·극지 표시 한계·동일 좌표          | normalize `> splits an antimeridian crossing…`, `> flags positions beyond the web-mercator display latitude`, `> accepts repeated identical coordinates without splitting or inventing motion`                                                |
| 결손이 앞뒤 직선으로 이어지지 않는다             | normalize `> keeps an unpositioned sample with its measurements and never fills the gap`                                                                                                                                                      |
| **단순화·LOD 전후 모든 집계 동일**               | normalize `> simplification and level-of-detail changes leave every aggregate identical`(tolerance 0/1/5/20/100, vertex 수는 실제로 줄고 집계·원본 track은 불변)                                                                              |
| 표시 선 길이 ≠ 기기 거리 ≠ 재계산 거리           | normalize `> device, recomputed and displayed distances are three separate values`, fit `> keeps the device-reported distance apart from the recomputed distance`                                                                             |

## Peer review 대응 (base `0bf41ca`)

독립 peer review가 blocking 7건과 non-blocking 3건을 **모두 재현된 결함**으로 보고했고 전부

1. **메모리 한도가 메모리를 제한하지 않던 문제.** 입력 byte와 상수를 비교하던 검사(정확히는

2. **record 후처리 루프의 미제한 작업.** 루프 안에 `budget.check()`와 `budget.charge()`를 넣고,

3. **trailer CRC 우회.** `fileCrc !== 0` 예외를 삭제하고 trailer를 **항상** 비교한다. "CRC 0은

4. **빈 GPX 숫자가 0이 되던 문제.** 좌표는 공백/빈 문자열이면 `TRACK_COORDINATE_INVALID`로

   아예 청구되지 않았고(256자 이름 route가 342 B 한도에서 1,166 B를 생산), 배열 구분자도 빠져
   있었다(4,000점 track이 853,709 B 한도에서 857,474 B를 생산). 이제 항목마다
   `정확한 직렬화 byte + 1`을 청구하고, segment는 구조와 id를 나눠 정확히 청구하며, track·route의
   자체 구조와 문서 skeleton은 배열을 비운 객체의 정확한 직렬화로 청구한다. escape는
   `JSON.stringify` 결과를 UTF-8로 재므로 포함된다. 네 개의 공격적 fixture(긴 이름 route,
   4,000점, escape 이름, 다중 track/route/waypoint)로 "통과 최소 한도 ≥ 실제 크기"를 검증한다.
2. **중첩 `<gpx>`가 track을 덮어쓰던 문제.** root가 아닌 위치의 GPX `gpx` element를
   `TRACK_GPX_INVALID_ROOT`로 거절하고, 열려 있는 track/route/point가 있는데 같은 종류가 또
   열리면 `TRACK_XML_MALFORMED`로 거절한다. 파서 상태가 조용히 교체될 경로를 없앴다.
3. **같은 초의 stop을 놓치던 문제.** timestamp 비교를 버리고 **message 순서**로 바꿨다. TS는
   stream 내 message ordinal을 record와 stop에 기록하고 "이전 record와 현재 record 사이에 stop
   ordinal이 있는가"로 판정한다. Python은 `parse_fit_streams(..., with_order=True)`가 넣어 주는
   `_message_ordinal`로 같은 판정을 한다(변환 경로는 이 인자를 쓰지 않으므로 출력 불변).
   같은 초 stop이 끊고, 첫 record 앞의 stop은 끊지 않는 것을 양쪽 테스트로 고정했다.
4. **외부 namespace의 `hr`을 읽던 문제.** 심박은 Garmin TrackPointExtension v1/v2 namespace이고
   `trkpt > extensions > TrackPointExtension > hr` 구조일 때만 읽는다. `urn:evil`의 `hr`,
   `extensions` 없는 구조는 무시한다. 기존 fixture도 namespace를 선언하도록 고쳤다.
5. **lap 대응을 통째로 버리던 문제.** 겹침이 있으면 전부 `null`로 만들던 방식을 버리고, stream당
   한 번 만드는 포함 관계 표로 **유일하게 포함되는 시각은 관계를 유지**하고 둘 이상이 포함하는
   시각(공유 경계 포함)만 `null`로 둔다. 경계 정책을 계약 주석과 코드 주석에 명시하고 테스트로
   고정했다.
6. **XML 한도 우회 2건.** 같은 attribute의 반복을 `TRACK_XML_MALFORMED`로 거절하고(중복은 XML
   위반이며 `Map.size`를 키우지 않아 32개 상한을 지나쳤다), self-closing element도 depth 검사에
   포함한다. 이 변경으로 `gpx > trk > trkseg > trkpt`의 실제 depth가 4가 되어 기존 경계 테스트
   값을 3/2에서 4/3으로 고쳤다.
7. **문구 정정.** "모든 부분을 할당 전에 청구한다"는 표현을 버렸다. 정규화 sample은 이제 생성
   직전에 청구하지만, XML scanner의 임시 문자열·attribute map과 Zod 사본은 청구되지 않는다는
   점을 "고정한 경계"와 "검증하지 않은 것"에 명시했다.

검토자가 근거와 함께 유지하라고 한 항목은 바꾸지 않았다: stop event type 1/4/8/9 목록(폐기된
`end` 계열과 다른 alert은 기록 중단 근거가 아니라는 점을 주석과 문서에 명시했다), `0x7FFFFFFF`만
sint32 invalid로 보는 −180° 보존, `activity-details.ts`의 base 동일성.

### 3차 검토 대응

세 번째 peer review가 2차 수정 7건을 모두 fixed로 확인하고 3건을 남겼으며 모두 반영했다.

1. **심박 구조 검증의 남은 구멍.** `trkpt > foreign:wrapper > extensions > TrackPointExtension >
hr`이 여전히 읽혔다. `extensions`가 **현재 trkpt의 직계 자식**인지까지 확인하도록 고치고
   wrapper fixture를 추가했다. 이제 "이 구조에서만 읽는다"는 문장이 코드와 일치한다.
2. **Python의 조용한 저하.** message ordinal이 없을 때 stop을 버리거나 `False`를 돌려주던 경로를
   없앴다. `message_ordinal()`이 누락 시 `ValueError`(타입 불일치는 `TypeError`)로 실패하고,
   stop이 있는 호출에서 record ordinal이 없으면 같은 방식으로 실패한다. CLI는 항상
   `with_order=True`로 부르므로 현재 도달하지 않는 경로이지만, 내부 계약 위반은 "stop 없음"으로
   조용히 바뀌면 안 된다. 계약 위반을 실제로 일으키는 테스트를 추가했다.
3. **출력 회계의 남은 과대평가.** 검토자가 측정한 2,000 segment의 +2,003 B는 배열마다 **첫
   항목에도** 구분자를 물리던 탓이었다. 이제 구분자는 항목 **사이**에만 청구한다(첫 항목은 0,
   segment의 첫 id는 따옴표만). 기존 4개 fixture와 새 2,000 segment fixture 모두에서
   `threshold - 실제 크기 <= 8 B`를 단언한다.
4. **메모리 행.** 계획 7절이 요구하는 "실제 메모리 상한 + 초과 시험"은 **충족하지 못했음**을
   "검증하지 않은 것" 목록에 명시하고, worker 배선 단계로 이월한다고 적었다.
5. **flake.** 추측을 지우고 관측만 남겼다(위 "전체 suite 실행과 미해결 실패 1건").
