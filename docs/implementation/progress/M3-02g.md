# M3-02g · 제품 HealthKit 동의·검토 UI

상태: 로컬 수용 완료. `phase/m3-02`의 하위 작업이며 phase 독립 검토 전이다.

## 구현 범위

- native 계정 화면은 서버 HealthKit 동의와 iPhone 운동 읽기 요청을 서로 다른 명시적 액션으로 보여준다. 서버의 동의 revision을 다시 읽고, 제한된 전송 대기·보류 상태를 표시한다. Apple이 앱에 알려주지 않는 읽기 허용 여부와 실제 표본 부재를 확정하지 않는다. 브라우저 계정 화면은 iPhone 앱에서만 수집할 수 있음을 알린다.
- 본인 계정의 동의가 유효한 경우에만 검토 대기 중인 active workout의 UUID·digest·종목·시각·기간·거리를 제한된 목록으로 조회한다. tenant 경계, 결정적 순서, 수량 제한, 철회 후 비공개를 실제 저장소와 API에서 검사한다.
- 공통 Web·mobile Activity 화면은 목록을 사용자가 열기 전에는 조회하지 않는다. UUID 하나를 선택해 새 Activity 생성 또는 현재 선택한 FIT/수동 Activity 연결을 명시적으로 확인한다. 처리 경로는 기존 M3-02i/e 명령을 재사용한다. 응답을 확인하지 못한 쓰기는 같은 본문과 멱등 키로만 재시도하며, 동의·원본·대상 충돌은 목록을 다시 확인한다.
- 확정된 Activity는 공통 URL 선택과 기존 Activity 상세 조회를 사용한다. HealthKit 소유 source는 Apple 건강 운동으로 구별되고, 보조 연결은 원래 대표 source와 Activity 합계를 유지한다.

## 검증과 한계

- M3-02g 집중 계약·API·컴포넌트 시험과 native 계정 shell 시험을 통과했다. 브라우저 인증 transport에서 필요한 HealthKit 경로만 허용하고 인접 경로 차단을 확인했다.
- 실제 PostgreSQL 전체 통합 87개 파일·840개 시험 통과. 전체 단위·컴포넌트 4,229 통과·기존 7건 건너뜀. 생성물 검사, 전체 Prettier·ESLint, TypeScript 34/34, build 15/15, 기본 Playwright 4/4가 통과했다. 인증된 Web·mobile 320px HealthKit 선택 검사 2/2가 통과했다.
- 첫 전체 단위 실행에서 새 HealthKit 알림이 추가되자 기존 native shell 테스트의 단일 alert 가정이 깨졌다. 알림의 정확한 문구를 확인하도록 고친 뒤 전체를 다시 실행해 통과했다. 첫 브라우저 집중 실행에서는 인증 transport 허용 목록에 새 경로가 없어 실패했고, 정확한 경로 허용과 회귀 시험을 추가한 뒤 재실행해 통과했다.
- 첫 identity 전체 실행은 별도 worktree에 지도·고도 생성 자료 경로가 빠져 코스 검사가 실패해 중단했다. 자료 경로를 지정한 다음 실행은 303 통과·13건 건너뜀·1건 실패였다. 실패는 HealthKit 문구를 분리한 뒤 이전 결합 문구를 찾던 계정 삭제 테스트였고, 현 화면의 Garmin 상태와 HealthKit 안내를 각각 확인하도록 고쳐 해당 파일을 단독 재실행해 통과했다. 이 두 실행은 전체 통과 증거로 세지 않는다.
- 지도·고도 자료 경로를 지정한 전체 identity 두 실행은 각각 304 통과·13건 건너뜀(14.4분, 14.4분)이었다. 첫 실행 이후 테스트의 시간 의존 단언만 수정했고 제품 코드는 바꾸지 않았다.
- 두 번째 전체 실행은 Next 활동 지도 휠·resize 항목 1건이 실패해 초기에 중단했다. 집중 반복에서는 Next 2/3 실패, Vite 3/3 통과였다. 실패 시 지도 범위와 연결된 차트 확대는 유지됐지만 마지막 지도 이벤트가 뒤따른 resize의 `programmatic`으로 기록됐다. 따라서 지속되는 결과인 지도 범위 변경·차트 확대를 확인하고 마지막 이벤트 출처에 대한 시간 의존 단언을 제거했다. 그 후 집중 반복 Next·Vite 6/6이 통과했다. 중단 실행과 실패한 집중 반복은 전체 통과 증거로 세지 않는다.
- Aside CLI update 확인은 `fetch failed`, Chrome 탭 연결은 `Debugger unattached`였으므로 제품 브라우저 검증에는 Playwright를 사용했다. 기기 확인 시 iPhone은 Xcode에 `Offline`으로 표시됐다. 서명된 제품 iPhone의 실제 운동 수집·삭제·background delivery·offline ACK·재설치·계정 전환은 M3-02h의 `not_executed`로 남는다. 브라우저 mock 응답과 PostgreSQL 시험은 실기기 증거가 아니다.
