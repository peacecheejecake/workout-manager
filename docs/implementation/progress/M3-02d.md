# M3-02d · HealthKit 원본의 집계 제외 검토 대기 투영

상태: **completed (로컬 저장 경계)**. `phase/m3-02`의 하위 작업이며 phase 독립 검토 전이다.

## 범위

- 수신한 workout UUID별 원본에서 tenant 범위의 검토 대기·삭제 상태를 원자적으로 만든다.
- 유사한 시간·거리만으로 Garmin 또는 다른 운동과 자동 병합하거나 canonical Activity를 새로 만들지 않는다. 검토 대기 원본은 대시보드·기간 합계에 포함하지 않는다.
- 재전송, 삭제 비부활, 동의 철회, 계정 삭제·내보내기와 동시성에서 원본과 투영의 수명을 맞춘다.

## 판정 경계

명시적 사용자 연결 또는 독립 운동 생성, 재설치 재조정, 공통 Activity 화면, 실제 iPhone 경로는 이 노드에서 `not_executed`이며 후속에서 별도 확인한다.

## 구현·검증 기록

- migration 060은 raw workout `(athlete_id,sample_id)`마다 검토 대기·삭제·억제 lineage 한 행을 둔다. raw INSERT/상태 UPDATE 트리거가 같은 거래에서 투영하므로 투영 실패 시 원본과 ACK도 롤백된다. 기존 raw 행은 migration 거래 안에서 backfill한다. canonical Activity와 기간 합계는 생성·변경하지 않는다.
- runtime role은 lineage 읽기만 가능하고 FORCE RLS가 tenant를 격리한다. raw 삭제와 동의 철회·계정 삭제는 FK CASCADE로 lineage를 제거한다. 계정 내보내기 v26은 UUID와 제한된 상태만 포함하며 v25 이하는 그대로 읽는다.
- 구현 agent의 격리 PostgreSQL 집중 39/39에서 owner 업그레이드 backfill, 권한·테넌트, ACK 롤백, 중복 upsert·삭제·철회·내보내기를 확인했다. 첫 업그레이드 검사에서 FORCE RLS 아래 기존 행이 빠지는 문제를 발견해, migration의 DDL 잠금 거래 안에서만 raw 테이블의 FORCE를 잠시 풀고 다시 켜 수정했다. 수정 후 전체 집중 검사를 통과했다.
- root의 결합 트리 검사에서 생성물, Prettier, ESLint, 전체 TypeScript 34/34, 단위 4,197 통과·7 건너뜀, 실제 PostgreSQL 통합 822 통과, build 15/15, 기본 Playwright 4/4가 통과했다. 첫 단위 실행의 로컬 fixture/Python 경로 실패는 재실행으로 해결했고 최초 실패를 통과로 바꾸지 않는다.
- 계정·화면 identity 전체를 직렬로 두 번 실행해 각각 **302 통과·13 건너뜀**을 확인했다. 건너뛴 외부 조건과 서명된 제품 iPhone의 `not_executed`는 통과로 바꾸지 않는다.
