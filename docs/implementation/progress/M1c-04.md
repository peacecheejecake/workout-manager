# M1c-04 · 다영역 통합 승인

상태: **완료 (schema v4 승인 core와 통합 Planner)**. V023-A29/A30/A36 범위에서
훈련·영양·회복·routine schedule 변경을 하나의 서버 소유 후보로 고정하고,
사용자의 명시적 확인 뒤 같은 transaction에서 네 도메인 version/head/history,
승인 이력, outbox와 receipt를 적용한다. 승인 전에 EvidenceSnapshot, 대화·선호·
제약 revision, 정책 버전, 16종 읽기 의존성과 존재하거나 아직 없는 네 plan head를
다시 검사한다. 성공 응답을 잃고 같은 idempotency key로 재요청하면 새 버전을
만들지 않고 최초 결과를 반환한다.

Migration 026은 훈련 plan에 버전과 분리된 안정적 aggregate ID를 추가하고, v4
후보·승인·이력 원장과 FORCE RLS, append-only 제약, 계정 말소 연동을 제공한다.
현재 plan head 저장소가 tenant마다 한 행을 갖는 계약에 맞춰 schema v4도 현재
훈련 aggregate/head를 하나로 제한하며, 다른 aggregate를 요청하거나 후보에 둘을
담으면 거부한다.
새 훈련 버전과 함께 승인한 영양 계획은 그 새 버전을 참조한다. 네 도메인 중
마지막 쓰기가 실패해도 앞선 쓰기와 outbox가 모두 rollback된다. 계획 승인은
Activity, IntakeEntry, RecoveryActionLog, RoutineRun을 생성하지 않는다.
RoutineRun과 스트레칭 detail은 실제 Activity 집계에 다시 더하지 않는다.

API는 명시적인 `maxSchemaVersion=4` 협상을 요구하고 구형 경계에는 schema v4를
노출하지 않는다. production에서 비활성인 서버 소유 fixture만 E2E 후보를 만든다.
web과 mobile-web은 같은 후보의 네 변경, head 기준, 의존성, 오류·미확인 상태를
검토하고 확인 checkbox가 선택된 뒤에만 승인한다. 승인 성공은 서버 commit 응답
뒤에 표시한다. 통합 Planner v4는 훈련·영양 계획/실제와 함께 회복 계획/실제,
루틴 발생분/run, 스트레칭 Activity detail을 날짜별로 표시한다. v1 기본 응답과
v2/v3 unsupported 동작은 유지한다.

검증: 전체 `pnpm check`의 포맷·lint·24개 패키지 타입 검사와 195개 파일/2,020개
단위 테스트, 격리 PostgreSQL 35개 파일/289개 테스트, 전체 production build
9개 task, OIDC·임시 PostgreSQL·Playwright Chromium E2E 1개가 통과했다. 실DB 시험은 원자
commit/rollback, 없는 head의 동시 생성, run·회복 방법·대화·동의·정책 최신성,
EvidenceSnapshot 전체 의존성 신선도, 영양 session/food 참조 소유권, unknown 거부,
tenant 소유권, 안정적 훈련 aggregate, 재전송과 runtime 권한을 포함한다. 브라우저
시험은 서버 fixture 재전송, web/mobile-web 검토, 320/768/1280 reflow와 focus 유지,
명시 승인, 네 도메인 조회, 실제 원장 비생성과 Planner 비중복 집계를 확인했다.
정확한 최종 파일·테스트 수와 peer-review 해시는 아래 리뷰 결과에 기록한다.
