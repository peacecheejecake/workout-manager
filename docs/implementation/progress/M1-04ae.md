# M1-04ae · 기간 우선순위 편집·버전 호환성

상태: 완료. S04의 기간별 우선순위를 편집·표시·저장한다.

## 범위와 설계 선택

- 원문은 Wave/Phase/Block의 우선순위를 요구하지만 enum은 정의하지 않았다. 기존 세션의
  vocabulary를 재사용한 `low/normal/high`와 미지정 `null`을 공통 기간 계약에 추가한다.
  Season에도 같은 입력을 제공한다. 이는 기간의 상대적 중요도를 사용자가 지정하는 선택이며,
  세션 우선순위·훈련 강도·수행 의무와 별개다.
- `priority`는 optional/nullable이며 과거 snapshot·receipt의 필드 누락을 그대로 보존한다.
  새 기간의 미지정은 명시적 null이다. 보통으로 자동 채우거나 과거 버전을 backfill하지 않는다.
- 기존 공유 초안·미리보기·명시 저장·취소를 사용하고 기간 상세·목록·전후 비교에 표시한다.
  기간 우선순위로 하위 세션의 중요도·날짜·부하를 바꾸거나 자동 상속하지 않는다.
- 세션 잠금은 기존 의미를 유지한다. 기간 우선순위만의 변경을 세션 잠금으로 차단하지 않는다.
  기존 JSON snapshot 계약을 확장하므로 DB column migration은 없다.
- 기간의 실행 가능한 제약은 별도 미완료 범위다. 원문에는 제약 종류·상속·충돌·미정 값·
  저장 차단/경고 정책이 없으므로 자유문 메모나 임의 생리적 상한으로 대체하지 않는다.
  사용자는 운동 불가 날짜·가용 시간부터 구현하도록 선택했다. 다음 별도 task에서
  날짜별 시간량과 충돌 표시를 구현하며 이 우선순위 작업의 완료에 포함하지 않는다.
