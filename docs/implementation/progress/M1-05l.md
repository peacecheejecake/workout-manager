# M1-05l · 코치·후보 검토 제품 UI

상태: **completed**. S10의 상담·저장 근거 화면에 실행 요청과 사용자용 진행 단계,
취소, 실행 이력, 명시적인 비프로덕션 fixture 후보 검증, 후보 링크를 연결했다.
근거와 완전히 읽은 대화 revision이 있어야 실행할 수 있다. 응답이 불확실할 때 같은
멱등 키로 재확인하고, tenant·로그인 세션·상담별 캐시와 요청 수명을 분리한다.

S11은 두 shell의 `/proposals/:candidateId` 경로에서 현재 상태·계획 head·후보를
조회한다. 원안과 제안의 날짜별 일정·세부 표, 기간과 세션 변경, 시간·거리 영향,
전략, 오류·경고·미확인을 함께 표시한다. 서버에 실제로 저장된 복수 후보가 있을
때만 서로 이동할 수 있다. 선택 변경은 부모 후보를 수정하거나 계획에 적용하지 않고
새 후보를 만든다. stale·철회 후보의 본문과 승인 동작은 숨긴다. 사용자의 확인
체크박스와 승인 버튼 뒤에도 상태·head를 다시 읽고 서버 승인 결과를 받아야 확정
버전과 저장된 계획 링크를 보여준다. 오류·미확인이 남은 후보는 승인할 수 없다.
mobile-web에도 공유 계획 모듈의 `/planner` 경로를 연결하여 성공 링크가 실제
저장된 계획 버전으로 이동한다.

실제 브라우저 검증: Aside CLI로 로컬 OIDC fixture에 로그인해 Next S10과
mobile-web S10의 인증·빈 상태, 잘못된 mobile-web 후보 주소의 오류를 확인했다.
전체 후보 흐름은 Playwright+로컬 OIDC+격리 PostgreSQL으로 검증했다. Next에서
저장 근거의 fixture 실행·부분 후보를 검토하고 mobile-web 320px에서 키보드로
명시 확인·승인한 뒤 새 계획 버전을 재조회한다. 768/1280px 전후 비교의 전체
화면 가로 넘침도 검사한다. 코칭 OIDC 회귀 6개, 두 shell 상담 회귀 2개와 격리
PostgreSQL 통합 226개, 전체 unit/component 1,785개, 생성물·Prettier·ESLint·
20개 패키지 및 루트 typecheck, 전체 build가 통과했다. 동료 리뷰 수정 후 관련
unit/component 13개와 전체 typecheck·lint·build, 두 shell 승인→mobile-web 계획
경로의 실DB 브라우저 테스트를 재실행했다. fixture 결과는 실제 모델 판단이나
프로덕션 코치 품질의 증거가 아니다.

브라우저 통합 중 로그인 transport의 새 코칭 경로 허용 누락을 수정하고 세션별
허용/유사 경로 거절 테스트를 추가했다. 기존 내보내기 통합 테스트의 v9 타입
좁히기와 계정 교체 shell fixture의 in-flight 요청 구분도 보완했다. Herdr
split-pane 리뷰의 세 지적에 따라 실패·재조회 중 오래된 질문/후보 본문을 숨기고,
현재 계획 head와 다른 후보 본문을 숨기며, mobile-web 계획 링크를 실제 화면에
연결했다. 정확한 base/tree identity는 task 커밋 본문에 기록한다.
