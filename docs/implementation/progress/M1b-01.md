# M1b-01 · 영양 수동 core

상태: **completed** (수동 영양 원장·두 웹 셸). G1 러닝 core 위에 영양 계획,
식품 정의, 실제 섭취를 별개의 저장 원장으로 추가했다.

계획은 사용자 확인 뒤 불변 `NutritionPlanVersion`으로 승인하며 새 계획 복제와
버전 갱신도 새 승인을 요구한다. 이 과정은 `IntakeEntry`를 생성하지 않는다.
식품 정의는 기준량·원자료·버전을 고정하고 사용자가 만든 값에 검토 완료 출처를
부여하지 못하게 한다. 실제 섭취는 확인, 안정된 명령 키, revision CAS로 생성·정정·
삭제된다. 삭제 읽기에는 tombstone만 남고 계정 삭제는 건강 원장을 지운다.

섭취 화면은 빈칸의 미상 값과 보고된 0을 구분하고, 알려진 값만 합산한다. 식품
기준 `per_serving`·`per_100g`·`per_100mL` 변환은 고정 버전과 수량·단위를
명시해 한 번만 적용하며, 불명 단위·나트륨/소금 환산이나 섭취/소비 에너지의
혼합 합계는 만들지 않는다. 한 `IntakeEntry`에 활동 둘을 연결해도 조회·합계는
원장 ID당 한 번이다. 웹과 모바일 웹은 같은 모듈을 사용하고 단일 편집기 초안은
로컬 상태, 서버 데이터는 인증 세션별 TanStack Query가 소유한다.

검증: 계약·API·화면 focused Vitest, PostgreSQL 통합 232/232, 실제 로컬 OIDC와
격리 PostgreSQL을 쓰는 Chromium 수용 5/5 (영양 1개와 기존 export 회귀 4개).
양쪽 웹 셸 production build, 타입·ESLint·Prettier를 통과했다. 브라우저 수용은
계획/실제 분리, 두 활동 연결·단일 집계, 0/미상 정정, 양쪽 셸 표시, 삭제 tombstone,
v10 계정 내보내기를 확인한다.

V022-A11–A13의 수동 흐름과 A14의 원장·내보내기·삭제 부분, A17–A18의 입력·
단위·부분값 부분을 구현했다. A14의 파생 EvidenceSnapshot/제안 최신성, A15의
세션 이동 combined preview, A16의 미래 상대 항목 재연결과 공동 승인 검증은
M1b-03 소유다. 이 수동 core 검증을 그 통합 수용 완료로 간주하지 않는다.
목록은 100건 상한을 넘으면 불완전함을 표시하며, 해당 날짜 활동 선택도 첫
100건까지만 제공한다. 추가 페이지 탐색은 후속 UI 작업이 필요하다.

실 브라우저 도구: Aside CLI 업데이트가 `fetch failed`였고 Chrome 컴퓨터 제어용
Orca는 `runtime_open_timeout`으로 창을 열지 못했다. AGENTS.md 순서에 따라
Playwright의 실제 Chromium을 사용했다. iPhone 실기기는 검증 범위가 아니다.

Herdr split-pane 1차 독립 리뷰: base `ed3ee41b023f18d619edf0727acc7ba55e6a4488`,
staged tree `dfe31c76de167974482116e65e5116492ceef299`. 편집기 재조회 중 초안
유실, 복수 영양 목표 편집, 새 상대 시각의 계획 연결, 메모 정정 시 원래 시각 소실,
섭취 목록 커서의 마이크로초 소실 등 P2 5건을 확인했다. 초안 baseline을 유지하고
최신 revision 충돌 시 제출을 차단했다. 목표 입력 초안과 나머지 목표를 분리했고,
소유 훈련 계획 세션을 조회·선택하도록 했다. 수정하지 않은 섭취 시각은 원래
instant를 사용하고, 커서는 PostgreSQL 마이크로초 정밀도를 보존한다. 보완한
영양 컴포넌트 테스트 15건과 커서 경계 테스트를 포함한 격리 DB 전체 240건이
통과했다. 뒤의 DB 전체에는 동시 진행 중인 보강 수동 core도 포함된다.
