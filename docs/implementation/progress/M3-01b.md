# M3-01b · 제품 Capacitor iOS shell·제한 bridge

상태: **completed** (한정된 M3-01b 범위). 기준 `phase/m3-01` `acb63a6`. 선행 M3-01a의 엄격한 v2 계약을 실제 제품 iOS shell에 연결했다. Phase 독립 검토와 main 병합은 후속이다.

범위는 번들 `apps/mobile-web/dist`를 쓰는 Capacitor iOS 프로젝트, main-frame·로컬 origin 검증, 명시된 `hello`와 `app.openSettings`만 처리하는 Swift plugin, 외부 페이지를 privileged WebView 밖에서 여는 정책, WebView에서 capability 확인과 인증 unavailable 표시다. WebView가 임의 URL을 native에서 fetch하거나 문자열을 실행하는 명령은 없다. 기존 probe fixture의 HealthKit 권한·표본·telemetry 코드를 제품 bundle로 복사하지 않는다.

현재 브라우저 로그인은 same-origin cookie/CSRF를 사용한다. `capacitor://localhost`에서 인증된 제품 기능이 작동한다고 주장하지 않고, system authentication session·일회성 code·Keychain·고정 HTTPS API transport는 별도 후속 작업으로 둔다. 이 노드의 시뮬레이터·컴파일 증거는 제품 iPhone 실기기의 Back/IME/foreground/HealthKit 수용이 아니다.

## 검증

- Node 24.12.0에서 새 36개 workspace의 `pnpm install --frozen-lockfile`: 통과. offline lockfile 갱신은 registry metadata가 없어 실패했고, 고정 버전 8.5.2의 온라인 갱신 후 재실행했다.
- `pnpm check:generated`, `pnpm format:check`, `pnpm lint`, `pnpm typecheck`(34/34와 root): 통과. 초기 formatter/linter는 복사된 iOS `public/` 생성물을 검사해 실패했고, 생성물 제외를 도구 설정에 추가했다. 추적하는 Assets JSON 3개는 형식을 맞췄다.
- `pnpm exec vitest run packages/platform/tests/native-bridge-client.test.ts packages/platform/tests/capacitor-bridge-port.test.ts`: 13/13 통과. `pnpm test`: 4,147 passed, 7 skipped. `pnpm build`: 15/15. `pnpm test:integration`: 임시 PostgreSQL에서 804/804 통과.
- `xcodebuild` unsigned generic iOS Simulator Debug 빌드: 구현 agent와 root 재실행 모두 통과. 최종 `mobile-web/dist/index.html`과 iOS `public/index.html`의 SHA-256이 일치하고, 주 JS bundle도 일치한다. 원격 `server.url`은 없다.
- 격리된 iPhone 17/iOS 26 Simulator: 첫 bridge 등록 시도는 plugin unavailable이었으며, `CAPInstancePlugin` 등록으로 수정했다. 이후 임시 검증 overlay에서 `hello.result`와 ID·v2, HealthKit/auth false, `UNSUPPORTED_VERSION`, `UNSUPPORTED_METHOD`, 시스템 설정 화면 열림·앱 복귀 뒤 `opened`를 확인했다. 검증 overlay는 복사된 생성물에서 제거하고 최종 bundle로 동기화·재빌드했다. 첫 흰 화면의 원인은 단정할 수 없으며, 초기 source-frame URL 검사 대신 local 목적지 URL과 main-frame bridge 검사로 범위를 조정했다. 외부 최상위 navigation은 Safari에서 열렸고 앱 복귀 후 로컬 화면이 유지됐다. 외부 iframe은 빈 화면으로 관측했지만 네트워크 실패와 구분할 수 없어 Swift 차단 분기와 함께 제한적으로 해석한다. `_blank` 자동 `link.click()`은 Safari로 전환되지 않았으며 사용자 제스처 시험은 Mac 잠금으로 **not_executed**다. 이 정책의 보안 독립 검토는 phase 검토 때 별도로 받는다.
- Aside skill을 읽고 `aside --update`를 시도했으나 `fetch failed`로 사용할 수 없었다. Chrome에서 모바일 웹 홈·계정 경로를 확인했다. Playwright에서 native 플랫폼을 모의한 `/account` 진입은 인증 화면 대신 unavailable 화면을 표시하고 `/bff/` 요청이 0개였다. 새 identity 회귀 시험 단독 1/1 통과. 실제 WKWebView UI는 위 Simulator 기록과 구분한다.
- 전체 identity 회귀 두 회차: 각각 302 passed, 13 skipped (약 14.2분·15.2분). 조건부 제외·외부 증거는 통과로 표시하지 않는다.
