# M3-01 · Native shell·secure bridge phase

상태: **completed (로컬 구현·검증 범위)**. [M3-01a](M3-01a.md)부터 [M3-01f](M3-01f.md)까지 각 노드의 구현과 검증을 완료했다. 이 phase의 전체 `main` 대비 독립 검토와 병합 결과는 아래에 별도로 기록한다.

## 범위와 증거

- 제품 Capacitor iOS shell에 버전·메서드·payload를 검사하는 제한 bridge를 연결했다. 외부 navigation 및 WebView 메시지는 로컬 origin과 허용된 목적지로 제한한다.
- native 전용 OIDC 일회성 교환과 Keychain 세션 경계, 고정 HTTPS API origin의 두 인증 읽기 경로, 철회와 계정 범위 정리를 구현했다. 공개 HTTPS/IdP 설정이 없으면 인증 기능은 unavailable이다.
- 계정과 로컬 임시 초안 흐름에 가로 키보드 focus reveal, 미저장 Back 확인, foreground 세션 재확인을 연결했다. 초안은 서버 저장이나 실제 수행 기록으로 표시하지 않는다.
- 각 노드의 집중 검사와 전체 lint·typecheck·build·unit·integration·identity 결과는 노드 기록을 따른다. 최신 `main` 통합 뒤 생성물·포맷·lint·typecheck 34/34·build 15/15·unit 4,174 통과/7 제외·integration 811 통과를 다시 확인했다. iOS 웹 자산을 다시 복사하고 unsigned Simulator 빌드도 통과했다.
- 첫 병합 후 identity 전체 실행은 288 통과/16 제외/11 실패였다. 이 worktree에는 `.geo-build` 자료가 없어 코스 검색·고도·지도 사례가 `no_dataset`/`out-of-view`였다. 공용 생성 자료의 명시적 `IDENTITY_E2E_GEO_DATA_DIR`·`IDENTITY_E2E_BASEMAP_DIST_DIR`를 지정한 실패 영역 집중 재실행은 29/29 통과했다. 같은 자료를 지정한 전체 재실행 두 회는 각각 302 통과/13 제외(각 13.1분)였다. 첫 실패를 통과로 소급하지 않는다.

## 외부 수용 한계

- 서명된 제품 앱 설치와 실제 iPhone의 키보드·Back/edge gesture·foreground·Keychain·로그인·철회·운영 API 성공은 **not_executed**다. Xcode의 `No Accounts`와 프로비저닝 프로필 부재로 서명된 기기 빌드가 실패했고, 기본 제품 Info.plist의 운영 HTTPS API/IdP origin도 비어 있다.
- M2 전체 화면 조합·전체 업무 API와 HealthKit collector는 각각 M3-03·M3-02의 후속이다. M0-06c feasibility 앱의 실기기 관측을 제품 앱의 수용 근거로 대체하지 않는다.

## Phase 독립 검토

첫 Codex CLI `gpt-6-sol` high/read-only 검토는 `main` `8bd3814259922478e7b4a05111966b6621a14e05` → phase `6685fbbc36f8f2807e8b7b5eda878e8b7307903a` 전체 67파일 diff에 **CHANGES_REQUESTED**를 냈다. P2: JS의 시간초과·취소가 native 인증 작업에는 전파되지 않아 늦은 code 교환·Keychain 저장이나 로그아웃으로 화면과 실제 세션이 달라질 수 있었다. 검토자는 diff·기록·`git diff --check`를 확인했고 전체 시험이나 실기기 실행을 독립 재현하지 않았다.

수정은 Capacitor 포트의 요청 ID 기반 `cancel` sideband와 정리 응답 대기, Swift의 활성 Task·인증 세션·URLSession 취소, 교환 결과가 이미 도착한 로그인 토큰의 삭제·철회, 서버 철회가 확인된 로그아웃의 Keychain 정리다. 시간초과·취소 후 화면은 native 세션을 재조회하고, 불확실한 오류에서는 초안을 유지한다. 취소 응답 자체가 오지 않는 경우 대기는 유한하며 결과를 성공으로 추정하지 않는다. 서버가 교환·철회를 완료했지만 HTTP 응답이 유실되면 원격 결과를 즉시 확정할 수 없다는 한계는 남는다.

수정 후 집중 TS/화면 시험 31/31, 생성물·포맷·lint·typecheck 34/34·build 15/15·전체 unit 4,180 통과/7 제외·integration 811 통과, unsigned iOS Simulator 빌드가 통과했다. 공용 지리 자료를 지정한 전체 identity 두 회는 각각 302 통과/13 제외(각 13.1분)였다. 수정 HEAD의 독립 재검토는 남아 있다. 이 절의 수정 판정은 구현자 점검이며 독립 승인으로 간주하지 않는다. 승인 뒤에만 `main`을 fast-forward한다. 푸시는 사용자 작업이다.

두 번째 Codex CLI `gpt-6-sol` high/read-only 검토는 같은 main base → phase `ac98af47818879d5601753d7b32d55b0fd51912e` 전체 67파일 diff에 **CHANGES_REQUESTED**를 냈다. 첫 P2는 **NOT FIXED**다. `LocalBridgeViewController`의 실제 WK 메시지 가드가 `exchange`만 전달해 새 `cancel` sideband가 Swift 작업에 도달하지 못했다. 구현자는 로컬 main frame의 허용 목록에 `cancel`을 추가했다. 앞선 TS 모의 plugin 시험만으로는 이 경계의 통과를 증명하지 못한다.

수정 뒤 실제 iPhone 17 Pro/iOS 26 Simulator의 서명 없는 제품 앱에 임시 로컬 `capacitor://localhost` 검증 화면을 넣고 실행했다. 화면에서 `WorkoutNativeBridge.cancel({id})`는 `{"status":"cancelled"}`를 반환했고 허용되지 않은 메서드는 1.8초 동안 응답하지 않아 timeout으로 관측했다. 임시 스크린샷 `/private/tmp/wm-cancel-guard-probe.png`의 SHA-256은 `4849c64485f36f16230c1d466ca0767cd6345d99a4f9cc3fbb6843d87626eaf9`다. iframe은 메시지 전송까지만 관측했고 거부를 동적으로 증명하지 못했다. 코드의 `isMainFrame` 검사만 확인했다. 시험용 앱은 제거하고 복사된 웹 자산을 복원했으며 `apps/mobile-web/dist/index.html`과 iOS `public/index.html`의 SHA-256은 둘 다 `6413f99ae2ccdc9b5ac0f58e32f4fb5c8c450e6264ba30dbd2765aab2d3c7a43`이다. 서명된 iPhone의 인증 작업 취소나 실제 서버 경합 검증은 **not_executed**다.

세 번째 Codex CLI `gpt-6-sol` high/read-only 검토는 main `8bd3814259922478e7b4a05111966b6621a14e05` → phase `690a607630660f60501399b593ec9587ae57756a`의 전체 67파일 diff를 **APPROVE**했다. 첫 인증 취소 P2와 두 번째 WK 메시지 가드 P2를 모두 현재 코드와 시험 근거로 **FIXED** 판정했고 새 실행 가능한 지적은 없었다. 검토자는 해시·청결 상태·전체 diff·`git diff --check`를 확인했으나 무거운 시험과 서명된 iPhone/운영 HTTPS/실제 인증 경합을 독립 재실행하지 않았다. 이 판정 기록의 추가분은 별도 읽기 전용 refresh 검토 대상으로 남긴다.
