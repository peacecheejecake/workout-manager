# M1-04g · 수동 활동·보고 계약/API

상태: 완료. S08·V2-A31의 수동 actual과 자기보고 계약/API를 구현했다. 입력·정정 UI는 후속 task다.

## 범위와 의미

- `POST /activities`는 `confirmed: true`인 명령에서 서버 ID·manual 출처와 원본을 생성한다.
  FIT/fixture 가져오기에서 manual 출처 위조를 거부한다. 동일 명령은 생성 결과를 재사용하며,
  삭제 후 재시도는 기존 ID만 반환하고 활동을 복원하지 않는다. 생성 영수증에는 건강 본문을 넣지 않는다.
- RPE 0~10/null·메모·계획 버전/세션 연결을 사용자 자기보고로 저장한다. RPE 미보고와 0은 다르다.
  보고 시각·출처·방법은 서버가 기록한다. RPE가 같고 메모만 변경되면 기존 보고 시각을 유지한다.
  보고 전체를 명시적으로 교체하며 원본·과거 보고/정정 이력을 덮어쓰지 않는다.
- 계획 연결은 해당 사용자 소유의 실제 snapshot와 session만 허용한다. 소유한 과거 버전도 허용한다.
  연결은 계획을 수정하거나 계획된 수행을 실제 기록으로 자동 확정하지 않는다.
- 정정은 제목/종목/시각·시간대/거리/시간·정의/보고를 revision·사유·멱등 키로 보호한다.
  수정된 종목·시각은 목록 필터/정렬과 대시보드 집계에 반영한다. 시각 null은 기간에 임의 배정하지 않는다.
  미래 시각은 서버 현재 시각의 5분 초과를 거부한다. year 0000과 잘못된 계획 UUID도 거부한다.
- 마이그레이션 008은 manual 출처와 4000자 메모를 위한 JSON byte 한도를 확장한다.
  기존 활동 JSON·정정 영수증의 자기보고 필드 생략과 기존 dashboard의 manual count 생략을 허용한다.
  생략한 보고를 RPE 0으로 바꾸지 않는다. export v2의 기존 overlay/history에 보존하므로 collection은 늘리지 않는다.
- 초기 수동 보고는 정정 건수에 포함하지 않는다. 이후 정정한 기록만 dashboard의 사용자 정정 수에 포함한다.
  수동 기록은 목록/상세 및 dashboard 출처에 별도로 표시한다.
- 로컬 삭제는 조회·집계에서 숨기며 suppression·원본/이력을 유지한다. 계정 전체 삭제는 관련 건강 본문과
  영수증을 제거한다. 복원 시 최신 삭제 원장을 먼저 재적용한다.
