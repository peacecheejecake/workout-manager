# M2-04b · 객체 저장 port와 파일 upload

상태: **완료 (M2-04/FUT-06은 미완료)**. Private PDF와 Markdown 원본의 bounded upload,
인증 download, 불변 file version, soft-delete/account-erasure raw object 정리를 web과 mobile-web에
연결했다. URL 수집·parser·본문/page locator·검색/RAG·공유·reviewed 전환·코치 사용은 M2-04c/d
이후 범위이며 구현하지 않았다. 파일 lifecycle은 `raw_stored/not_indexed`, `includeForCoach=false`,
`reviewedState=unreviewed`으로 유지한다.

`@workout/server-media`는 provider-neutral object storage port, tenant/resource/upload-scoped
content-addressed key,
streaming SHA-256·크기·형식 검증과 private local filesystem adapter를 제공한다. PDF는 10 MiB와
`%PDF-` signature, Markdown은 1 MiB와 strict UTF-8/제어문자 제한을 적용한다. 임시 object를 같은
filesystem에서 no-overwrite hard-link로 publish한다. 같은 upload retry만 동일 key를 재사용하고,
별도 intent는 byte hash가 같아도 고유 key를 가져 cleanup 경쟁을 차단한다. 다른 content 충돌,
absolute non-root, traversal, symlink, cross-tenant/cross-upload key를 거절한다.

Migration 028은 text/file XOR, immutable object metadata, upload intent, file quota, FORCE RLS,
function-only cleanup queue를 추가한다. API는 intent → temporary stream 검증 → DB `prepared` 기록 →
atomic publish → `staged` → finalize를 사용하며 object I/O를 DB transaction 밖에서 수행한다. object를
만들기 전에 deterministic temporary key를, publish 전에 final key와 descriptor를 영속화하므로 중단된
쓰기도 30분 만료 뒤 exact-key cleanup 대상으로 남는다. tenant별 active intent 20개와 prepared/staged
50 MiB를 제한한다. active+failed intent는 tenant당 100개로 제한하고, cleanup이 끝난 failed intent는
7일, 완료 cleanup 운영 기록은 30일 보존 뒤 worker가 각각 최대 100건씩 정리한다. finalized receipt는
보존한다. finalize는 CAS·tenant quota·receipt·outbox와 file version/head를 한 transaction에 기록한다.
public DTO와 export v13은 안전한 filename/MIME/byte size/SHA-256만 포함하고 storage ref를 제외하며
v1~v12 artifact 읽기를 보존한다.

삭제는 reader와 download를 DB tombstone으로 즉시 막고 모든 raw object를 durable queue에 넣는다.
계정 말소 뒤에도 queue는 남는다. 전용 최소 권한 worker는 먼저 만료 intent를 bounded batch로 queue에
넣고 opaque key 한 건을 lease한다. DB가 live version·active intent 부재를 다시 authorize한 key만
검증·삭제하고 성공 또는 bounded retry를 기록한다. SECURITY DEFINER 함수는 worker가 제공한 절대 시각을
신뢰하지 않고 DB 시각으로 expiry·lease·authorization·finish를 판정한다. prepare/finalize와 delete
authorization은 DB fence로 경합하며, upload별 고유 final key는 한 intent의 보상 정리가 다른 version
원본을 지우지 못하게 한다. 100회 삭제 실패는 성공으로 기록하지 않은 dead-letter 운영 개입 상태로
격리해 뒤 queue가 계속 진행되게 한다.

두 shell 화면은 PDF/Markdown 생성·새 버전, 진행/오류/재시도, descriptor, 인증 download, 삭제를
제공한다. `prepared`를 정상 중간 상태로 처리하고 `UPLOAD_RESUME_REQUIRED`는 같은 intent로,
`UPLOAD_RETRY_REQUIRED`와 terminal failed replay는 새 idempotency key로 다시 예약한다. File은 local
React state에만 두고 Query cache나 persisted state에 복제하지 않는다.
업로드 완료는 “원본 파일 저장됨 · 본문 파싱 안 됨 · 검색 색인 안 됨”으로 표시한다.

검증: `pnpm check`의 generated/format/lint와 26개 package typecheck가 통과했다. sandbox local-port
제한으로 처음 전체 Vitest의 OIDC/Garmin 9건만 EPERM이었고, loopback 허용 재실행에서 201 files /
2,103 tests가 통과했다. 격리 PostgreSQL은 37 files / 306 tests, production build는 10 tasks가
통과했다. worker는 3 files / 24 tests, M2-04b 표적 API/UI/platform/media는 5 files / 123 tests가
통과했다. 실제 OIDC·same-origin BFF·격리 PostgreSQL·Chromium E2E 2건은 text 회귀와 Markdown
create/upload/download/version/tenant isolation/delete, 320px reflow를 확인했다. 합성 PostgreSQL +
private object archive backup/restore drill은 36 checks를 통과했다.

UI 검증에서 Aside daemon은 auth challenge `fetch failed`로 사용할 수 없었고 computer-use 상태에는
Chrome browser surface가 없었다. 따라서 repository 지침의 fallback인 Playwright Chromium을 사용했다.
Native HealthKit/WKWebView와 원격 object provider는 이 검증 범위가 아니다.
