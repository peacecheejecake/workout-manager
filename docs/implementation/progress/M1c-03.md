# M1c-03 · 회복 전략 수동 core

상태: **완료 (수동 core 및 운영 권한 코드)**. S35에서 개인 회복 방법, 기간과 목표를 가진
전략 초안, 명시적 선택, 다음 확인 조건, 비운동 행동 실제를 분리했다. `full_rest`는
다른 행동을 추가하지 않는 정식 선택지이며 선택만으로 휴식 수행·수면 시간이나
회복 효과를 생성하지 않는다. 수동 방법은 미검토로 표시하고 치료·효능·기기
제어를 제안하지 않는다. 행동은 Activity·IntakeEntry와 다른 원장에 저장하며
확인한 값·미확인·중단·불편감과 개정을 구분한다.

기존 체크인·활동·섭취 관측과 훈련·영양 계획은 원본 ID와 revision/head를
참조한다. 변경·삭제된 참조는 재검토 대상으로 표시하지만, 이 task는 알림
전달이나 계획 자동 변경·네 도메인 원자 승인을 수행하지 않는다. 현재 S35 UI는
새 전략에서 기존 관측·계획을 탐색해 연결하는 선택기를 제공하지 않는다.
참조 계약과 API 검증은 구현했으며 이 UI 연결과 자료/RAG·코칭은 후속 작업이다.
웹·mobile-web에서 같은 회복 원장을 표시하고, 확인된 행동의 정정·삭제를
지원한다.

025 migration은 방법/전략 불변 버전, 행동 개정과 현재 head, FORCE RLS,
계정 말소 연동을 제공한다. 기존 `erase_account(text)`를 감싼 새 함수의
EXECUTE 권한은 migration 뒤 `grantOperations` 재실행이 필요하다. 최초 구현 때
보류했던 운영용 `grantRecoveryCore`는 2026-09-19 사용자 승인 후 추가했다.
필요한 최소 권한은 `recovery_method_version`, `recovery_strategy_version`,
`recovery_action_revision`의 SELECT·INSERT와 `recovery_method_head`,
`recovery_strategy_head`, `recovery_action_log`의 SELECT·INSERT·UPDATE다.
DELETE 권한은 요청하지 않는다. 임시 E2E fixture도 동일한 helper를 사용한다.
실제 운영 DB 적용은 별도 배포다.

검증: 전체 `pnpm check`의 포맷·lint·24개 패키지 타입 검사와 191개 파일/1,966개
단위 테스트, 격리 PostgreSQL 33개 파일/273개 테스트, 전체 production build가
통과했다. 실제 OIDC·임시 PostgreSQL·Chromium E2E에서 방법 저장, 휴식안 선택과
행동 원장 분리, 정정·삭제, 웹→mobile-web 이동과 320px 표시를 확인했다.
Aside CLI 업데이트 확인은 `fetch failed`였고 Chrome용 Orca 데스크톱 런타임은
실행 시간 초과로 접근할 수 없어 Playwright Chromium을 사용했다. 실기기,
실제 Garmin, 알림 전달, 임상·효능 검증은 수행하지 않았다.

Herdr split-pane 독립 리뷰는 기준 HEAD
`dea3b6b903d0db3cc4aa893af04806e9d1108313`와 최초 staged diff SHA-256
`142a2a5e81f89aba45d386e2fcf150a1f56338cb05f110e8664d8c0bd58a10d6`에서
삭제 후 과거 receipt 반환, 응답 유실 뒤 새 키로 중복 생성, 재조회/새 revision에
따른 편집 초안 소실, 정정 시 시각·timezone 변경 P2 네 건을 발견했다. 삭제 후
과거 active 결과 반환을 막고, 방법·전략·행동 생성/정정의 불확실한 명령을 같은
본문과 키로 재전송하도록 고쳤다. 재조회 실패·동시 개정 때 편집 baseline과
초안을 유지하며, 메모만 정정하면 원래 시각·timezone을 보존한다. DB·UI
회귀를 추가하고 전체 검사·빌드·OIDC/Chromium E2E를 재실행했다. 진행 기록과
task graph를 제외한 staged code diff SHA-256은
`f5fac2e61c31619ebad1c1e67f626477009a5134658a68771792f5049612b17d`이다.
최종 Herdr 독립 재검토에서 P2 네 건의 수정과 회귀 검사를 확인했고, 추가
actionable finding은 없었다. 문서·task graph 상태와 staged code diff 해시도
일치했다.

2026-09-19 운영 권한 후속 검증: nonowner 역할의 회복 테이블 SELECT·INSERT,
현재 head/log의 UPDATE, DELETE 부재와 FORCE RLS를 격리 PostgreSQL에서
확인했다. 다른 계정의 기록을 읽거나 쓰지 못하고 최신 계정 말소 wrapper로
회복 기록이 삭제되는 것도 확인했다. 전체 `pnpm check` 191개 파일/1,978개
테스트, 실DB 34개 파일/276개 테스트, 전체 build와 OIDC·Chromium
루틴/스트레칭/회복 E2E 3개가 통과했다.
