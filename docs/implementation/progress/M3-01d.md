# M3-01d · iOS 시스템 로그인·Keychain 세션 경계

상태: **completed** (한정된 구현·로컬 수용 범위). 기준 `phase/m3-01` `1f1ad49`. 선행 M3-01c의 native 전용 서버 교환 경계를 제품 iOS host에 연결했다. Phase 독립 검토와 main 병합은 아직 수행하지 않았다.

고정 HTTPS API·IdP origin을 앱 빌드에 명시하고 Keychain 접근이 가능할 때만 `auth.transport`를 제공한다. 기본 설정은 비어 있으며 기능을 닫는다. iOS에서 PKCE verifier를 생성하고 `ASWebAuthenticationSession`으로 IdP를 열어 고정 callback의 일회성 code를 교환한다. 받은 bearer는 API origin과 함께 `WhenUnlockedThisDeviceOnly` Keychain에 보관하며, 앱의 API origin이 바뀌면 오래된 로컬 credential을 삭제한다. 네트워크 요청은 ephemeral session, cookie/cache/redirect 거부, 16 KiB 응답 상한을 사용한다. Bridge의 `auth.signIn`·`auth.session`·`auth.signOut`은 로그인 상태·계정 ID·만료 시각만 WebView로 보낸다. 로그아웃은 서버의 204 철회 또는 이미 무효한 bearer의 401을 확인한 뒤 로컬 credential을 삭제한다. 서버 교환 후 Keychain 저장이 실패하면 bearer 철회를 시도하고 실패 상태를 돌려준다.

## 남은 범위

- 서명된 제품 앱의 Keychain 읽기·쓰기·삭제, 실제 iPhone의 시스템 로그인·취소·만료·로그아웃, 운영 HTTPS API/IdP redirect 및 callback은 **not_executed**. 공개 HTTPS origin과 공급자 설정은 `EXT-HOSTING`에서 다룬다.
- 현재 `auth.session`은 Keychain의 로컬 만료만 확인한다. 원격 back-channel 철회 뒤 표시 상태 재확인과 401 처리·계정 scope 무효화는 후속 native API transport에서 구현한다. 서버는 철회된 bearer로 제품 API 접근을 거부한다.
- API origin을 바꾼 앱 빌드는 이전 origin의 bearer를 로컬에서 삭제하고 재사용하지 않는다. 이전 서버에 닿지 않는 전환에서는 그 서버의 세션이 기존 만료 시각(최대 8시간)까지 남을 수 있으므로 운영 배포 전환 시 서버 철회가 필요하다.
- 제품 API 업무 전송, 전체 M2 모듈 조합, HealthKit collector, 제품 host Back/IME/foreground 수용은 이 노드의 완료 증거가 아니다. M3-01 후속 및 M3-02/03에서 추적한다.
