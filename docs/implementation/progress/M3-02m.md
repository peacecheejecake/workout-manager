# M3-02m · 서버 등록 UUID에 제한한 native 수집

상태: **구현·로컬 합성 검증 완료**. M3-02l의 실제 등록 목록과 v2 batch 계약을 native collector에 연결했다. 운동 후보 선택·등록 UI/bridge는 M3-02n, 역사 자료·해제 수명주기 감사는 M3-02o, 제품 실기기 수용은 M3-02h의 별도 조건이다.

## 경계

- NativeAuth의 고정 bearer GET `/bff/v1/healthkit/workout-registrations`만 사용한다. limit 100, 최대 100페이지·10,000 UUID·페이지 32 KiB, 정확한 DTO keys, 동일 registry revision, 중복 UUID/cursor 및 비정상 continuation을 검증한다. 마지막 페이지와 최종 동의 revision·현재 credential/session/owner 검증 전에는 snapshot을 반환하지 않는다. URL·token·UUID·claim epoch는 WebView에 전달하지 않는다.
- 계정별 SQLite에 등록 UUID/claim epoch·registry revision과 UUID/epoch chunk별 anchor를 보관한다. 디스크에 저장된 snapshot은 재실행·계정 전환 뒤 fresh 증거가 아니다. 전체 목록의 오류·offline·partial은 기존 snapshot/outbox를 보존하고 query·upload를 차단한다. 낮아진 revision·동일 revision의 다른 membership을 원자적으로 거절한다.
- observer와 anchored query는 최대 100 UUID의 명시 predicate를 사용한다. 등록이 0개이면 query를 만들지 않으며 범위 없는 fallback은 없다. callback/page/ACK는 캡처한 owner/generation fence를 통과해야 한다. 반환된 sample·deleted UUID도 해당 chunk에 포함되는지 검사한다.
- stage는 현재 등록 claim epoch를 넣은 immutable v2 batch와 scoped anchor를 하나의 transaction으로 저장한다. upload는 완전하게 검증된 현재 목록의 UUID/epoch가 모두 일치하는 batch에 한한다. v2 ACK의 schema·installation·batch·count를 검증한다. 등록 관련 409는 큐를 보류하며 동의 만료로 오인해 지우지 않는다.
- membership/epoch 변경은 anchor와 known mapping을 초기화하고 기존 pending body를 재작성하지 않는다. 한 pass는 최대 20페이지이며 chunk를 순환한다. consent 변경은 기존 정책대로 오래된 로컬 epoch 자료를 정리하고 installation을 회전한다. historical v1은 첫 consent migration에도 receipt scope·body를 보존하고 업로드를 보류한다.

## 실제 검증 (2026-10-05)

세 합성 harness는 macOS에서 실제 Swift 실행 파일로 빌드·실행했다. 임시 SQLite fixture만 사용했고 defer로 자기 fixture 디렉터리를 정리했다.

| 검증                                   | 결과                                                                                                                                                                                                                  |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HealthKitWorkoutStateHarness           | **68 단언 통과**: 원자 stage/anchor, ACK·corruption·outbox cap, owner partition, offline/restart/reinstall, consent rotation, explicit deletion, epoch 재등록, legacy singleton/control/v1 보존, stale callback fence |
| HealthKitRegisteredWorkoutPagesHarness | **117 단언 통과**: terminal만 반환, mixed revision, duplicate UUID/cursor, truncated/error reply, 페이지/바이트/continuation 상한                                                                                     |
| HealthKitWorkoutUploaderHarness        | **33 단언 통과**: v2·epoch·duplicate 검증, v1 body/ACK 거절, private registry 409 큐 보존, 동의 오류·재시도·revision 최대/초과/누락/잘못된 숫자                                                                       |
| 기존 HealthKitWorkoutDebugProbeHarness | **통과**: 기존 scope/ownership/denied-read retry 합성 회귀; HealthKit I/O 실행 아님                                                                                                                                   |

| 변경 diff                              | `git diff --check` 통과                                                                                                                                                                                               |

명령은 저장소 루트에서 실행한다. 생성 실행 파일·로그·cache는 `/private/tmp`에만 두고 커밋하지 않는다.

```sh
xcrun swiftc -module-cache-path /private/tmp/wm-m3m-swift-cache \
  apps/mobile/ios/App/App/HealthKitWorkoutState.swift \
  apps/mobile/ios/App/App/HealthKitWorkoutUploader.swift \
  apps/mobile/ios/tests/HealthKitWorkoutStateHarness.swift -o /private/tmp/wm-m3m-state
/private/tmp/wm-m3m-state
# 같은 두 producer와 Pages/Uploader harness를 각각 빌드·실행
xcrun swiftc -typecheck -target arm64-apple-ios17.0 \
  -sdk "$(xcrun --sdk iphoneos --show-sdk-path)" \
  -module-cache-path /private/tmp/wm-m3m-swift-cache \
  apps/mobile/ios/App/App/HealthKitWorkoutState.swift \
  apps/mobile/ios/App/App/HealthKitWorkoutUploader.swift \
  apps/mobile/ios/App/App/NativeAuth.swift \
  apps/mobile/ios/App/App/HealthKitWorkoutCollector.swift
# 같은 네 파일에 -emit-library -o /private/tmp/wm-m3m-native-final.dylib로 compile/link
```

최종 로그: `/private/tmp/wm-m3m-state-final.log`, `wm-m3m-pages-final.log`, `wm-m3m-uploader-final.log`, `wm-m3m-typecheck-final.log`, `wm-m3m-compile-final.log`, `wm-m3m-debug-probe.log`.

### 실패·경고 보존

- 최초 state/producer typecheck는 nested encoder에서 MainActor static helper를 호출해 실패했다. UUID 문자열 변환을 nonisolated encoder 내부에서 직접 수행한 뒤 재검증했다.
- fence 교체 중 authorization continuation의 옛 변수 이름이 남아 typecheck가 실패했다. 공통 fence 호출로 수정 후 최종 네 consumer 검증이 통과했다.
- 확대 state harness 초기 실행은 consent를 다른 SQLite 인스턴스에서 회전한 뒤 옛 테스트 owner를 다시 읽어 `corruptState`로 실패했다. callback fixture를 해당 시험의 안정된 인스턴스로 수정하고 최종 전체 harness를 재실행했다. 로그 `wm-m3m-state-r2.log`, `wm-m3m-state-r3.log`, `wm-m3m-state-diagnostic.log`에 보존한다.
- 전체 Xcode unsigned project build 첫 시도는 SwiftPM/module cache의 sandbox 쓰기 거절로 dependency resolution 단계에서 실패했다(`wm-m3m-build.log`). 전체 앱 build 통과로 보고하지 않는다. 별도 SDK 소비자 compile/link는 성공했으나 clang의 macOS sysroot/iOS target 경고가 남았다. 기존 debug probe에는 HKWorkout 생성자 deprecation 경고가 남았다.

## 남은 수용

HTTPS 등록/list/수신 전체 경로, 실제 OS observer/background delivery/anchored delete, 개인 HealthKit, iPhone collector install/launch/read 및 서명 앱 수용은 **not_executed**다. Swift compile·합성 fixture를 실기기 통과로 사용하지 않는다. 기존 v1 또는 새 목록에서 해제된 epoch의 pending batch는 보류되며 자동 변환·재귀속하지 않는다. 선택·해제 상태 표시와 처리 정책은 n/o에서 연결해야 한다. 이번 변경은 API/worker/migration/TS 계약·graph·auth 정책·제품 UI를 수정하지 않는다.

## 승인된 upload 상한 보정

루트의 좁은 추가 승인을 받아 기존 upload 가드 **한 줄**을 Uploader의 공통 `acceptsConsentRevision` 검증으로 연결했다. 기존 0 하한을 유지하고 현재 계약의 최대 2,147,483,647을 허용한다. 같은 실제 가드를 harness가 직접 실행해 최대값 허용·초과값 거절, nil/NSNull/Boolean/string/음수/소수/NaN/infinity 거절과 누락 body schema의 default 부재를 확인했다. Uploader 최종 **33 단언**, 세 harness 합계 **218 단언**이 통과했다. NativeAuth의 다른 endpoint/auth 정책은 변경하지 않았다. 네 consumer arm64 SDK typecheck·unsigned compile/link를 이 소스에서 다시 실행했다. shared TS 계약은 변경하지 않아 추가 TS 소비자 검사 대상이 없다. 이 순수 가드/컴파일 결과는 실제 네트워크 업로드 성공을 뜻하지 않는다.

## 루트 결합 확인

루트는 네 producer의 등록 snapshot·epoch·동의 revision·계정 generation fence, 제한 UUID query, terminal pagination, immutable pending/anchor transaction과 세 harness의 소스·실제 실행 로그를 대조했다. 포맷 후에도 세 harness **218 단언**을 재컴파일·실행했고 네 arm64 소비자 typecheck·unsigned compile/link가 종료 코드 0이었다. NativeAuth는 새 고정 목록 메서드와 upload 가드 한 줄 외에 원래 HEAD와 byte-identical임을 확인했다. 로그는 `/private/tmp/wm-m3m-{state,pages,uploader,typecheck,compile}-format.log`와 `wm-m3m-{typecheck,compile}-authscope.log`다. 기존 clang sysroot 경고와 전체 Xcode build 실패는 보존한다.

이 결과로 M3-02m의 로컬 구현 수용만 완료했다. M3-02n 선택 UI·bridge와 M3-02o 통합·자료 감사는 다음 노드이며 운영·개인 HealthKit·기기 검증은 여전히 not_executed다. phase 독립 검토 전 main에 병합하지 않는다.

## 독립 phase P1 후속 수정 · 2026-10-06

위 초기 pending 보류 정책의 한계가 전체 phase 검토에서 P1로 확인됐다. 해제된 X의 미ACK 배치가 다른 Y의 동기화를 계속 막는 경로를 수정했다. 인증된 완전한 동일 계정/동의 registry snapshot transaction에서 stale UUID/epoch event를 정리하고 mixed의 유효 tombstone은 새 key로 원래 sequence에 보존한다. 유효 original retry·영구 거절·unknown v1 quarantine은 유지하며 oldevent를 새epoch로 재귀속하지 않는다. State92/root독립실행, 관련 harness 합계438와 iOS15 Release/DEBUG unsigned compile을 확인했다. 상세 finding·실패/포맷 한계·독립 재검토는 [phase 기록](M3-02-phase-review-20261006.md)을 따른다. 실기기/운영 미실행은 유지한다.
