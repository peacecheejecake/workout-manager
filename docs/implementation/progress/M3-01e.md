# M3-01e · Native 인증 API Host 전송·철회 상태 반영

상태: **완료(로컬 수용 범위)**. 기준 `phase/m3-01` `8ca6c3f`. M3-01d의 Keychain 세션 경계 위에 고정된 두 읽기 경로를 연결한다. Phase 독립 검토와 main 병합은 후속이다.

## 수용 범위

- native URLSession이 Keychain bearer를 사용해 `GET /bff/v1/session`과 `GET /bff/v1/consents/ai`만 고정 HTTPS API origin으로 보낸다. URL·method·body는 bridge에서 임의 확장할 수 없다. JavaScript에는 bearer, verifier, credential 저장소 정보가 전달되지 않는다.
- 서버의 401은 native credential과 WebView의 계정 scope를 무효화한다. 첫 화면에서 실제 AI 동의 읽기를 표시하되 데이터 공백·오류·오프라인을 동의 거부로 가장하지 않는다.
- 코드·계약·서버 소유권 fixture·모의 브라우저·시뮬레이터 결과와 운영 HTTPS·실기기 결과를 따로 기록한다. 공개 origin이 없는 현재 운영 실연결은 **not_executed**다.

## 구현과 경계

- Swift `NativeAuth`는 빌드에 설정된 HTTPS API origin에만 Keychain bearer를 붙여 두 GET을 수행한다. 요청은 쿠키·캐시·리다이렉트를 차단하고 16 KiB로 제한하며, 200 본문의 필드·타입과 계정 일치를 검증한다. 401 또는 만료된 credential은 Keychain에서 제거한다. `auth.session`도 서버의 `/session`을 다시 읽으므로 로컬 만료 시각만으로 원격 세션 유효성을 주장하지 않는다.
- v2 bridge의 `api.read`는 두 경로만 허용하고 method/body/URL을 JavaScript에서 지정할 수 없다. 응답은 상태·제한된 본문만 전달하며 bearer·PKCE·저장소 정보는 전달하지 않는다. 웹 `AuthenticatedTransport`도 두 GET, `body: null`, `idempotencyKey: null`만 받는다.
- native 첫 화면은 서버의 AI 동의 응답을 표시한다. 로딩, 명시적 비동의, 전송 오류, 401 철회를 구분한다. 401과 명시적 로그아웃은 WebView 개인 저장소 및 계정 화면 상태를 비운다. 비동기 응답은 로그아웃·계정 변경 시 abort하여 오래된 동의 표시를 막는다.

## 미실행 및 후속

- 서명된 iOS 앱의 Keychain 성공 경로, 실제 iPhone의 WebView·인증·백그라운드 동작, 운영 HTTPS API/IdP의 정상 로그인과 철회 전파는 **not_executed**다. unsigned simulator의 Keychain 접근은 `-34018`로 거부되어 성공 경로로 기록하지 않는다.
- 제품의 나머지 업무 API 쓰기·파일·지도 전송은 이 노드의 두 읽기 경로 밖이다. M3-01의 후속 shell 작업과 M3-03 최종 통합에서 다룬다. Phase 단위 독립 검토 전에는 `main`에 병합하지 않는다.
