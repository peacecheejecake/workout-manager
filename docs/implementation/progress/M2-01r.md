## 1. `/courses/new`·`/courses/:id/edit` (S14-address)

요구 원문(`01_product_screen_spec.md:52`)은 "S14 경로 편집 `/courses/new`, `/:id/edit` | 지도
waypoint·보행 경로·고도·저장"이다. 행이 빠진 이유는 두 가지였다. 라우트가 없었다. 그리고
**빈 지도에서 코스를 시작할 방법 자체가 없었다.** 코스 생성은 기록 구간, 복사, GPX 가져오기
세 가지뿐이었다. 경로 제안(`course_route_proposal`)은 **코스에 속하는 행**이라 코스가 없는 초안에는
쓸 수 없다.

**설계 판단: 미리보기는 아무것도 저장하지 않고, 저장이 다시 계산한다.**

- `POST /bff/v1/courses/route-previews`(엔진이 구성된 경우에만 등록)는 기존 제안 경로와 같은
  bounded port를 쓴다. tenant rate·동시성·경유점·거리·deadline 한도가 같고, 연결이 끊기면
  취소된다. 결과는 **저장하지 않는다.** 서버가 계산한 선의 SHA-256(`geometrySha256`)을 함께 돌려준다.
- `POST /bff/v1/courses`에 `from.kind = 'routed-waypoints'`를 추가했다. 요청에는 경유점,
  `draftRevision`, `reviewedGeometrySha256`, `acknowledgedGraph {previous: null, next}`만 있다.
  geometry는 없다. 서버는 **엔진에 다시 묻는다.** 그 답의 graph가 `next`와 다르면
  `409 COURSE_GRAPH_ACKNOWLEDGEMENT_STALE`, 선의 digest가 검토한 digest와 다르면
  `409 ROUTE_PREVIEW_CHANGED`로 거절하고 아무것도 쓰지 않는다. 재계산이 실패하면
  `ROUTE_PREVIEW_NOT_REPRODUCED`로 거절한다. 확정적 거절(no_route 등)은 409, 엔진 상태(429/502/504)는
  그대로 둔다. 같으면 **서버 자신의 답**을 lineage 없이(`[]`, edit `created`) 쓴다.
- 새 초안의 경유점은 `sourceSampleId`를 가질 수 없다(`courseNewWaypointListSchema`, 400).
- 대안으로 제안 표의 `course_id`를 nullable로 바꾸는 방법도 있었다. 그러려면 supersession(041),
  reaper, consume 함수, 재수집(reclaim) trigger, `erase_account` 경로까지 코스 없는 행을 다뤄야 한다.
  코스에 매달리지 않은 private 좌표 행을 새로 만드는 일이기도 하다. **저장하지 않는 쪽**을 골랐다.
  비용은 엔진 호출 두 번이다. 두 번 모두 tenant 한도에 들어간다. "검토한 것이 저장된 것"은 digest
  비교로 지킨다. 엔진은 같은 graph에서 결정적이다(fixture도 그렇다).

**화면.** 새 화면 로직을 복제하지 않고 기존 부품을 조합했다.

- `course-waypoint-list.tsx`: 경유점 목록 편집기(선택·순서·잠금·이동·삭제·좌표 입력·undo/redo·
  초안 상태)를 `CourseEditor`에서 **꺼내** 두 화면이 함께 쓴다.
- `RouteReviewSummary`: 검토 요약을 `course-editor.tsx`에서 꺼냈다.
- `course-new.tsx`의 `NewCourseWorkbench`: 같은 `CourseMapPane`(export만 추가), 같은
  `CoursePlaceSearch`, 공유 목록, 미리보기·검토·저장으로 조합했다. 첫 두 점은 놓은 순서대로
  시작·끝이 된다(`addVia`가 2개 미만이면 뒤에 붙인다). 새 초안의 점은 모두 지울 수 있다.
  저장한 코스는 여전히 두 끝을 지킨다. 화면 전체가 `athleteId:sessionId`로 key되어 로그아웃이나 계정
  전환 뒤 이전 소유자의 점이 남지 않는다. 늦게 도착한 저장 응답은 세션이 사라졌으면 이동하지 않는다.

## 2. S13 접근성 메모 — 저장하는 데이터다

원문(`01_product_screen_spec.md:161`): "S13 코스 카드에 지도 썸네일, … **접근성 메모**, 마지막 사용을
표시한다." 계획 5절 108행도 M2-01j S13 수용에 "접근성 메모"를 포함한다. 메모는 **소유자가 적는
글**(계단·경사·야간 폐쇄)이다. 다시 만들 수 없으므로 저장한다. 표시만 하는 파생 정보가 아니다.

- **course content가 아니다.** 쓰면 수정본이 생기지 않는다. head, content digest, GPX export에
  영향이 없다. 그래서 revision이 아니라 자기 표 `course_accessibility_note`에 둔다.
- **쓴 수정 번호를 함께 저장한다**(`written_at_revision`). 요청은 화면이 보던 head를
  `expectedRevision`으로 보낸다. 서버는 tenant 명령 잠금(`hashtextextended(id,0)`) 아래에서 head와
  비교하고, 다르면 409다. 경로가 바뀐 뒤(reroute·trim) 카드와 상세는 "수정 번호 N에서 적음 · 이후
  코스가 바뀜"을 보인다. 옛 선에 대한 "계단 없음"이 새 선의 설명처럼 읽히지 않게 하려는 것이다.
- 한 줄 256자, course 이름과 같은 텍스트 규칙(제어·양방향 override·꺾쇠 거절, 앞뒤 공백 거절)이다.
  DB CHECK도 길이와 trim을 강제한다.
- 화면은 "본인이 적은 내용이며 이 서비스가 확인한 사실이 아닙니다"라고 말한다. "메모 없음"과
  "메모를 불러오지 못했습니다"를 구별한다.

**계약·영속·migration**

- 계약: `courseAccessibilityNote{,List,Write,WriteResult}Schema`.
- API: `GET /bff/v1/courses/accessibility-notes`와 `PUT /bff/v1/courses/:courseId/accessibility-note`
  (`note: null`이면 지운다). 남의 코스는 404, 재수집된 코스는 410, head 불일치는 409다.
- migration `043_course_accessibility_notes.sql`(버전은 목록 위치다. 병합 때 M2-01s의 042 뒤, version 43에 놓였다). 새 표 하나,
  `ENABLE`+`FORCE ROW LEVEL SECURITY`, tenant policy, `(athlete_id,course_id) → course ON DELETE CASCADE`.
  **기존 함수는 하나도 재정의하지 않았다.** `erase_account`도 감싸지 않았다. 계정 삭제는
  migration 034의 `DELETE FROM course`가 cascade로 메모까지 지운다. 잠금 순서(77206 → 0 → 행)는
  바뀌지 않았다.
- grant: runtime 역할은 `SELECT,INSERT,DELETE`와 `UPDATE(note,written_at_revision,updated_at)`만
  갖는다. 메모를 다른 코스·다른 소유자에게 옮길 수 없다. export는 `SELECT`다.
- 수명: 코스 삭제는 cascade로 지운다. 계정 삭제도 cascade다. 원본 활동 삭제로 **재수집**된 코스는
  이름처럼 메모도 남긴다. 둘 다 소유자의 말이고 기록 좌표가 아니다. 새로 쓰기는 거절하고(410)
  **지우기는 허용**한다. 소유자의 글을 거두는 데는 head가 필요 없다.
- export **v22**: `courseAccessibilityNotes`(course_id, note, written_at_revision, created_at,
  updated_at)를 추가했다. v2–v21은 그대로 읽는다. v21 artifact에 v22 collection이 붙어 있거나 v22가
  v21을 사칭하면 거절한다(계약 시험). 노드 코드의 v21 고정값은 모두 v22로 올렸다.
- backup drill: 메모를 심고 복원 뒤 같은 글과 같은 수정 번호가 있는지, export v22에 있는지 확인하는
  검사 2개를 추가했다(62 → 64).

## 3. "미계산 초안" (S14-uncomputed-draft, S14-no-confirmation)

원문(`:165`): "경로 계산 불가 상태에서 직선 연결은 **미계산 초안**으로 표시한다. 이를 보행 가능한
코스나 실제 거리로 확정하지 않는다." 계획 5절은 "미계산·계산 중·stale"의 구별을 요구한다.

전에는 경유점을 점으로만 그렸다. 직선이 없으니 "확정하지 않는다"는 공허하게 참이었다.

- `draftRouteStatus`는 여섯 상태를 구별한다. `stored`(저장된 경유점과 같음), `incomplete`(새 초안 점
  2개 미만), `uncomputed`, `stale`(계산 결과가 이전 초안의 것), `computing`, `computed`. 되돌려 저장본과
  같아지면 `stored`로 돌아간다.
- 지도: `uncomputed`·`stale`일 때만 경유점을 순서대로 잇는 직선을 geo-kit의 **새 role
  `uncomputed`**로 그린다. 전용 layer에서 회색 2px **점선**이다. 경로 layer의 filter는 이 role을
  제외한다. 이 선은 측정하지 않고, 저장 버튼도 나타나지 않는다.
- 말과 스크린리더: 목록 위의 `role="status"` 문단이 "**미계산 초안** · … 지도의 회색 점선은 경유점을
  순서대로 이은 직선일 뿐이며, 걸을 수 있는 경로도 실제 거리도 아닙니다."라고 말한다. 경유점 목록은
  `aria-describedby`로 이 문단을 가리키므로 목록과 함께 읽힌다. 숫자 거리는 넣지 않았다.
- 편집기에 있던 별도 stale 문단은 이 상태 문단에 합쳤다. live region이 둘이면 두 번 읽히기 때문이다.
- M2-01q와 겹치는 변경은 geo-kit `map-path.ts`(role 1개), `maplibre-adapter.ts`(layer 1개, filter
  1개), `course-workbench.tsx`의 `CourseMapPane` 두 줄(공유 선택 hook)이다. 모두 국소 변경이다.

점선 직선**과 점이 보이고, 계산 뒤에는 점선이 사라지고 제안 선(실선)만 남는다. 첫 캡처에서 결함 하나를

새 초안 지도는 이제 점 수가 바뀔 때마다 다시 맞춘다(수정 뒤 5). Aside·Chrome은 쓰지 않았다. harness
서버가 Playwright 실행 동안만 살아 있기 때문이다.

**실행하지 않은 것**

- 실제 GraphHopper 모드(`IDENTITY_E2E_ROUTING=graphhopper`)의 새 spec. 재계산 digest 일치가 실제 엔진에서도
  성립하는지(결정성)는 **미실측**이다.
