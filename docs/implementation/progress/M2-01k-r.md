## 진행 중 발견한 공통 경계 결함

새 갤러리 브라우저 시험의 첫 실행은 기존 16바이트 PNG signature fixture가 실제 표시 가능한 그림이 아니어서 실패했다. 완전한 작은 PNG와 화면 아래 카드 스크롤을 사용해 다시 실행하자 Next·Vite 모두 Alice의 `blob:` 이미지가 실제 표시됐다. 그 뒤 별도 계정 탭에서 로그아웃해도 원래 갤러리 탭이 Alice 이미지를 유지해 두 shell에서 실패했다. `AuthenticatedWorkspace`는 다른 계정 값의 storage 이벤트만 처리하고 로그아웃으로 account-scope key가 제거되는 이벤트를 무시했다. Vite(`:4200`)와 Next 계정 탭(`:3100`)은 storage 출처가 달라 탭 재포커스 시 세션 재확인도 필요했다. 공통 platform이 두 신호를 처리하도록 수정한 뒤 집중 브라우저 시험은 Next·Vite **2/2** 통과했다. Headless `bringToFront()`가 focus 이벤트를 일관되게 보내지 않아 시험이 명시적으로 `focus` 이벤트를 보낸다. 이는 브라우저 handler를 통한 근거이며 실제 OS 탭 전환의 자동 focus 전달을 입증하지 않는다. 첫 fixture 실패와 제품 결함을 구별해 기록한다.

## 변경과 비공허성

- `AuthenticatedWorkspace`: 같은 origin의 account-scope key 삭제 이벤트에서 오래된 private child를 즉시 unmount한다. 다른 origin의 탭이 다시 활성화되면 세션을 재확인한다. 이미 받은 응답은 이전 세대로 돌아갈 수 없다. 각각의 처리 제거 변이는 새 단위 시험을 실패시켰다.
- `ActivityBatchExport`: 현재 controller가 획득한 선택 잠금을 unmount 때 풀고 소유한 Blob URL을 revoke한다. 잠금 해제 제거 변이는 새 단위 시험의 `locked=false` 단언을 실패시켰다.
- 갤러리 URL·채워진 cache·미저장 입력·늦은 open, 활동 preview worker·identity export URL, 영양·루틴 초안 및 늦은 결과는 실제 값이 들어 있는 component 시험으로 대조했다. 브라우저 갤러리 시험은 다른 탭의 명시 로그아웃 뒤 원래 탭의 표시 그림과 Blob URL 정리를 확인했다.
