Git 밖의 `/srv/workout-manager/secrets`에 root 전용 0600 파일과 서로 다른 무작위 DB 비밀번호를 만들었다. 실제 `db_setup` 컨테이너가 `DATABASE_SETUP_COMPLETE`로 마이그레이션 65개를 적용했다. 후속 SQL 조회에서 RLS가 켜진 public 테이블 139개, 앱·소유자·작업자 다섯 역할의 `SUPERUSER`·`BYPASSRLS`·`CREATEDB`·`CREATEROLE` 모두 false를 확인했다. 제한된 `workout_runtime` 계정으로 직접 로그인해 `consent` SELECT 권한은 true, public 스키마 CREATE 권한은 false였다. 이 검증은 전용 빈 DB의 역할·스키마 준비에 한정하며 사용자 데이터/백업 복구 시험은 아니다.
- 사용자가 로컬 Zitadel issuer·client ID·client secret의 정확한 AWS 목적지 전송을 승인한 뒤 서울 Secrets Manager `workout-manager/prod/oidc` 생성을 확인했다. 값을 담은 임시 로컬 파일은 삭제했다. Secrets Manager에서 새 서버 root 전용 `app.env`로 전달하는 첫 요청은 자동 승인 검토가 **거절**했다. AWS 저장소 전송 승인만으로는 서버 목적지를 승인한 것이 아니라는 이유였다. 사용자가 계정·secret·서버·파일을 지정한 전송을 별도로 명시 승인한 뒤 재시도해 `oidc_delivery_written`을 확인했다. 파일은 `0600`·root 소유, OIDC 세 항목이 있으며 값은 출력하지 않았다.

Workout 공개 HTTPS·로그인·로그아웃·전체 제품 검증과 worker 스케줄·복구 드릴은 **not_executed**다.

- 기존 Caddy 컨테이너에서 `wm-hosting-app:3100`의 내부 HTTP 200을 확인했다. 기존 apex Caddyfile에 새 workout 사이트 블록을 추가한 **후보 파일**을 컨테이너의 `caddy fmt`와 `caddy validate`로 확인해 `Valid configuration`을 얻었다. 후보는 활성 파일에 적용하거나 reload하지 않았다. 가비아 DNS는 아직 `workout` A 레코드가 없고, 로그인·CAPTCHA가 필요하다. Zitadel Cloud는 현재 로그인 계정에서 개인 프로필만 보여 앱 프로젝트 관리 권한이 확인되지 않았다. 따라서 공개 연결과 HTTPS callback 등록은 대기 중이다.
- 최신 전용 DB를 root 전용 `0600` `pg_dump -Fc` 파일(1,245,518 bytes)로 백업하고 `pg_restore --list`를 확인했다. 외부 네트워크와 공개 포트가 없는 임시 PostgreSQL 17.6 컨테이너의 첫 복원은 RLS 정책이 `workout_owner`를 참조하지만 새 cluster에 역할이 없어 **11개 오류로 실패**했다. 이를 성공으로 세지 않았다. 임시 DB를 지우고 제한된 `workout_owner` 역할을 만든 뒤 `pg_restore --exit-on-error --no-owner --no-acl --create`를 재실행해 오류 없이 완료했다. 복원본의 migration 65개, RLS 테이블 139개, public 테이블 140개, 정책 142개는 실행 중인 전용 DB와 일치했다. 임시 컨테이너와 시험 비밀번호 파일은 삭제하고 백업은 보존했다. 이 검증은 schema·내용 복원에 한정되며 새 cluster에서 앱·작업자 권한을 재구성한 뒤 제품을 기동하는 전체 운영 복구는 **not_executed**다.
- 월 USD 60 Budget의 조회 당시 `CalculatedSpend`는 실제 $24.384, 예측 $26.884였다(예산 집계 지연과 월말 변동 가능). 기존 세 머신의 기본요금 $24/월에 신규 8 GiB 머신 $44/월을 상시 더하면 **$68/월**로, 백업·도메인·세금 전에 이미 Budget을 넘는다. 사용자는 기존 apex의 `Ubuntu-2`만 남기고 나머지 인스턴스는 스냅샷 보존 뒤 삭제하기로 결정했다. 최종 한 머신에서 apex와 `workout`을 서로 다른 Host 이름으로 서빙하는 목표이며 가비아 DNS 접근을 확인해야 한다. 기존 `Ubuntu-2`의 2 GiB는 전국 경로 엔진의 로컬 peak RSS 1,391 MiB만으로도 여유가 좁아 전체 앱을 그대로 함께 올릴 수 있다고 판정하지 않는다. 스냅샷에서 더 큰 머신을 만드는 방법과 일시적 중복 요금, 기존 사이트의 구성·데이터·복구를 검증한다.
- AWS는 App Runner를 신규 고객에게 닫고 ECS Express Mode를 권장한다. ECS Express Mode는 기본 HTTPS 주소를 제공하므로 사용자 소유 도메인 없이 시험 주소를 만들 수 있다. 실제 계정의 사용 가능 여부와 비용은 확인 전이다.
- 월 상한의 잠정 후보는 서울 Lightsail IPv4 8 GiB 인스턴스에 웹·API·worker·전국 경로 엔진·PostgreSQL을 함께 올리고, 별도 비공개 백업 버킷을 쓰는 방식이다. 실제 계정의 `lightsail get-bundles`에서 Linux `large_3_0`(8 GiB, 2 vCPU, 160 GB)이 월 $44로 제공됨을 확인했다. 공식 요금표의 100 GB 버킷 $3, Secrets Manager 2개 약 $0.80, Route 53 hosted zone 사용 시 $0.50에 스냅샷 저장량 160 GB를 **예시로** $8로 잡으면 월 약 $56.30이다. 이는 **상한이 아닌 조건부 예시**다. 도메인 등록·DNS 질의·초과 전송·추가 스냅샷 변경 블록·세금·환율이 더해지며, 월 10만 원 이하 청구를 아직 증명하지 못했다. 로컬 전국 graph 308 MB, basemap 97 MB와 경로 엔진 peak RSS 1,391 MiB는 확인했지만 전체 프로세스 동시 메모리와 운영 백업 크기는 미측정이다. 단일 서버의 장애 복구·백업 복원과 삭제 억제 보존을 검증해야 한다. Lightsail의 일반 service role 부재 때문에 서버가 Secrets Manager를 무자격증명으로 직접 읽는 설계는 쓰지 않는다. 단기 배포 신원으로 읽어 제한된 서버 환경 파일에 전달하는 방식은 비밀 회전·권한·운영 수용 기준을 별도 확인해야 한다.
- 현재 API는 개발용 TypeScript 실행만 제공했다. 이 phase의 배포 준비 변경은 API를 Node 24 실행용 JavaScript로 번들링하고, 웹과 loopback API를 단일 컨테이너에서 기동하며 별도 private resource mountpoint가 없으면 시작을 거부한다. mountpoint 확인만으로 영속성을 증명하지 않는다. ECS 서비스에 EFS 또는 동등한 영속 저장소를 연결하고 재시작 후 같은 객체를 읽는 검증은 외부 수용 조건이다. 웹 프로세스에는 명시한 환경 변수만 전달하여 API의 DB 접속 문자열과 OIDC secret을 제외한다. 컨테이너 healthcheck는 API·웹 응답과 PostgreSQL `SELECT 1`을 모두 요구하며 오류 세부 정보를 출력하지 않는다. 잠금 파일 고정 설치, contracts/API/Web 빌드, 설정 누락 시 종료, lint·format·diff 검사는 통과했다. Docker daemon을 사용할 수 없어 **이미지 빌드·컨테이너 내부 실행은 not_executed**다.

## ODbL 산출물 로컬 재빌드

- 기존 배포·rollback 포인터는 건드리지 않았다. 전국 extract `osm-extract-south-korea`를 허용 목록에서 새 root로 받아 286,403,403 byte와 pin SHA-256 `848daadc56b2c2a808b30b2778f834c2802097ab382805c9fd42f248f4d6284b`를 확인했다. 취득 기록에는 HTTP 200과 Last-Modified `2026-09-02 05:13:33 GMT`가 남았다.
- 새 전국 graph는 `.geo-build-routing/kr-260929-odbl/foot`, build ID `c41b48d128fee2d5`, content SHA-256 `c3cb95d62b6972047397ae7940568bbf245afb6daf354268201193807e6e587f`다. 새 배경 지도는 `.geo-build-basemap-kr-260929-odbl/dist/ebe407d9dcbe-muldszzf`, build ID `ebe407d9dcbe`, 4,817 tiles다. 배경은 현재 스크립트의 서울 extract를 사용했고 동일 SHA의 기존 PBF와 앞선 build report의 취득 기록을 재사용했다.
- `scripts/check-odbl-artifacts.mts`를 두 새 root에 대해 실행해 basemap·graph 모두 `passed: true`를 확인했다. 이는 **로컬 산출물 검사**이며 공개 HTTPS 응답·활성 manifest·실제 서빙·coverage 판정이 아니다. 로컬 artifact root는 Git 제외 상태이고 배포 경로가 정해질 때 이동·보존 방식을 결정한다.

## 남은 외부 수용

1. 현재 단일 Lightsail 서버의 실제 비용·스냅샷 저장량과 월 예산을 계속 확인한다. 전용 PostgreSQL과 비공개 파일 저장소의 재시작 후 지속성, 전체 운영 복구, worker 실행과 삭제 억제를 검증한다. 위 격리 복원 드릴은 제품 기동까지의 복구 증거가 아니다.
2. 가비아 DNS에 `workout` 주소를 연결하고 검증된 Caddy 후보를 활성화해 공개 HTTPS를 확인한다. 공개 `/map-data-licence`와 script 응답 바이트를 활성 manifest SHA-256에 다시 대조한다. 내부 응답 검사는 공개 응답 검사를 대신하지 않는다.
3. Zitadel에 HTTPS redirect·post-logout·back-channel URL을 등록한다. `NODE_ENV=production`, secure `__Host-` cookie, secret manager 전달과 배포 환경의 로그인·계정 전환·로그아웃·취소·만료·back-channel 전파를 각각 확인한다. 실제 공급자에서 접근 불가능한 취소 경로는 미검증으로 남긴다.
