## 후속 서버 구현 준비 대조

API/worker 담당과 persistence 담당의 읽기 전용 source 대조를 Root가 수령했다. 이는 실행 시험이나 gate 구현 완료가 아니다.

- 공통 tenant 거래는 계정 잠금 후 시작하지만 모든 업무의 app 동의를 검사하지 않는다. 새 gate를 공통 tenant 진입에 일괄 배치하면 최초 동의·조회·내보내기·삭제·로그인을 막을 수 있다.
- 새 처리 검사는 해당 명령의 거래 잠금 안에서 성공한 기존 receipt 재반환 뒤, 새 저장 전에 수행해야 한다. 동의 철회와 같은 command 잠금으로 직렬화하며 부재 원장도 고려한다. check-in의 별도 잠금 순서와 기존 AI/HealthKit gate를 보존해야 한다.
- 수동 계획·실제·대화만 수정하면 다른 승인·영양·회복·자료 처리까지 구현됐다고 볼 수 없다. 증거/후보의 동의 dependency manifest와 호환 계약도 정책 확정 후 별도 범위로 다뤄야 한다.
- HTTP 연결/수집 요청만 막으면 예약 Garmin 수집·기존 worker 큐·재시도·수집 후 별도 저장 거래를 놓친다. cleanup/삭제 worker는 철회 이후에도 처리할 수 있어야 한다.
- 준비 보고서 원본: `/private/tmp/wm-s22-api-worker-guard-coverage-20261006.md`. 실제 PostgreSQL 경쟁·기존 receipt 재반환·tenant/kind 격리 및 기존 큐 검증은 향후 선택한 정책과 구현 범위에 맞춰 실행한다.
