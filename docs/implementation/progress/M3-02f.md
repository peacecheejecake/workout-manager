# M3-02f · HealthKit 재설치·anchor 재조정

상태: 로컬 수용 완료. `phase/m3-02`의 하위 작업이며 phase 독립 검토 전이다.

## 수용 경계

- 새 설치와 사용자의 명시적 권한 재확인에서 기존 미전송 배치를 먼저 보존·전송한 뒤 nil-anchor 재조회한다. 앞서 읽기 거부 상태의 빈 조회가 anchor를 진행시켰더라도 과거 운동을 다시 발견할 수 있어야 한다.
- 빈 조회는 읽기 허용·자료 부재·삭제의 증거가 아니다. 실제 `HKDeletedObject` UUID만 tombstone으로 전송한다. 중단·offline·계정 전환에도 기존 outbox를 버리지 않는다.
- 재설치 전에 전송하지 못한 삭제는 새 설치의 현재 표본 조회만으로 복원할 수 없다. 서버의 기존 행을 자동 삭제하지 않으며 이 한계와 사용자 삭제 경로를 명시한다.
- 서명된 iPhone의 재설치·권한 변경·background wake 실행은 M3-02h의 별도 증거다.

## 검증

- Swift/SQLite harness의 원자적 staging·replay·ACK·격리·재설치 재조정 시험이 통과했다. 새 durable `reconcile_pending` 표식은 앞선 outbox ACK 뒤에만 anchor와 known UUID를 nil로 재설정한다. 중단·오프라인에서는 기존 배치가 남는다.
- 같은 UUID를 새 `installationId`·`batchId`로 서버에 다시 보내는 실제 PostgreSQL 시험이 통과했다. 서버 raw·lineage는 각 1개이고 receipt는 2개이며, 실제 delete 뒤 지연 upsert는 tombstone을 되돌리지 못했다.
- 생성물·포맷·린트·전체 typecheck 34/34·단위 시험 4204 통과/7 skip·통합 시험 829/829·전체 build 15/15·기본 브라우저 E2E 4/4가 통과했다. root가 Swift harness와 서명 없는 Simulator 앱 전체 빌드를 재실행해 통과했다. 로컬 지도·장소 데이터 경로를 지정한 identity 브라우저 두 실행은 각각 302 통과·13 skip이었다.
- 새 설치 전에 유실된 미전송 삭제를 현재 조회만으로 추론하지 않는다. 실기기 재설치·권한 재요청·background wake는 아직 `not_executed`이며 M3-02h에서 검증한다.
