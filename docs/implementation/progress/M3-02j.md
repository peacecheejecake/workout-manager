# M3-02j · HealthKit 계정별 운동 등록 정책·계약

상태: **로컬 수용 완료**. [계정별 운동 선택·등록 ADR](../research/healthkit-account-registration-adr.md)의 사용자 결정을 등록·조회 runtime 계약으로 옮겼다. 서버 차단·제품 연결과 M3-02 phase 독립 검토는 후속이다. 이 계약만으로 M3-02h 실기기 수용을 판정하지 않는다.

## 정책과 계약 범위

- 사용자가 명시적으로 고른 `HKWorkout` UUID의 현재 제품 계정 귀속은 **사용자 선언**이다. HealthKit 필드로 인간 소유권을 증명하지 않는다. 계정 말소 때 활성 귀속 원장을 삭제하고, 같은 UUID의 다른 계정 명시 재등록을 허용한다. 따라서 다른 계정 차단 보장은 활성 claim 동안에 한정된다.
- 새 `packages/contracts/src/healthkit-registration.ts`는 계정 ID를 입력받지 않는 엄격한 Zod DTO를 정의한다. 최대 50개 중복 없는 UUID 등록에는 `accountAttributionDeclared: true`, 동의 revision, registry revision, idempotency key가 필요하다. 결과의 `claimEpoch`는 UUID이며, 제한된 목록은 최대 100개 항목과 opaque cursor를 사용한다. **개별 등록 해제 DTO는 정의하지 않았다.** 해제 시 raw·Activity·outbox 정리 및 재등록 정책을 사용자가 결정한 뒤 별도 계약으로 다룬다. 계정 **말소** 뒤 재등록 허용 결정은 유지한다.
- 등록된 표본의 수신 배치는 `schemaVersion: 2`와 이벤트별 `claimEpoch`를 요구한다. 기존 `schemaVersion: 1` 배치는 이 새 스키마에 들어갈 수 없다. 현행 v1 수신 경로의 실제 차단은 후속 서버 노드의 책임이며, 스키마만으로 막혔다고 판정하지 않는다.
- 오류 DTO는 현재 제품 API의 `{ error: { code }, requestId }` envelope를 따른다. 타 계정 식별자·운동 UUID를 오류에 싣지 않는다. `REGISTRATION_REQUIRED`, `CLAIM_CONFLICT`, `CLAIM_EPOCH_EXPIRED`, `REGISTRY_REVISION_CONFLICT`, `LEGACY_BATCH_UNSUPPORTED` 등을 명시한다. 코드의 HTTP 상태·거래 동작은 후속 API/DB 구현에서 검증한다.
- 새 `packages/contracts/tests/healthkit-registration.test.ts`는 선택 선언·동의 revision·UUID 대소문자 중복·50건 상한·목록·v1 거부/v2 epoch·비공개 오류 모양을 검증한다. 테스트는 선언·형식 검증이며 계정 소유권이나 실기기 동작의 증거가 아니다.

## 2026-10-05 검증 기록

- 첫 `pnpm --filter @workout/contracts typecheck` 시도는 셸 기본 Node `v20.10.0`이 저장소 요구 `>=24.12.0 <25`와 맞지 않아 **실행 전 실패**했다. 이를 typecheck 실패나 통과로 세지 않는다.
- 번들 Node `v24.19.0`을 `PATH`에 지정해 새 등록 계약과 기존 수신 계약의 초기 Vitest를 실행했다: **2개 파일·12개 테스트 통과**. 독립 감사에서 개별 해제 정책이 미정임을 확인해 해제 DTO와 해당 테스트 1개를 제거했다. 아래 최신 검사 결과를 최종 근거로 사용한다.
- 루트가 public `./healthkit-registration` subpath export를 추가한 상태에서 `@workout/api`와 `@workout/platform` typecheck는 각각 통과했다. 아직 새 계약을 호출하는 구현 소비자는 없으므로 이 결과는 통합 사용성 검증이 아니다.
- 첫 `@workout/mobile-web` typecheck는 `packages/experience/ui-spike/src/interaction-panel.tsx`의 `@dnd-kit/dom`을 찾지 못해 **실패**했다(`TS2307`). 패키지와 lockfile에는 선언돼 있었지만 이 worktree의 `node_modules`에 `dom` 링크가 없었다. 제한된 sandbox의 `CI=true pnpm install --frozen-lockfile` 첫 시도는 registry DNS `ENOTFOUND` 경고를 내고 완료 결과를 확보하지 못했다. 동일 명령을 접근 가능한 환경에서 다시 실행해 788개 패키지를 저장된 pnpm store에서 재사용했고 종료 코드 0으로 설치했다. lockfile 변경은 없었다. 작업 트리의 graph·package export 변경은 루트의 별도 통합 작업으로 보존했다.
- 재설치 후 `@dnd-kit/dom` 링크를 확인했다. `@workout/mobile-web`, `@workout/api`, `@workout/platform`, `@workout/contracts` typecheck를 각각 재실행해 모두 통과했다. 이어 전체 `pnpm typecheck`가 종료 코드 0으로 통과했다: Turbo **34/34 성공, 그중 7 cached**, 뒤이은 루트 TypeScript 검사도 통과했다. 캐시 결과는 새 컴파일로 세지 않는다. 아직 새 계약을 호출하는 구현 소비자는 없으므로 이 결과는 등록 경로의 동작 검증이 아니다.
- **개별 해제 DTO 제거 후 최신 재검증:** 등록 계약과 기존 수신 계약 Vitest **2개 파일·11개 테스트 통과**. `@workout/contracts` build/typecheck, `@workout/api`·`@workout/platform`·`@workout/mobile-web` typecheck, 변경 계약·테스트 ESLint, 계약·테스트·문서 Prettier가 각각 통과했다. 기존 전체 workspace typecheck는 해제 DTO 제거 **전** 결과이므로 최신 변경 전체의 새 통과 증거로 세지 않는다.

## 후속 경계

- 루트는 public subpath export와 그래프·진행 상태를 통합했다. 구현 소비자 연결은 후속이다. M3-02k/l은 실제 PostgreSQL의 단일 활성 UUID owner, 서버 선배포 v1 차단, claim epoch·동의 잠금, API 오류 매핑, 계정 말소 후 재등록을 검증해야 한다. M3-02m/n은 등록 UUID만 조회하는 native 수집·명시 선택 UI와 상태/bridge를 구현해야 한다.
- 기존 raw의 소유권을 자동 backfill하지 않는다. 제품 collector의 `predicate: nil` 위험은 아직 남아 있다. AWS·iPhone·제품 서버를 실행하거나 변경하지 않았다. 서명된 제품 iPhone의 수집·삭제·offline ACK·계정 전환과 M3-02h 전체 실기기 수용은 **not_executed**다.
