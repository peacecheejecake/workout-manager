# M3-01c · Native OIDC 일회성 교환·세션 서버 경계

상태: **completed** (한정된 서버 경계). 기준 `phase/m3-01` `ed130d1`. M3-01b의 제한된 iOS shell 위에 제품 인증을 바로 켜지 않고, 서버의 native 전용 세션 경계를 준비했다. Phase 독립 검토와 main 병합은 후속이다.

## 범위와 수용

- 고정 앱 redirect가 명시적으로 설정된 경우에만 native OIDC 시작·교환 경로를 연다. 앱의 PKCE verifier는 시작 시 서버에 전달하지 않는다. IdP callback은 짧게 유효한 일회성 code만 고정 앱 redirect에 싣는다.
- 서버는 code hash와 PKCE challenge를 저장하고, PostgreSQL에서 code 소비와 native bearer session 생성을 원자적으로 처리한다. browser cookie와 native bearer의 종류를 저장하고 서로 바꿔 쓸 수 없게 한다. Back-channel logout·계정 삭제 barrier를 유지한다.
- `EXT-BACKCHANNEL` 구현은 이미 main에 있지만 실제 공급자 전파 수용은 `in_progress`다. 여기서는 해당 구현의 로컬 native 세션 철회만 확인하며 공급자 gate를 완료로 표시하지 않는다.
- 실제 localhost OIDC fixture 및 격리 PostgreSQL에서 만료·재사용·잘못된 challenge·동시 교환·교차 사용·철회를 검증한다. 운영 HTTPS redirect, iOS ASWebAuthenticationSession·Keychain·transport, 제품 iPhone 로그인은 이 노드의 완료 증거가 아니며 별도 M3-01 후속에서 **not_executed**로 추적한다.

## Native 호출 계약

1. 앱이 Base64URL 43자 난수 `codeVerifier`를 만들고 SHA-256 Base64URL `codeChallenge`만 `POST /bff/v1/auth/native/start`에 보낸다. 응답 JSON의 `location`을 시스템 `ASWebAuthenticationSession`으로 연다. 이 경로에는 browser cookie·bearer를 보내지 않는다.
2. 기존 IdP callback에서 서버가 native state를 한 번 소비하고 `org.workoutmanager.app://auth/callback?code=…`로 이동한다. 이 URL에 bearer, verifier, IdP token을 싣지 않는다. 앱 URL scheme 등록과 실제 iOS 수신은 후속 작업이다.
3. 앱은 code와 보관한 verifier를 `POST /bff/v1/auth/native/exchange`에 보내고 JSON bearer를 Keychain에 저장한다. Keychain과 고정 HTTPS API transport는 후속 구현이며 현재 제품 앱에서 이 흐름을 호출하지 않는다.
