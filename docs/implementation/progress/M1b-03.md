# M1b-03 · 영양·보강 통합

상태: **완료**. M1b-01의 영양 계획·섭취 원장과 M1b-02의 보강 수행 원장을
현재 훈련 계획 및 공동 후보 검토 경계에 연결했다.

훈련 계획 버전은 기존 고정 보강 링크를 원자적으로 복사하고 명시 변경만 새
버전에 반영한다. 시작·완료한 세션의 링크 변경은 공동 후보 검증에서 거절한다.
세션 시각을 바꾸면 현재 상대 영양 계획의 영향 검토를 요구하며, 단독 계획
편집으로 그 변경을 적용할 수 없다. 공동 후보 schema v3은 훈련·영양 범위,
현재 원장·카탈로그·제약·동의·대화·실행 개정, 부재한 영양 head, 상대 영양
영향과 고정 보강 변경을 명시한다. 최종 승인은 최신 상태를 재확인한 뒤 훈련·
영양 계획·이력·outbox·영수증을 하나의 PostgreSQL 트랜잭션에 저장한다.
부분 선택은 새 후보를 만들며 원 후보의 일부를 암묵적으로 적용하지 않는다.

통합 Planner는 한 SQL 읽기 시점의 훈련 세션, 영양 계획, Activity, 섭취를
별도 레이어와 단위별 집계로 제공한다. 보강 set log는 동일 canonical Activity의
상세로만 표시해 수행 횟수·운동 시간을 다시 더하지 않는다. 상대 영양 앵커의
미해결 시각은 실제 섭취로 추정하지 않고 별도 목록에 남긴다. 단일 요청은
93일로 제한한다.

보강 실제 세트는 사용자가 명시 동의한 경우에만 브라우저의 계정 범위 대기함에
최대 7일·100명령·256 KiB 저장한다. 확인된 세트 생성·정정·삭제만 저장하며
재접속 후 자동 동기화에서 같은 ID와 키·본문으로 재전송한다. 충돌은 검토
상태로 멈추고,
로그아웃·계정 전환·세션 만료 때 private 저장소를 지운다. 승인 명령과 타이머는
오프라인 대기함 대상이 아니다. 같은 계정의 여러 탭이 동시에 대기함에 쓰면
브라우저 localStorage가 원자적 추가를 제공하지 않으므로, 다른 탭의 변경을
감지한 현재 탭은 추가 기록을 막고 재확인을 요구한다.

FIT parent와 부분 bout는 opt-in `--include-bouts`의 Activity Details V3/내보내기
v4에 명시적으로 담는다. 기존 v1~v3 내보내기와 receipt hash는 유지한다. 확정된
lap만 parent 안의 비중첩 bout로 배정하고 나머지는 `mixed_unallocated`로 표시한다.
혼합 파일은 parent Activity 한 건으로 집계하며 확정 strength bout에는 같은
Activity ID의 보강 실행·세트를 연결한다. 합성 FIT의 40분 러닝·10분 보강·10분
미배정 parent 60분을 시험했고 전체 Activity 시간은 60분 한 번만 집계했다.
영양 actual은 별도 섭취 원장에 남고 운동 시간 분모에 섞이지 않는다.

영양 선호 전용 원장도 아직 없으므로 공동 후보의 preference revision은 현재
사용자 제약 원장의 변경을 보수적으로 추적한다. 실제 LLM·공식 Garmin·실기기
검증은 이 수동/fixture 범위 밖이다.

검증: 격리 PostgreSQL 30개 파일·262개 테스트, 계약 34개 파일·454개 테스트,
Python pytest 75건·Ruff, 전체 `pnpm check`(포맷·린트·22개 패키지 타입 검사·
182개 파일/1,915개 단위 테스트), Web·mobile-web production build가 통과했다.
통합 Planner, 공동 후보 승인, 보강 오프라인 대기함은 각각 실제 OIDC/PostgreSQL/
Chromium E2E로 검증했다. 공동 후보는 320/768/1280px 화면과 키보드 접근도
확인했다. E2E harness 종료 시 격리 PostgreSQL 정리를 확인했다.

커밋 전 Herdr 분할 창 독립 리뷰는 기준 HEAD
`9bec7530604551ccea89a2d0bc6edf95ad884515`, 최초 staged diff SHA-256
`6eb4c8598ff246b5693f38438964ec647f381c6a89e95a07e175562a11148135`
에서 P2 4건을 지적했다. 준비 receipt에는 제안 원문 대신 정규 요청 해시만
보관하고, 이전 버전 완료 보고는 현재 세션 잠금을 유지하며 허용했다. 회수 후보는
조회 캐시에서 제거하고, 상대 영양 항목 ID는 기존 문자열 계약을 재사용한다.
각 경로의 회귀와 전체 검사·빌드를 재실행했다. 수정분의 독립 재검토는 위 기준
HEAD와, 이 진행 기록을 제외한 staged diff SHA-256
`9e7f44cc3a178b64fd825c173fc63a98260ca7ec8b04ca90e6657a8a27a9a3f1`을
확인했다. 최초 P2 4건이 모두 해결됐고 추가 actionable finding은 없었다.
