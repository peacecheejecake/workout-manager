# M1-04aj · 세션 완료 확인·철회 UI

상태: 구현·검증 완료.

- 현재 저장된 계획 세션에 명시 완료 확인·사유 있는 철회/재확인·보고 이력을 연결한다.
- 보고는 실제 관측과 별도다. 미저장 계획 초안·선택을 보존하며 완료 보고는 초안 undo 대상이 아니다.
- 완료된 일정의 날짜·Block·시작 시각·시간대·삭제를 UI에서 보호하고 서버 보호를 유지한다.
- 응답 유실은 동일 명령·key로 확인한다. 충돌은 최신 기록 확인 후 새 명시 확인이 필요하다.
- 기간 날짜 이동은 M1-04ak, 외부 출시 gate는 기존대로 남는다.

## 복구와 상태 소유권

- 현재 보고·이력·목록은 인증 사용자/세션으로 격리된 TanStack Query가 소유한다.
  계획 초안은 기존 Zustand에 보존하며 완료 응답을 계획 snapshot에 복사하지 않는다.
- 명시 확인 전에는 쓰지 않는다. 새 세션은 저장 후 확인할 수 있고, 저장된 대상과 날짜·시간대를
  확인 화면에 표시한다. 철회/재확인은 정정 사유가 필요하다.
- 네트워크 유실·5xx·형식 불일치 응답은 고정한 명령/key로 재시도한다. 성공 영수증을 현재 상태로
  취급하지 않고 새 조회로 확인한다. 409는 사유를 보존하고 새 명시 확인을 요구한다.
- 계정·선택이 바뀐 뒤 이전 요청이 도착해도 새 화면 상태나 콜백을 변경하지 않는다.
- 완료 일정과 이미 작성한 초안이 충돌하면 초안을 버리지 않고 미리보기·저장을 막는다.
  제목·목적·계획 길이·강도·새 ID 복제는 기존 잠금 조건 아래 계속 사용할 수 있다.
- 완료 목록 조회가 실패하면 미확인 상태를 표시하고 재조회를 제공한다. 서버는 모든 계획 저장에서
  완료 보호를 다시 검사하므로 오래된 화면이나 직접 요청도 보호를 우회하지 못한다.

## 식별자 전달

- 브라우저는 `GET/POST /plans/session-completion?sessionId=…`를 사용한다. 공백·슬래시·한글을
  포함하는 계약상 유효한 ID를 URLSearchParams로 전달한다. 서버는 정확히 sessionId 하나만 검증한다.
- 기존 `/plans/sessions/:sessionId/completion` 경로는 호환성을 위해 유지한다.
  일반 Host 경로의 traversal/인코딩 검증은 변경하지 않는다.
