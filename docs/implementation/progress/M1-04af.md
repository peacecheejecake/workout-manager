# M1-04af · 기간 운동 불가 날짜·가용 시간 제약

상태: 완료. 사용자가 S04 제약의 첫 범위로 운동 불가 날짜·가용 시간을 선택했다.

## 범위와 의미

- 기간별 특정 현지 날짜의 운동 불가와 운동 가능 시간량을 편집한다. 가용 시간은 시각창이
  아닌 날짜별 계획 시간 합계의 한도이며 0–86,400 정수 초다. 0은 명시적 가용량 0이고
  항목 부재는 미지정이다. 생리적 상한이나 실제 휴식·수행 결과가 아니다.
- 직접 지정한 제약과 조상 기간의 조건을 함께 적용한다. 불가 날짜는 합집합, 가용량은
  최솟값이며 출처를 표시한다. 같은 날짜 여러 계획 세션의 알려진 시간을 한 번씩 합산한다.
  세션 시간이 null이면 미정으로 남기며 단계 시간이나 거리로 보완하지 않는다.
- 알려진 합계가 가용량을 초과하거나 불가일에 세션이 있으면 충돌이다. 합계가 초과하지
  않더라도 미정 시간이 있으면 가용량 충족 여부를 미확인으로 표시한다. 저장 전 표시하되
  충돌 있는 수동 계획의 명시 저장은 허용한다. 자동 이동·단축·삭제·actual 생성은 없다.
- 날짜는 기간의 종료일 미포함 범위에 있어야 하며 목록별 중복을 거절한다. 기간 축소 때
  조건을 자동 삭제하지 않는다. structural invalid는 기존 미리보기 검증에서 차단한다.
- optional constraints는 과거 누락을 보존하고 명시 해제는 두 빈 목록으로 저장한다.
  snapshot/receipt/export의 과거 원문과 세션 잠금 의미를 유지한다. DB migration은 없다.
- 특정 시각창·요일 반복·종목 제한·훈련량 상한은 이번 task에 포함하지 않는다.

- 계약 2 files / 32 tests, 신규 UI 6 tests, API 32 tests 통과. 날짜·중복·범위·정수 초,
  조상 조건 합성·다중 세션 합계·null/0·불가일의 0초 세션·DST 현지 날짜·불변성을 확인했다.
- 실제 PostgreSQL integration 13 files / 117 tests 통과. 충돌·시간 미정 계획의 명시 저장,
  legacy snapshot·receipt replay·계정 내보내기·빈 목록 해제·잠금 세션·actual 불변을 확인했다.
- production build 7 tasks, `pnpm check --maxWorkers=2` 80 files / 950 tests 통과.
  최초 check는 신규 UI 테스트 파일의 포맷을 수정한 뒤 재실행했다. 기존 우선순위 UI 시험의
  전 영역 legacy 문구 부정 검사가 새 제약의 누락 안내도 잡아 우선순위 행으로 한정했다.
- 신규 제약 E2E 2개와 기존 우선순위 E2E 1개 통과. 첫 실행은 출처 제목·종류 표시로 변경한

  기존 우선순위 E2E도 같은 이유로 legacy 문구 검사를 우선순위 행에 한정했다.
