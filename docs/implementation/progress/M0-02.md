# M0-02 · 공유 runtime 계약

기준일: 2026-09-16. 상태: **완료** — 구현·로컬 검증·독립 리뷰 완료.

`docs/.pre/contracts.ts`, `extensions-v022.contracts.ts`, `extensions-v023.contracts.ts`의
공개 데이터 타입을 `packages/contracts`의 Zod 스키마와 inferred TypeScript로 구현했다.
원본 설계 및 규칙 문서는 변경하지 않았다. core/approval은 root, nutrition/routines는
Codex native agent에 파일 소유권을 분리해 병렬 배정했다.

## 현재 구현의 wire 동작

- 공개 subpath: `@workout/contracts/{primitives,core,nutrition,routines,approval}`.
- ID는 비어 있거나 앞뒤 공백이 있으면 거부한다. 기존 opaque ID를 UUID로 강제 변환하지 않는다.
- revision은 0 이상의 safe integer다. 날짜는 실제 달력 날짜, 시각은 offset을 포함한 ISO 문자열,
  timezone은 runtime이 인식하는 IANA 이름이다. 원래 offset을 보존하고 시간 비교에는 epoch를 사용한다.
- 문자열·수치를 자동 변환하거나 기본값으로 채우지 않는다. unknown/null과 관측값 0을 구분한다.
  단위·status·target/actual·count definition을 discriminated schema로 검증한다.
- 알려진 DTO의 미정의 필드는 거부한다. 미래 필드를 조용히 버리는 forward compatibility는 없다.
- 승인 v3는 `JointApprovalRequest`, v4는 `IntegratedApprovalV023`으로 명시 분기한다.
  `decodeApprovalRequest`는 모르는 버전을 `UNSUPPORTED_SCHEMA_VERSION`, 잘못되거나 혼합된
  payload를 `INVALID_APPROVAL_PAYLOAD`로 반환한다. v3를 v4로 자동 마이그레이션하지 않는다.
- v3의 null nutrition head, v4의 explicit absent aggregate head를 그대로 보존한다.
  v4는 write domain에 대응하는 head expectation을 요구한다.
- 루틴 graph의 참조·cycle·choice group, 유한 일정 window, 실행 상태/시각, 회복 선택 참조를 검증한다.
  래퍼·링크 데이터에서 실제 운동 기록을 생성하지 않는다.

## 검증과 한계

- `pnpm check`: format/lint/typecheck 및 전체 Vitest 174개 통과(계약 96개, 기존 tooling 78개).
- Frozen lockfile 설치 통과. 기존 Playwright fixture 4개 회귀 통과.
- `pnpm build`: 계약 JavaScript/declaration 및 기존 fixture 빌드 통과.
- 실제 사용자·DB·provider를 사용하는 검증이 아니다. UI 변경이 없어 실 브라우저 탐색은 추가하지 않았다.
- 스키마 통과는 승인 완료가 아니다. 소유권/ACL, 참조 실재 여부, freshness, 후보에서 계산한 전체 write set,
  실제 recurrence expansion, actual allocation 중복, transaction/idempotency는 후속 서버 검증이다.
- HostContext/AuthTransport 함수는 TypeScript 인터페이스이며 JSON wire 스키마 대상이 아니다.
  URL 구문 검증만으로 Host allowlist·SSRF 방어가 완료되지 않는다.
- OpenAPI/client 생성은 실제 API endpoint가 생기는 M0-05에서 연결한다.

다음 준비 작업은 M0-03 Host/Zustand/두 shell과 M0-05 API/DB 기반이다. 두 작업은 M0-02 이후 병렬 가능하다.
