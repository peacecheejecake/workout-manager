# M1-06c · Garmin OAuth 연결 기반

확인일: 2026-09-16. 상태: **연결 기반 구현·로컬 검증 완료**.
사용자 결정에 따라 기존 OIDC 앱 로그인을 유지하고 `/account`에 별도 Garmin 연결을 추가했다.
FUT-04의 연결 기반 범위이며 EXT-G, M1-06b 공식 수집, 실제 Garmin 검증은 완료하지 않았다.

## 구현

- 별도 status/connect/callback/connection 경로와 공식 OAuth 2.0 PKCE adapter. 앱 세션을 새로 만들거나
  Garmin ID로 OIDC 계정을 교체하지 않는다. 공개 endpoint만 사용하며 실제 권한 범위는 공급자 응답으로 검증한다.
- 연결 시작에 현재 세션·Origin·CSRF를 검증하고, 10분·일회성 state와 암호화 PKCE verifier를 시작
  계정·세션에 결합한다. callback의 commit 직전에도 DB에서 세션·generation·삭제 여부를 검사한다.
  URL의 성공 표시만으로 연결됨을 표시하지 않는다. code와 provider 오류 원문은 로그·최종 URL에 남기지 않는다.
- Token은 AES-256-GCM으로 암호화하고 계정·용도·key ID를 AAD에 결합한다. tenant RLS와 refresh lease/CAS를
  사용한다. 브라우저·export·일반 outbox에는 token을 넣지 않는다. API 설정을 생략해도 OIDC는 유지된다.
- 설정 UI는 미설정·미연결·승인 중·연결됨·재연결 필요·해제 중·오류를 구분한다. 연결 해제는 OIDC 로그인을
  유지한다. 재연결 필요 상태에서는 기존 연결을 먼저 해제하고 정리 후 다시 연결한다.
- Worker 전용 role과 durable encrypted cleanup queue로 provider registration 철회를 처리한다. 사용자 ID와
  active 소유권을 확인하기 전에는 원격 삭제하지 않는다. 이미 다른 계정이 소유한 연결을 강제로 옮기거나 끊지 않는다.
  등록별 lease를 직렬화하고 성공 후 같은 등록의 오래된/회전된 credential 작업을 함께 정리한다.
- 계정 삭제 거래에서 진행 중 callback/refresh를 차단하고 cleanup을 함께 기록한다. 실패한 거래는 함께 rollback한다.
  복구 시 백업의 Garmin credential·attempt를 재사용하지 않고 최신 cleanup 원장을 별도로 적용한다.

## 검증 기록

초기 E2E에서 승인·해제·OIDC 유지·거절·callback 재실행 거절은 통과했으나, 로그아웃 뒤 만료된
연결 시도가 화면에 ‘승인 진행 중’으로 남았다. 연결 시작 세션의 유효성을 상태 조회에도 반영한 뒤
실제 앱/API/DB와 로컬 OIDC·Garmin fixture를 쓰는 E2E 9개를 통과했다.

Aside에서도 합성 OIDC 로그인 → 별도 로컬 Garmin 승인 → 연결됨·ACTIVITY_EXPORT → 연결 해제 →
미연결 복귀를 확인했다. OIDC 계정은 유지됐고, 스크린샷 `artifacts/garmin-connected.png`를 직접 검토했다.
상태 재조회 시 설정 패널과 운영 요약이 다르게 남는 문제는 두 Query를 함께 갱신하도록 수정했다.
최종 build에서도 연결 → 해제 → 재조회 후 두 영역의 미연결 상태와 OIDC 계정 유지를 다시 확인했다.
최종 화면 증거는 같은 Aside 세션의 `artifacts/garmin-disconnected-viewport.png`이며 직접 검토했다.
전체 페이지 캡처의 중복 합성 때문에 viewport 캡처와 전체 accessibility snapshot으로 확인했다.

독립 리뷰에서 재연결 필요 상태의 버튼이 남아 있는 만료 credential 때문에 계속 거절되는 문제를 발견해,
기존 연결 해제 후 다시 연결하도록 UI 흐름을 명확히 했다. 최종 검사·리뷰 결과는 작업 커밋에도 기록한다.

## 한계와 운영 입력

검증 공급자는 로컬 HTTP 합성 fixture다. 공식 Garmin 계정·client 발급·실제 응답·데이터 수집 성공의
증거로 사용하지 않는다. token 만료 필드·permissions payload 등은 실제 파트너 환경에서 재확인해야 한다.

철회 scheduler와 keyring/secret manager, 최신 삭제·cleanup 원장의 독립 내구 저장소는 운영 배포 시
구성해야 한다. OAuth/token 회전과 DB는 분산 transaction이 아니며 공급자 응답 직후 process가 중단되면
재연결 또는 사용자 측 공유 권한 확인이 필요할 수 있다. 정리 credential 만료가 원격 철회 성공을 뜻하지 않는다.
상세 설정·보존 조건은 [Garmin 운영 설정](../garmin-setup.md)에 기록했다.
