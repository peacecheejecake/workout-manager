# M3-02c · HealthKit 고정 동의·권한·상태 bridge

상태: **completed (로컬 경계)**. `phase/m3-02`의 하위 작업이며 phase 독립 검토 전이다.

## 범위

- strict native bridge v3에서 HealthKit 서버 동의와 운동 읽기 요청 이력을 분리한다. 구버전 조합은 버전 불일치로 닫는다.
- WebView에는 지원 여부, 명시적 요청 이력, 계정 범위의 제한된 전송 대기·보류 요약만 제공한다. bearer, 표본, UUID, anchor, 정밀 시각은 제공하지 않는다.
- 서버 동의는 고정 경로의 native bearer GET/PUT과 revision/idempotency 검증을 사용한다. 동의 철회 시 로컬 수집 상태도 제거한다.

## 판정 경계

제품 화면의 명시적 버튼 연결, 서명된 iPhone 권한 요청과 실제 수집은 이 노드에서 `not_executed`이며 M3-02의 후속 통합에서 별도 확인한다. HealthKit의 요청 완료는 읽기 권한이 허용되었다는 증거가 아니다.

## 구현·검증 기록

- `@workout/contracts/native-bridge`의 strict v3 요청·응답을 추가했다. v2 host와 v3 WebView 조합은 handshake 버전 불일치로 닫는다. `healthkit.workouts`는 기기 지원만 뜻하며 실제 읽기 권한은 노출하지 않는다.
- 2026-09-28에 Apple의 [HealthKit 권한 안내](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)와 [observer 실행 안내](https://developer.apple.com/documentation/healthkit/executing-observer-queries)를 재확인했다. Apple은 읽기 허용·거부를 앱이 구별할 수 없고 background delivery는 Simulator가 아닌 실제 기기에서 시험해야 한다고 명시한다.
- 고정 HealthKit 동의 GET/PUT, 명시적 `healthkit.workouts.requestAccess`, 계정 범위의 제한된 `healthkit.workouts.status`를 연결했다. WebView에는 bearer·표본·UUID·anchor·정밀 시각을 반환하지 않는다. 철회가 서버에서 확정되면 로컬 상태를 지우고 실패는 `LOCAL_RESET_FAILED`로 드러낸다.
- 구현 agent의 관련 계약·platform 테스트 35/35, 계약·platform 타입 검사, 서명 없는 iOS Simulator build가 통과했다. 최초 Xcode sandbox 접근 실패 뒤 접근 가능한 실행에서 `BUILD SUCCEEDED`를 얻었다. root의 결합 트리 검사에서 생성물, Prettier, ESLint, 전체 TypeScript 34/34, 단위 4,197 통과·7 건너뜀, 실제 PostgreSQL 통합 822 통과, build 15/15, 기본 Playwright 4/4가 통과했다.
- root가 최종 Vite bundle을 `cap sync ios`로 복사한 뒤 웹 `index.html`과 iOS public 사본의 SHA-256 일치를 확인하고, v3 웹·Swift host 조합의 unsigned Simulator Debug build를 다시 통과시켰다.
- 첫 전체 단위 실행은 격리 환경의 localhost fixture 접근과 Python 경로 누락으로 실패했다. 기존 Python runtime 경로와 localhost 접근이 가능한 실행에서 전체를 재검증했다. 실패 실행을 통과로 세지 않는다.
- 계정·화면 identity 전체를 직렬로 두 번 실행해 각각 **302 통과·13 건너뜀**을 확인했다. 건너뛴 외부 조건과 서명된 제품 iPhone의 `not_executed`는 통과로 바꾸지 않는다.
