# M1-05d · 구조화 근거 본문·의존성 snapshot 저장

상태: 완료. S10/FUT-02의 구조화 근거 고정과 원본 수명주기 기반이다.
M1-05a의 원장 revision 캡처와 M1-05b의 불변 상담 범위를 결합한다. S05 계획 종류를
해석하거나 계획을 쓰지 않으므로 독립 착수하며, 부모 M1-05의 M1-04 의존성은 유지한다.

## 저장 범위

`running-core-v1`은 선택한 상담의 불변 계획·전체 사용자 메시지, 명시적 1~90일 현지 날짜 창의
활동·체크인, 그 계획 세션의 사용자 완료 보고를 캡처한다. 날짜 창 시간대와 원본 관측 시간대는
별도다. 시작 시각이 없는 활동은 날짜 불명으로 포함하고 기간 내 관측이라고 추정하지 않는다.
상담이 가리키는 과거 계획과 현재 plan head 의존성을 구분한다. null·0·미입력 제약을 보존한다.

본문과 원장 stamp는 같은 SQL statement snapshot에서 읽는다. 사용자 메시지는 100개,
활동은 500개, 체크인은 100개, 완료 보고는 1,000개, 본문은 2MiB로 제한한다. 한도를 넘으면
명시 오류를 반환하며 일부를 조용히 잘라 완전한 근거로 저장하지 않는다.

자료·GPS/상세 원본·전체 사용자 선호/제약·정책 및 아직 없는 도메인 원장은 포함하지 않는다.
이 제한된 profile을 완전한 EvidenceSnapshot, AI 전송 권한, 계획 승인 freshness 또는 생리학적
근거 검증으로 취급하지 않는다. 근거 drawer·Decision/Proposal·승인은 후속 통합이다.

## 삭제와 동의

이 캡처는 사용자가 앱 안에서 자기 자료를 검토·저장하는 기능이다. AI 동의가 없더라도
저장할 수 있으며 외부 모델로 전송하지 않는다. AI 동의 상태는 읽은 그대로 의존성에 남긴다.
명시적인 AI 동의 철회는 기존 저장 근거의 본문을 회수한다. 재동의가 회수된 본문을 복구하지 않는다.

포함된 활동·체크인 삭제도 관련 snapshot 본문을 같은 transaction에서 회수한다. 회수 후에는
snapshot/thread ID·생성 시각·회수 사유만 남고, 조회·목록·export 및 이전 명령 재전송에서
본문을 되살리지 않는다. 영수증에는 snapshot ID만 저장한다. 계정 삭제는 snapshot을 상담보다
먼저 제거한다. 무기한 건강 내용 보존을 불변성의 의미로 사용하지 않는다.

## 검증

- 계약·export 호환성 15개, 인증 transport 38개, API inject 23개 시험 통과.
- `pnpm check --maxWorkers=2`: 생성물·Prettier·ESLint·전체 consumer typecheck 및
  143개 파일의 1,602개 unit/component 시험 통과.
- `API_ORIGIN=http://127.0.0.1:4301 pnpm build`: production build 7개 통과.
- 실제 PostgreSQL 22개 파일 172개 시험 통과. 신규 9개는 과거 계획/현재 head 구분,
  DST 날짜 투영·날짜 불명·null/0, 본문/manifest 일관성, 동시 중복 명령, RLS·권한,
  활동/체크인 삭제·명시 AI 거절·재동의·export/erase, outbox 실패 rollback과 수량/2MiB 한도를 검증한다.
- SQL 본문 조회 직후 다른 transaction의 관측 수정이 커밋되어도 본문과 stamp는 이전 시점으로
  일치한다. 직접 SQL 활동 삭제·동의 제거와 경합하는 경우에는 `pg_blocking_pids`로 실제 잠금
  대기를 확인한 후 캡처를 커밋하고, 삭제 transaction이 새 snapshot까지 회수함을 검증했다.
  원본 삭제 경로도 DB trigger에서 잠금을 획득하므로 애플리케이션 호출 순서에만 의존하지 않는다.
- 실제 OIDC/API/DB E2E 3개 통과: 신규 2개와 기존 대화 원장 1개. 생성·목록·조회·동일 키,
  최신 계획/대화와 과거 근거 분리, 다른 사용자 404, 원본 삭제·동의 철회 뒤 조회/재전송/export
  본문 제거를 확인했다. 해당 코드의 최종 scoped lint/typecheck도 통과했다.
- 첫 PostgreSQL 실행은 새 migration 013을 기대 목록에 넣지 않은 기존 시험 1개가 실패했다.
  목록을 갱신한 다음 실행은 별도 E2E와 병행 중 임시 PostgreSQL 시작 단계에서 실패했다.
  각 실행의 종료를 확인하고 다른 DB 작업이 끝난 뒤 동일 전체 시험을 단독 재실행해 통과했다.
- 초기 build는 작성 중인 새 DB 시험의 export 필드명 불일치로 실패했다. 실제 v6 필드인
  `evidenceSnapshots`로 통일한 후 전체 build와 consumer typecheck를 통과했다.
- 격리된 PostgreSQL의 실제 backup/restore drill 최종 24개 검사 통과. 보존 계정의 본문·동일 키
  영수증 복원, 계정 삭제 재적용, 복원 후 원본 삭제에 따른 조회/export/재전송 본문 회수를 확인했다.
  백업 이후 AI 동의 철회는 별도의 최신 회수 원장과 동의 상태를 함께 적용하여, 이전 dump의
  본문과 동의가 서비스 접근 전에 제거·갱신됨을 검증했다. 이전 실행 기록을 보존했고 임시
  cluster·archive·원장 정리를 확인했다. [실행 결과](../research/backup-restore-result.json)는
  로컬 합성 데이터 검증이며 production 외부 원장 보관 서비스나 RPO/RTO 검증이 아니다.
- 첫 Herdr 독립 리뷰의 P2 1건은 백업 이후 AI 동의 행 삭제를 복원 원장에서 표현하지 못한
  문제였다. 명시적 exists/absent 상태와 백업 당시 소유자 포함 대상 coverage를 추가했다.
  원장 항목 누락은 실패하며, 동의 부재는 이전 동의 행 삭제로 적용하고 계정 삭제를 우선한다.
  기존 false 철회 사례와 별도로 행 삭제 후 부재·본문 회수·동일 키·export를 실제 복원 검증했다.

UI 변경은 없다. API E2E의 브라우저 로그인 외에 새 Aside UI 검증이나 Native 검증을 주장하지 않는다.
94개 node DAG의 참조·비순환·증거 경로를 검사했으며 부모 및 외부 출시 gate는 그대로다.
독립 Herdr 리뷰 대상 base/tree·결과는 커밋 본문에 기록한다.
