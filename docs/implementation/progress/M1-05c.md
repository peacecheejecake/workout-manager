# M1-05c · 상담 기록 UI·검토 범위·메시지 복구

상태: 구현·검증 완료. S10 / FUT-02의 사용자 상담 기록 화면을 Next와 Vite 공통 모듈로 연결한다.
M1-05b API, M0-03 Host, M0-04 UI를 사용한다. 부모 M1-05의 M1-04 의존성은 유지한다.

## 범위

저장된 계획 버전·세션/Block/Phase를 선택해 제목과 첫 메시지를 저장한다. 기존 상담의 범위는
생성 당시 불변 계획에 고정한다. 그 범위의 상위/하위 기간 제약과 세션 잠금을 읽기 전용으로
표시한다. 미입력 제약과 빈 배열을 구분하며 전체 사용자 제약·선호를 모두 로딩했다고 주장하지 않는다.

대화·계획 조회는 사용자/세션별 TanStack Query, 미전송 초안과 재확인 명령은 메모리 Zustand,
선택 상담·계획 버전·scope·목록 페이지는 URL이 소유한다. 로그인 수명이 끝나면 제거한다.
모델 전송·assistant 답변·후보·계획 승인은 이번 화면에 포함하지 않는다.

## 복구와 조회 한계

메시지 편집을 시작할 때 revision을 고정한다. 409는 초안을 보존하고 사용자가 최신 기록을
읽고 확인해야 새 명령을 보낼 수 있다. 응답 유실·5xx·해석 불가 응답은 같은 body/key로만
재확인한다. 미확정 동안 입력·화면 전환을 잠그고 자동 재전송하지 않는다.

성공 직후 생성된 상담을 선택하며 배경 재조회가 뒤늦게 사용자의 새 선택을 덮어쓰지 않는다.
로그인 수명 종료는 요청 취소·query 제거·Zustand 초기화를 수행하고 늦은 응답을 무시한다.
브라우저 저장소에 건강 초안을 쓰지 않으며 미전송 내용이 있으면 페이지 이탈 경고를 제공한다.

상담 목록은 20개 단위, 메시지는 50개 단위로 명시적으로 더 조회한다. 계획 선택은 기존 API의
최근 100개 history 범위이며, 선택된 상담은 별도 ID 조회로 원래 계획 버전을 읽는다.
URL의 scope 변경은 기존 상담의 고정된 범위를 변경하지 못한다. 전체 제약·선호 및 Evidence,
모델 답변·승인 통합은 부모 M1-05에 남는다.

## Shell 연결

Next `/coach`와 Vite `/coach`는 같은 `CoachingWorkspace`를 사용한다. 인증·브라우저 URL 연결은
각 shell에 남겨두고 도메인 모듈은 Next API를 참조하지 않는다. Vite `/account`는 기존
`IdentityWorkspace`를 재사용한다. 기본 `/` 개발 화면과 `/ui-spike` 검증 화면은 유지한다.

Vite 개발/preview는 `API_ORIGIN=http://127.0.0.1:4301`처럼 명시한 origin에만 `/bff`를
proxy한다. 원격 배포의 BFF 경로는 hosting 구성이 담당한다. API의 `PUBLIC_ORIGIN`은
실제 사용하는 shell origin과 일치해야 한다. 로컬 통합 fixture는 두 shell origin만 허용하며,
실제 서비스의 허용 origin 설정을 넓히지 않는다. Native 로그인·토큰 bridge 완료를 의미하지 않는다.
