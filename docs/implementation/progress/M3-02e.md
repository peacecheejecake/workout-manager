# M3-02e · HealthKit 검토 대기 운동의 기존 Activity 연결

상태: 로컬 수용 완료. `phase/m3-02`의 하위 작업이며 phase 독립 검토 전이다.

## 수용 경계

- 사용자가 명시적으로 선택한 active HealthKit UUID만 기존 본인 Activity에 보조 lineage로 연결한다. 유사 시각·거리로 자동 연결하지 않는다.
- 기존 Activity의 대표 source/head/original/overlay와 기간 집계는 그대로 둔다. HealthKit 운동을 두 번째 Activity로 만들거나 두 번 합산하지 않는다.
- 동의·tenant·revision·원본 생존·삭제 억제·멱등 키를 같은 DB 거래에서 검사한다. 원본 삭제·동의 철회·계정 삭제 시 보조 연결도 제거한다.
- HealthKit 단독 Activity 생성, 제품 UI, 서명된 iPhone 전체 경로는 별도 M3-02i/g/h에 남는다.

## 검증

- 실제 PostgreSQL 집중 시험 6/6: 동일 키 동시 재전송·다른 키 경합, stale revision/digest, tenant 격리, 억제/삭제된 원본과 대상, 대표 source·원본 불변과 Activity 합계 1, 원본 tombstone·동의 철회·계정 삭제를 검증했다.
- 전체 실제 PostgreSQL 통합 시험은 처음 828/829였고, 새 migration 061의 checksum 기대값 누락을 고쳐 829/829 통과했다. 재실행 전 로컬 격리 환경에서 PostgreSQL 공유 메모리 생성이 거부된 실행은 통과로 세지 않았다.
- 전체 단위 시험 첫 실행은 이 worktree의 Python 환경 부재와 격리된 로컬 fixture 접속 실패로 35건 실패했다. `uv sync --frozen`으로 Python 환경을 준비하고 fixture 접속이 가능한 환경에서 재실행해 4204 통과·7 skip을 확인했다.
- 생성물 검사, 포맷, ESLint, 전체 typecheck 34/34, 전체 build 15/15, 기본 브라우저 E2E 4/4가 통과했다. 로컬 지도·장소 데이터 경로를 지정한 identity 브라우저 두 실행은 각각 302 통과·13 skip이었다. 자료 경로를 지정하지 않은 앞선 실행은 장소·고도 데이터 부재로 실패해 중단했다.
- API 계약은 사용자 확인 `confirmed: true`, 표본 digest, 대상 revision, 멱등 키를 엄격히 요구한다. 저장소는 같은 tenant 거래에서 동의와 원본·대상을 검사하고 보조 연결만 만든다. 계정 export v27은 연결을 포함하되 표본 digest를 내보내지 않는다.
- 제품 선택 UI·새 HealthKit 소유 Activity·서명된 iPhone 전체 경로는 각각 M3-02g/i/h다. 이 경로의 외부 실행은 `not_executed`다.
