## 3. generic app/provider에 consumer가 없다는 결론의 근거와 한계

확인 범위: MAIN/M3의 `apps/**`와 `packages/**` production TS/TSX/Swift/SQL(시험·dist 제외). `getConsent/setConsent`, `/consents/*`, `FROM/JOIN consent`, consent trigger·definer, `consent.changed` topic 생산·소비와직접kind비교를검색하고 해당context를읽었다.

1. 공통repository는모든kind를검증·저장하고outbox에`consent.changed`를기록한다. topic생성은업무consumer의구현증거가아니다. 실제worker에서app/provider전용handler를찾지못했다.
2. export는전체kind의granted/revision을내보내며erase는별도계정수명주기에따른다. 원장관리consumer와사용허가gate를구별한다.
3. AItrigger는명시ai필터, HealthKittrigger는명시healthkit필터. M3등록/해제도healthkit전용revision/claimepoch를쓴다. app/provider false가이전용gate의동의를철회한것과같다는코드가없다.
4. Garmin서비스·저장소·API는connection/token/permission/owner상태를검증하지만일반consentkindprovider를참조하지않는다. OAuthscope/앱OIDC/OSHK권한은genericrow에자동반영되지않는다.
5. 이것은읽은저장소의coverage이며운영미등록외부consumer가없다는실측증거가아니다. genericrowfalse후전제품동작을새시험으로실행한것도아니다. row를표시하는가짜toggle이나성공토스트만추가하면이요구의효과검증이되지않는다.
