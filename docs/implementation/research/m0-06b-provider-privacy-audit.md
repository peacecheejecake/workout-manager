## credential·좌표 흐름

- 자체 배경 descriptor는 `apps/web/app/basemap-config.ts`와 `apps/mobile-web/src/basemap.ts`에서 같은 origin 경로만 만든다. Vite 쪽 공개 파일 요청은 `credentials: 'omit'`, `redirect: 'error'`다. `geo-kit/src/basemap.ts`가 style·TileJSON 자산 origin을 검사하고 `maplibre-adapter.ts`가 자체 protocol loader를 쓴다. 별도 지도 API key를 브라우저에 전달하는 경로는 이 구성에서 확인되지 않았다.
- 경로 계산은 인증된 `/bff/v1` API를 거쳐 내부 GraphHopper로 간다. `routing/transport.ts`는 정확한 waypoint를 URL query가 아닌 POST JSON 본문으로 보내고 redirect를 거부하며 credential을 포함하지 않는다. 이것은 **요청 줄** 유출면을 줄일 뿐이며 본문·메모리·DB의 위치정보 보호 전체를 입증하지 않는다.
- `apps/api/src/app.ts`는 Fastify 기본 요청 로그를 끄고 완료 로그에 method/status만 적으며 req/res/error serializer를 축약한다. `scripts/geo/graphhopper-foot-serving.yml`은 request log appender를 비우고 WARN 기준 및 특정 endpoint logger OFF를 설정한다. [기존 엔진 로그 probe](routing-engine-logs-m2-01ay.json)는 합성 요청에서 좌표가 stdout에 나오지 않은 관측이다. 다른 기동 방식·버전·역프록시에는 일반화할 수 없다.
- `/map/basemap/<deployment>/tiles/<z>/<x>/<y>.pbf`의 경로 자체가 viewport 위치를 나타낸다. 저장소에 Caddy/역프록시 설정 파일이 없어 access log 비활성화·IP와 tile 경로 분리·보존 기간을 코드로 검증하지 못했다. [ADR의 요구](self-hosted-map-adr.md#타일-접근-로그와-telemetry)는 여전히 운영 확인 항목이다. Next/Vite host, CDN, 수집기에서 request URI·query·본문·정확한 좌표가 기록되지 않는지 실제 설정 및 합성 요청으로 확인해야 한다.

## 판정과 후속

이 감사에서 약관 원문과 저장소의 사용 경계, browser key 부재, 일부 요청·로그 최소화 구현을 확인했다. `FUT-07-4` 전체 판정은 **`not_executed` 유지**: 실제 배포 산출물과 프록시/호스트 로그·보존 설정을 확인하지 않았고, 실기기 및 현재 배포의 검증도 없다. 과거 `P8-coverage`의 사전등록 실패 판정은 수정하지 않는다. 이후 별도 승인 기준의 재채점 결과는 [M2-01az 기록](../progress/M2-01az.md)을 따른다.

운영 확인에 필요한 입력은 비밀값 자체가 아닌 적용된 Caddy/호스트/CDN 로그 설정과 보존 정책, 서빙 중인 basemap·GraphHopper 배포 ID, 공개 ODbL 페이지의 실제 응답이다. 이를 받아 합성 위치에서 타일·경로 요청을 재현하고 access/application log를 검토해야 `FUT-07-4`의 남은 부분을 판정할 수 있다.
